## 1. UX 원칙 6개 (모든 화면에 적용)

| # | 원칙 | 구체적 의미 |
|---|------|-------------|
| **U1** | **촬영을 막지 않는다** | 정원이 없어도 촬영·합성·로컬 저장은 전부 성공한다. QR만 조용히 빠지고 `Done`으로 간다(현행 TempUser 초과 동작과 동일) |
| **U2** | **손님 앞에서 결제를 요구하지 않는다**(B2B) | 촬영 흐름에는 충전 CTA를 넣지 않는다. 잔량 안내 + "관리자에게 문의"만. 결제는 PIN 게이트 뒤 |
| **U3** | **차감은 항상 사전 확인 후** | MC가 줄어드는 모든 행위는 "얼마 차감 / 차감 후 잔액"을 보여 주고 확인을 받는다. 예외: 정원 내 QR 전송(플랜 소비는 차감이 아니다), 명시적으로 켠 오버리지 |
| **U4** | **불리한 선택을 숨기지 않는다** | "상시 운영이면 30일 플랜이 유리합니다" 같은 안내를 한다. 비싼 상품을 기본 선택으로 두지 않는다. 자동 갱신·자동 충전 기본 off |
| **U5** | **실패를 성공으로 보이지 않게 한다** | 결제 미확인은 "처리 중", 환급 불가는 명시. 낙관적 잔액 표시 금지([02 §8 C1](./02-wallet-ledger-and-entitlements.md)) |
| **U6** | **키오스크에서 읽을 수 있게** | 터치 타깃 ≥ 56px(웹 `Touch.CTA` 규격), 금액·잔량은 본문보다 큰 자릿수 강조, 색만으로 상태를 전달하지 않는다(아이콘·문구 병기) |

## 2. 상단바 — 잔량·잔액 표시

### 2.1 표시 규격

| 상태 | 표시 | 위치 |
|------|------|------|
| 게스트 | **표시하지 않음** | — |
| 로그인 + 정원 있음 | `QR 38/50` + `145 MC` | 우측(⚙ 설정 버튼 좌측) |
| 로그인 + 정원 소진 | `QR 0/50`(경고색) + `145 MC` | 동상 |
| 로그인 + 플랜 없음 | `QR —` + `145 MC` | 동상 |
| 무료 티어(temp_user) | `무료 12/30` + `145 MC` | 동상 |
| 조회 실패 | `QR ?` (회색) | fail-open([02 §8 C5](./02-wallet-ledger-and-entitlements.md)) |
| 과금 기능 off(`enabled=false`) | MC 배지 숨김, QR 배지는 유지 | |

| 규칙 | 내용 |
|------|------|
| 갱신 시점 | 로그인 직후 · QR 전송 후 · 구매 후 · 설정 진입. **폴링 금지** |
| ⚠️ 갱신 축 1개 소실 | 종전에는 **하트비트 응답**에 잔량을 실어 상시 신선도를 유지할 계획이었다([06](./06-single-session-enforcement.md) 폐기, 2026-08-10). 이제 갱신은 **이벤트 시점에만** 일어나므로, 같은 계정을 여러 기기가 쓰면 **다른 기기의 소비가 즉시 반영되지 않는다.** 폴링 금지 원칙은 유지하되, 표시값은 "마지막 갱신 시점 기준"임을 전제한다 → [03 §8](./03-qr-daily-quota.md) |
| 클릭 | 로그인 상태에서 배지를 누르면 **계정 팝오버**를 열고 "MC 충전·이력" 항목을 노출(PIN 게이트는 그 항목 진입 시) |
| B2B에서 손님 노출 | 잔량은 보이지만 **충전은 PIN 뒤**이므로 안전. 잔액을 숨기고 싶은 운영자를 위해 설정에 "상단바에 잔량 표시" 토글 제공(기본 on) |
| 촬영 화면 | 상단바가 숨겨지는 화면(촬영·결과)에서는 배지도 함께 숨는다(현행 상단바 규칙 그대로) |

### 2.2 계정 팝오버 항목 확장

현행 3항목(계정 관리 · 관리자 도구 · 로그아웃, `MainWindow.xaml:54-75`)에 **2항목 추가**:

| 항목 | 노출 조건 | 이동 | PIN |
|------|-----------|------|:---:|
| **MC 충전·상점** | 로그인 전원 + `billingEnabled` | `Store` 화면 | **필요** |
| **사용·구매 이력** | 로그인 전원 | `BillingHistory` 화면 | **필요** |
| 계정 관리 | 로그인 전원(현행) | `Account` | 필요(현행) |
| 관리자 도구 | `IsPower`(현행) | `Account(Admin)` | 필요(현행) |
| 로그아웃 | 로그인 전원(현행) | — | 불필요 |

> ✅ **PIN 게이트를 재사용**한다(`AppShellViewModel.EnsurePinGateAsync` — 판정이 이미 한 곳에 모여 있다). 새 게이트를 만들지 않는다. 웹은 `<PinGate>` 렌더 게이트 재사용([`design/web-step13`](../design/web-step13-settings-pin-gate.md)).

## 3. 상점(Store) 화면

### 3.1 레이아웃 (3섹션)

```
┌─────────────────────────────────────────────┐
│ ← 상점                          잔액 145 MC │
├─────────────────────────────────────────────┤
│ ① 내 사용 현황                              │
│   오늘 QR 전송  38 / 50   (내일 00시 초기화) │
│   보유 플랜  QR 하루 50개 · 30일             │
│              2026-09-05 만료                 │
│   프레임 생성권  2개                         │
├─────────────────────────────────────────────┤
│ ② 아이템 구매 (MC 사용)                      │
│  ┌──────────────┐ ┌──────────────┐          │
│  │ QR 하루 10개 │ │ QR 하루 50개 │  ...     │
│  │ 30일         │ │ 30일         │          │
│  │ 70 MC        │ │ 270 MC  [권장]│          │
│  └──────────────┘ └──────────────┘          │
│  ┌──────────────┐                            │
│  │ 커스텀 프레임│                            │
│  │ 만들기 1개   │                            │
│  │ 5 MC         │                            │
│  └──────────────┘                            │
├─────────────────────────────────────────────┤
│ ③ MC 충전 (결제)                            │
│  10 MC 1,000원 │ 30 MC 2,800원 │ 50 MC …    │
│  [ 결제하기 ]                                │
└─────────────────────────────────────────────┘
```

| 요소 | 규격 |
|------|------|
| ① 현황 | `GET /accounts/me/qr-usage` + `GET /entitlements` 결과. **진입 시 1회 조회** |
| ② 아이템 카드 | `GET /catalog`의 `items`(sortOrder). `dailyMax`·`durationDays`를 카드에 명시 |
| ③ 팩 카드 | `packs`. `badge` 표시. VAT 포함 총액 |
| 권장 배지 | 사용 패턴 기반 추천(선택 기능). **가장 비싼 것을 권장으로 두지 않는다**(U4) — 최근 30일 사용량 기준 |
| 채널 필터 | 모바일에서는 ③이 IAP 팩만(§9.3) |
| `billingEnabled=false` | ②③ 숨김 + "현재 상점을 이용할 수 없습니다." |

## 5. QR 정원 소진 UX (가장 자주 보이는 화면)

### 5.1 어디서 무엇이 바뀌나

| 화면 | 정원 있음 | 정원 소진 |
|------|-----------|-----------|
| 결과(`Result`) | [다음] → QR 화면 | [다음] → **`Done` 직행**(현행 TempUser 동작과 동일) |
| 결과 화면 하단 | — | 안내 배너 1줄(§5.2) |
| QR 화면 | 정상 | **진입하지 않음** |
| 업로드 중 소진(경합) | — | 업로드 실패 → 로컬 보존 + 안내(현행 실패 경로 흡수) |
| 설정 QR 항목 | 편집 가능 | **비활성 + 사유 문구**(현행 TempUser 패턴 그대로) |
| 상단바 | `QR 38/50` | `QR 0/50`(경고색) |

### 8.2 ~~강제 로그아웃 팝업~~ → ❌ **2026-08-10 폐기**

> 🚫 **이 절의 규격은 더 이상 구현 대상이 아니다.** 같은 계정의 동시 로그인을 차단하지 않으므로 **강제 로그아웃이라는 사건 자체가 발생하지 않는다.** 팝업·기기 이름 표시·"다른 창에서 로그인" 분기·촬영 중 표시 보류(최대 60초) 상태 기계를 **모두 만들지 않는다.**
>
> **폐기 사유**: 사용량(QR 전송 세션 1건) 과금이므로 동시 사용을 차단할 과금상 이유가 없다 — 여러 기기가 나눠 써도 총 청구는 사용량에 비례한다([06 §0](./06-single-session-enforcement.md)).
>
> ✅ **부수 이득**: 표시 보류 규칙은 **키오스크에서 가장 위험했던 설계**였다(손님 촬영 도중 로그아웃 팝업이 뜰 수 있었다). 그 위험이 사라졌다.
>
> ⚠️ **한 항목만 살아남는다** — JWT 만료 안내. 이것은 세션 통제가 아니라 **현행 동작**(토큰 8시간 만료 → 401)이며 웹에 이미 배선돼 있다(`webclient/src/shell/sessionExpiry.ts`). 아래 §8.2.1로 분리해 유지한다.
