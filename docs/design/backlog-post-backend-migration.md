## 운영 규칙 (반드시 준수)

1. **순차 진행**: 아래 순서대로 한 번에 하나씩. 각 항목은 (설계→)개발→리뷰(파이프라인) → **부모가 build/test 직접 검증 → 기능별 커밋** → 이 문서의 상태 체크 갱신 → 다음 항목.
2. **재개 프로토콜**: 세션이 요약/중단되면 **이 문서 + 태스크 목록**을 읽고, 아래에서 `[ ]`(미완)인 **첫 항목**부터 이어서 진행한다. `[x]`는 완료(커밋됨).
3. **자율 판단**: 개발 중 결정이 필요하면 **스스로 합리적 기본안으로 결정하고 진행**한다(사용자 대기 금지). 단 근거를 커밋/문서에 남긴다.
4. **사용자 수동 작업 분리**: 콘솔/배포/외부계정(OAuth·이메일 발송)·하드웨어(카메라·프린터 드라이버) 등 **내가 코드로 못 하는 일은 착수하지 말고 뒤로 미루고**, 반드시 **[USER-ACTIONS 문서](../USER-ACTIONS.md)** 에 추가 작성한다(항목 0에서 생성·이후 계속 append).
5. **커밋 규율**: 기능별 커밋. 시크릿/키 절대 커밋 금지. 빌드 0경고 유지.

### 2. 프레임 편집 완성도 (item 2)
- [ ] **2. 프레임 편집기 역할별 규칙 완성**
  - **user 계정**: **본인이 로컬에서 만든 프레임만 편집 가능**. DB에서 자동 다운로드된 기본 프레임은 **편집 불가**(진입/버튼 차단).
  - **manager 계정**: 로컬 프레임 + DB 연동(기본) 프레임 **모두 편집 가능**. 기본 프레임 편집 시 **"로컬만 적용 vs DB도 업데이트" 확인 팝업**. DB 업데이트 선택 시 **이미지·slot 정보 비교 → 변경분 있을 때만 업데이트**.
  - 코드[내]: 편집 진입 권한 판정(역할×프레임출처), 팝업, 이미지/슬롯 diff 판정(순수 테스트), DB 업데이트 경로(백엔드 `/frames` 재사용). 편집기 완성도(기존 미흡점 보완).
  - 참고: 프레임 출처 구분은 기존 규약(로컬 `local:`/번들 `bundle:`/DB id·`_` 이름 규약) 활용.
