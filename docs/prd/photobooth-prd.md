## 1. 개요

- **제품명**: **MC포토** *(가칭 — 추후 변경 가능)*
- **한 줄 정의**: Windows에서 동작하는 셀프 포토부스 앱. 촬영 → 커스텀 프레임 합성 → 결과물(네컷 사진 + 타임랩스 영상)을 QR 스캔으로 열리는 모바일 다운로드 페이지로 디지털 전달한다.
- **UX 벤치마킹**: "나만의 네컷" 사용 흐름(①홈 → ②촬영 안내 → ③컷 선택 → ④결과 화면 → ⑤QR 팝업)을 채택. 단 **차이점 2가지**: (1) 슬롯 수 제약상 **프레임은 촬영 전에 선택하고 촬영 이후에는 변경 불가**(BM ④의 프레임 전환은 미채택), (2) **⑥ 이메일 입력 단계 제외** — QR 스캔 즉시 다운로드 페이지 연결.
- **플랫폼**: Windows 10 / 11 터치스크린 키오스크. **가로형/세로형 모두 지원** — 화면 방향에 따라 레이아웃 자동(가로=가로 레이아웃, 세로=세로 레이아웃).
- **기술 스택**: .NET WPF

---

## 2. 목표 & 범위

- **목표**: 사용자가 직원 도움 없이 촬영부터 결과물 수령까지 스스로 완료.
- **MVP 포함**: 계정 로그인/권한 · 촬영 · 커스텀 프레임 등록/선택 · 촬영 중 영상 녹화(타임랩스) · 결과 합성 · QR → 모바일 다운로드 페이지.
- **MVP 제외(후순위)**: 인쇄, 결제 연동, AI 얼굴 보정, 크로마키/배경 합성, 원격 모니터링.

### F1. 촬영 (상세)
- **라이브 프리뷰**: 촬영 전/중 웹캠 화면 실시간 표시.
- **연속 촬영**: 설정된 컷 수만큼 컷별 카운트다운 후 자동 촬영.
- **바로 촬영(카운트다운 스킵)**: 컷별 카운트다운 진행 중 화면의 **[바로 촬영]** 버튼을 누르면 남은 카운트다운을 건너뛰고 **즉시 셔터**. (테스트·촬영 준비 완료 시 대기 불필요, 매 컷마다 사용 가능)
- **촬영 옵션(관리자 설정)**
  | 옵션 | 기본값 | 선택지 |
  |------|--------|--------|
  | 촬영 컷 수 | **6컷** | 6 / 8 / 10컷 (**최소 6**) |
  | 컷당 카운트다운 | **6초** | 3 / 6 / 8 / 10초 |
  | 거울모드(좌우반전) | **on** | on/off |
  | 플래시 | **off** | on/off (촬영 직전 화면이 하얗게 플래시 후 촬영) |
- **컷 선택 방식 (확정: 여유 촬영 후 선택 — 옵션 b)**: 설정된 컷수만큼 촬영 → 선택 화면에서 **정확히 프레임 슬롯 수만큼 선택**(빈 슬롯 없음). 선택 순서대로 슬롯을 채운다.
- **컷수·슬롯 관계 (단순화)**: 촬영 컷수 **최소 6**, 슬롯 **최대 6**으로 제한하므로 촬영 컷수 ≥ 슬롯 수가 **항상 성립**. → **프레임에 따른 컷수 변동·프레임 비활성 로직 없음**(제거).
- **재촬영**: 선택 화면에서 "다시 촬영"으로 **세션 전체 재촬영**(컷 단위 즉시 재촬영은 MVP 제외).
- **거울모드 적용 범위 (WYSIWYG)**: 거울모드 **on**이면 프리뷰뿐 아니라 **저장·합성되는 사진과 타임랩스 영상도 동일하게 좌우반전**된다 — 즉 **찍을 때 본 화면 그대로 저장**. **off**이면 프리뷰·저장 모두 정방향. (프리뷰와 결과물이 항상 일치)
- **캡처 종횡비 = 슬롯 종횡비 (중앙 크롭, 확정)**: 카메라 원본(예: FHD 1920×1080 가로)을 **선택한 프레임의 슬롯 종횡비에 맞춰 중앙 기준으로 크롭**한다 — 세로 슬롯이면 좌우를, 가로 슬롯이면 상하를 잘라냄. **비율을 늘리거나 줄이는 왜곡(resize/stretch)이 아니라 불필요한 영역을 잘라내는(crop) 방식**. 라이브 프리뷰·촬영·녹화 모두 동일하게 크롭된 화면을 사용해 **찍은 그대로가 슬롯에 딱 들어간다**(WYSIWYG). *한 프레임의 슬롯들은 동일 종횡비를 전제하며, 다르면 대표 슬롯 종횡비로 크롭 후 합성 시 슬롯별 중앙 크롭으로 보정.*

### F2. 커스텀 프레임 (상세)
- **프레임 이미지 등록**: **임의 크기·비율**을 그대로 수용한다. 고정 목록이 아니라 등록 이미지 원본 크기를 기준으로 처리.
  - 지원 형식: **PNG / JPG / JPEG**.
  - 예시 비율(가로/세로 무관): `4:3`, `16:9`, `4:1`, `3:4`, `9:16`, `1:4`, `1:1` … 그 외 임의 비율도 허용.
- **슬롯(사진 칸)**: 기본 **1~6개**, 각 슬롯의 **위치·크기 조절** 가능.
  - ⚠️ **프레임 크기에 종속**: 프레임이 작으면 슬롯 개수가 줄거나 슬롯 크기가 작아지도록 편집기가 제약/가이드한다(슬롯이 프레임 밖으로 나가거나 겹치지 않도록).
- **편집 UI**: 관리자가 슬롯 개수 지정, 드래그로 위치·크기 조절을 **쉽게** 할 수 있는 편집기 제공(스냅/경계 제한 등 보조).
- **편집기 범위(확정)**: 슬롯 배치(개수·위치·크기)만 제공. **텍스트·스티커·배경 등 장식의 in-app 편집은 제외** — 타이틀·문구 등 장식은 업로드하는 프레임 이미지에 **이미 포함**된 것으로 간주(예: `Frame.png`).
- **저장/불러오기**: 등록한 프레임을 DB에 저장하고 이후 불러와 재사용. **로그인 계정당 최대 10개**까지 저장.
- **선택**: 촬영 시작 시 저장된 프레임 목록에서 선택.
- **접근 권한**
  - **게스트(비로그인)**: 커스텀 프레임 없이 **기본 프레임만** 사용.
  - **로그인 사용자**: 기본 프레임 + 본인 커스텀 프레임(최대 10개).
- **기본 프레임 (Default Frame)** — 앱이 기본 제공하는 프레임. 사용 가능한 프레임 결정 순서:
  1. **DB에 등록된 기본 프레임**(관리자가 등록한 공용 프레임)이 있으면 **DB에서 다운로드**하여 사용(우선).
  2. 없으면 최초 설치 시 설치 폴더 내 **`Frame/` 폴더**에 설치된 번들 프레임 사용.
  3. 그것도 없으면 **fallback**: **하얀 바탕 · 슬롯 4개 · 3:4 비율**의 내장 기본 프레임 제공.
- **합성 레이어 모델 (확정: 배경형)**: 프레임 이미지 = 배경 레이어, 사진 = 슬롯 위에 얹기 (JPG 프레임도 지원). *(PNG 투명 오버레이 방식은 추후 확장)*
- **슬롯 채움**: cover(중앙 크롭). 캡처가 이미 슬롯 종횡비(§F1)라 실질적으로 왜곡·추가 크롭 없이 채워짐.
- **슬롯 자동 배치(기본값, 편집기에서 수동 조절 가능)**
  - 표준 비율(4:3, 3:4 등): 격자 배치 — 예: 4개 = 2×2.
  - 세로 긴 스트립(1:4, 1:3 등): 세로 1열 — 4개 = 1×4, 3개 = 1×3.
- **프레임 이미지 제한**: 장변 최대 4000px · 10MB (초과 시 리사이즈/거부).
- **슬롯 회전**: MVP 제외.

### F3. 영상 녹화·타임랩스 (상세)
- 촬영 세션(첫 컷~마지막 컷) **전체**를 웹캠 영상으로 연속 녹화. **프리뷰·촬영과 동일하게 슬롯 종횡비로 중앙 크롭된 화면을 녹화**(왜곡 없이 크롭 — 타임랩스도 슬롯 종횡비).
- 세션 종료 후 배속 처리하여 **타임랩스 클립** 자동 생성 — **목표 길이 10~15초 · 무음 · `mp4(H.264)`**.
- 생성물은 F5 결과물에 포함되어 함께 제공.

### F4. 결과 합성·보정 (상세)
- **기본 필터(선택 적용)**
  - **흑백**: 그레이스케일 변환.
  - **밝기**: 밝기(및 약한 대비) 조정.
  - **간단 뷰티**: 가벼운 피부 스무딩(소프트닝) + 톤 보정. *얼굴 인식 없이 전체 영역에 완만하게 적용하는 경량 버전(MVP). 얼굴 인식 기반 정밀 뷰티는 향후.*
  - 필터는 결과 화면에서 토글하며, **전체 컷 일괄 적용**.
- **결과 화면(BM ④ 구조)**: 합성 미리보기 + **필터 선택**을 한 화면에서 제공. **프레임은 촬영 전 선택으로 고정 — 결과 화면에서 변경 불가**(BM의 프레임 전환은 미채택).
- **합성**: (필터 적용된) 선택 컷 + 프레임 → 최종 이미지. 캡처가 이미 슬롯 종횡비이므로 슬롯에 **왜곡 없이** 배치(추가 종횡비 크롭 없이 슬롯 픽셀 크기로 uniform 스케일만).
- **출력 해상도**: **프레임 원본 해상도 기준**으로 합성(사진은 이미 슬롯 종횡비이므로 uniform 스케일 배치, 비율 왜곡 없음).
- **출력 포맷**: `AppSettings.outputFormat`(기본 JPG, JPG/PNG).
- **로컬 저장(독립 옵션)**: `AppSettings.saveLocalCopy` on이면 최종 결과물(사진 + 타임랩스 영상)을 로컬에 저장.
  - 기본 위치 **`{실행 경로}\result\`**, 세션마다 **`mcphoto_YYMMDD_HHMM\`**(예: `mcphoto_260720_1445`) 폴더를 만들어 그 안에 사진·영상 저장.
  - 저장 위치는 `AppSettings.localSavePath`로 **변경 가능**.
  - **QR 전송(F5)과 독립**하게 동작. ⚠️ QR 전송·로컬 저장이 **모두 off면 결과물이 남지 않음**.
  - **로컬 저장분은 자동삭제(TTL) 대상이 아님** — 영구 보존, 사용자가 수동 관리.

### F5. 디지털 전송 (상세)
- **기능 토글 (확정: 옵션화)**: 전송 파이프라인 전체(업로드 → QR → 다운로드 페이지)를 **on/off** 할 수 있다(`AppSettings.enableQrDelivery`, 기본 **on**). **off면 업로드·QR 없이** 결과 미리보기 후 완료로 진행. *개발 과정에서 불필요할 수 있어 둔 편의 기능 — 추후 제거 예정.* (로컬 저장은 F4의 `saveLocalCopy` 옵션이 담당 — F5 on/off와 **독립**.)
- **업로드 대상**: ① 프레임 포함 최종 이미지, ② 타임랩스 영상.
- **저장 정책 (Firebase 업로드본에 한함)**: Firebase Storage 업로드본을 **설정된 보관 시간(`retentionHours`, 기본 24h, 1~72h) 후 자동 삭제**(관리자 모드에서 변경). ⚠️ **자동삭제는 Firebase 업로드본(+해당 메타데이터)만 대상 — 로컬 저장분(§F4)은 삭제하지 않음.**
- **전달 방식 (확정: QR → 다운로드 페이지)** — 문자/이메일 직접 발송은 **제외**.
  - 결과물의 **다운로드 페이지 URL**로 **QR 코드** 생성 → 결과 화면 위 **QR 팝업**으로 표시(BM ⑤ 구조 — [홈으로]/[닫기] 버튼).
  - QR 아래에 **"업로드된 사진·영상은 N시간 후 자동 삭제됩니다"**(설정값 N 반영) 고지 문구 노출.
- **다운로드 페이지 (모바일 최적화)** — QR 스캔 시 열리는 간단한 웹페이지. *(벤치마크 ⑥의 이메일 입력 단계는 채택하지 않음 — 스캔 즉시 다운로드 제공)*
  - 구성: 사진 프리뷰 + [사진 다운로드] 버튼, 영상 프리뷰 + [영상 다운로드] 버튼.
  - 모바일 사용 비중이 높으므로 **모바일 우선 반응형 UI**.
  - 만료(보관 시간 경과) 시 안내 페이지 표시.

### F7. 관리자 모드 (상세)
- **진입**: 화면 좌상단 3초 롱프레스 → 로그인 → **로그인한 계정이면 진입**(user 포함 — 각 사용자가 자기 인스턴스의 관리자).
- **설정 편집(로그인 계정 누구나)**: `AppSettings` 항목 전체(촬영 컷수·카운트다운·거울모드·플래시·출력 포맷·표시 모드·카메라 장치·QR 전송·로컬 저장·보관 시간) 변경.
- **기본 프레임 관리 (power 전용)**: 공용 기본 프레임(isDefault) 등록·수정·삭제.
- **사용자 관리 (power 전용)**: 사용자 목록 조회·삭제·비밀번호 초기화(§F8).
- **간단 촬영 카운트**: 누적 촬영 횟수 표시 수준(상세 로그·통계는 MVP 제외).
- **앱 종료**: 전체화면 키오스크에서 앱을 종료하는 경로 제공.

### F8. 계정·로그인·권한 (상세)
- **로그인은 선택**: 비로그인(게스트)도 촬영·전송 등 기본 기능을 사용할 수 있다(단 **기본 프레임만**, 커스텀 불가). 커스텀 프레임 등록/사용은 로그인 필요.
- **로그인**: `id` / `pw` 입력. **인증 절차(이메일 인증·OAuth·2FA 등) 전부 제외** — id/pw만으로 계정 생성.
- **소유 주체 / 관리자성**: 로그인한 계정 = **프레임 소유 주체 + 자기 인스턴스의 관리자**(앱 설정 관리 가능). 프레임(최대 10개)은 계정에 귀속. *(다른 계정을 관리하는 '사용자 관리'와 공용 기본 프레임 관리만 power 전용)*
- **역할(Role)**
  | 역할 | 권한 |
  |------|------|
  | `user` | 자신의 프레임(최대 10개) 소유 + **앱 설정(AppSettings) 관리** = 자기 인스턴스의 관리자. (다른 계정 관리는 불가) |
  | `manager` | user 권한 + **사용자 관리**(다른 계정 조회·삭제·pw 초기화) + **공용 기본 프레임 관리** |
  | `admin` | 최종 관리자(**1인, = 본인**). manager 권한 + **manager 지정** |
- **사용자 관리 화면**: power 계정(`admin`/`manager`) 전용. 등록 사용자 목록 조회·삭제 및 **비밀번호 초기화**(이메일 인증이 없으므로 분실 시 유일한 복구 수단).
- **계정 삭제 시 정리(cascade)**: 삭제되는 계정 소유의 프레임(Firestore 문서 + Storage 프레임 이미지)을 함께 삭제한다.
- **admin vs manager**: 현재 기능 동일. 유일한 차이 = **admin만 manager를 지정** 가능.
- **초기 admin 계정(시드)**: DB에 사전 등록 — `id: devmcjo` / `pw: 1111` / role: `admin`. (최초 로그인 후 비밀번호 변경 권장)
- **계정 화면(로그인 상태)**: 롱프레스로 로그인 화면에 다시 진입하면, 로그인 상태에서는 **로그아웃 · 비밀번호 변경 · 관리자 모드(앱 설정)**를 제공한다(별도 "내 계정" 화면 없이 로그인 화면이 계정 허브 역할). 사용자 관리는 power 계정만.
- **키오스크 세션**: 촬영 1회 세션 종료 후 자동으로 대기화면(게스트)으로 복귀. 커스텀 프레임 사용 시에만 로그인.
- **관리자 모드 진입**: 화면 **좌상단 모서리 3초 롱프레스** → 로그인 → **로그인 계정이면** 관리자 모드(앱 설정) 진입. 사용자 관리·공용 기본 프레임은 power 계정 전용 섹션.

## 4. 사용자 플로우

```
대기(홈) 화면 → [촬영하기] → 로그인 or 게스트 선택
  → 프레임 선택 (게스트=기본 / 로그인=기본+커스텀)
  → 촬영 안내 화면(타이머·촬영 방식·컷 선택 방식 안내) → [촬영하기]
  → N컷 촬영(카운트다운 + 세션 녹화)
  → 컷 선택(정확히 슬롯 수만큼) → [다음]
  → 결과 화면(미리보기 + 필터 / 프레임은 촬영 전 선택 고정) → 합성 + 타임랩스 생성
  → (QR 전송 on) 업로드(TTL) → QR 팝업(스캔 시 모바일 다운로드 페이지, N시간 후 삭제 고지)
  → 완료 → 대기(홈) 화면   ※ QR 전송 off면 업로드·QR 생략, 로컬 Output 저장 후 완료
```

**프레임 관리 플로우 (F2)**
```
프레임 만들기 → 프레임 이미지 업로드(PNG/JPG/JPEG, 임의 크기·비율 — 캔버스 확정)
  → 슬롯 개수(1~6) 지정 → 슬롯 위치·크기 조절(자동 배치 후 수동 조정)
  → 저장(DB, 계정당 최대 10개) → [촬영 시 목록에서 불러오기]
```

## 5. 화면 구성 (초안)

1. 대기(홈) 화면 — [촬영하기] 중심 + 프레임 만들기/로그인 진입 (BM ①)
2. 로그인 / 게스트 선택 화면
3. 로그인·계정 화면 — 비로그인: id/pw 로그인 / 로그인 상태: **로그아웃 · 비밀번호 변경 · 관리자 모드(앱 설정)**(사용자 관리는 power만)
4. 계정 생성 화면 (id/pw)
5. 프레임 선택 화면 (게스트=기본만 / 로그인=기본+커스텀)
6. 프레임 편집기 (로그인 사용자 — 슬롯 개수·위치·크기, 프레임 크기 제약 반영)
7. 촬영 안내 화면 (타이머·촬영 방식·컷 선택 방식 안내, BM ②)
8. 촬영 준비 / 라이브 프리뷰
9. 촬영(카운트다운) 화면 — [바로 촬영] 버튼으로 카운트다운 스킵 가능
10. 컷 선택 화면 (완성 미리보기 + 컷 썸네일, 슬롯 수만큼 선택, BM ③)
11. 결과 화면 (미리보기 + 필터 / 프레임 촬영 전 선택 고정, BM ④)
12. QR 팝업 (QR + "N시간 후 삭제" 고지, BM ⑤)
13. 완료 / 감사 화면
14. 관리자 모드 (설정·기본 프레임·사용자 관리·앱 종료)
15. 사용자 관리 화면 (power 전용 — 목록·삭제·비밀번호 초기화)

＊ 별도 웹(키오스크 화면 아님): **모바일 다운로드 페이지** — QR이 가리키는 대상, 사진·영상 프리뷰 + 다운로드 버튼.

## 6. 데이터 모델 (초안)

**User (계정)**
| 필드 | 설명 |
|------|------|
| id | 로그인 ID |
| password | 비밀번호 (MVP: 인증/해싱 제외 가정 — §8 참조) |

**FrameTemplate**
| 필드 | 설명 |
|------|------|
| id | 프레임 ID |
| userId | 소유 계정 ID(로그인 사용자). 기본 프레임은 공용이므로 null/전용 값 |
| isDefault | 기본 프레임 여부(관리자 등록 공용 프레임) — 게스트에게도 노출 |
| name | 프레임 이름 |
| imageUrl | 프레임 이미지(PNG/JPG/JPEG, 임의 크기·비율) |

| createdAt | 생성 시각 |

> 기본 프레임 소스 우선순위: ① DB 등록 기본 프레임 → ② 설치 폴더 `Frame/` 번들 → ③ fallback(하양·4슬롯·3:4). (F2 상세 참조)

**ResultSession**
| 필드 | 설명 |
|------|------|
| id | 세션 ID |
| finalImageUrl | 프레임 포함 최종 이미지 원본 |
| timelapseUrl | 타임랩스 영상 |
| createdAt | 생성 시각 |
| expiresAt | `createdAt + retentionHours`(기본 24h) — 자동 삭제 기준 |
| downloadPageUrl | 모바일 다운로드 페이지 URL(QR 인코딩 대상) |

**AppSettings (관리자 설정)**
| 필드 | 설명 |
|------|------|
| cutCount | 촬영 컷 수 (기본 6, 옵션 6/8/10 — 최소 6) |
| countdownSec | 컷당 카운트다운 초 (기본 6, 옵션 3/6/8/10) |
| mirrorMode | 거울모드(좌우반전) on/off |
| flashMode | 플래시(촬영 직전 하양 화면) on/off |
| outputFormat | 최종 이미지 포맷 (기본 JPG, 옵션 JPG/PNG) |
| retentionHours | 결과물 보관 시간 (기본 24, 범위 1~72) — 관리자 모드에서 변경 |
| displayMode | 표시 모드 (기본 fullscreen, 옵션 windowed) — 창모드 최소 1280×720, 마지막 크기·위치 복원 |
| windowBounds | 창모드 마지막 창 크기·위치 (재시작 시 복원) |
| enableQrDelivery | QR 전송 기능(업로드+QR+다운로드 페이지) on/off (기본 on) — 개발 편의용, 추후 제거 예정 |
| saveLocalCopy | 결과물 로컬 저장 on/off (기본 off) — 세션별 폴더에 사진·영상 저장, QR 전송과 독립 |
| localSavePath | 로컬 저장 위치 (기본 `{실행 경로}\result\`, 변경 가능) — 세션 폴더 `mcphoto_YYMMDD_HHMM\` 자동 생성 |
| cameraDevice | 사용할 웹캠 장치 선택 (다중 카메라 환경 대비) |

> AppSettings는 **앱 인스턴스(설치) 단위 로컬 설정**이며, **로그인한 계정(user 포함)이 자기 인스턴스의 관리자**로서 관리자 모드에서 전 항목을 변경한다. 다른 계정을 관리하는 '사용자 관리'와 공용 기본 프레임(isDefault) 관리만 power(admin/manager) 전용.
>
> 모든 설정은 로컬 **INI 파일**(예: `{실행 경로}\MCPhoto.ini`, 쓰기 가능한 위치)에 저장되어 **프로그램 재시작 시 직전 값으로 복원**된다. 창모드는 마지막 **창 크기·위치**(`windowBounds`)까지 복원.

## 7. 하드웨어 · 기술 제약

- **카메라**: **웹캠으로 선(先) 진행** (UVC / Windows Media Foundation). DSLR 등 SDK 연동이 필요한 장비는 추후 추가 개발.
  - ⚠️ 웹캠은 라이브 프리뷰 + 정지 촬영 + 세션 영상 녹화(F3)를 **동시에** 지원해야 하므로 캡처 파이프라인 설계가 핵심.
- **디스플레이**: 가로/세로 터치스크린 — 화면 방향에 따라 레이아웃 자동(§1).
- **백엔드/저장소 (확정: Firebase)** — 기보유 무료 프로젝트 활용. 구성:
  - **Cloud Storage**: 최종 이미지·타임랩스 영상 파일 저장, 공유 다운로드 URL 제공. **경로 분리**: `results/{sessionId}/…`(TTL 삭제 대상) / `frames/{userId}/…`(프레임 이미지, TTL **비대상**) — 만료 정리 작업은 `results/`만 스캔.
  - **Firestore**: 계정(User)·프레임(FrameTemplate)·세션(ResultSession) 메타데이터 저장.
  - **Firebase Hosting**: 모바일 다운로드 페이지 배포.
  - ⚠️ **보관 시간 만료 삭제(업로드본 한정)**: 보관 시간이 가변(1~72h)이므로 `expiresAt` 기준 **만료 스캔 방식**으로 처리. Firestore 문서 TTL은 메타데이터만 지우므로, **Cloud Storage의 실제 파일도 예약 작업(Cloud Functions 스케줄러 등)으로 함께 삭제**해야 함. **로컬 저장분은 이 루틴과 무관(삭제 안 함).**
  - 참고: 무료(Spark) 요금제 한도·Blaze 전환 필요성은 **§10 인지 사항** 참조.
- **기술 스택(앱)**: **.NET WPF** (Windows 네이티브, 애니메이션 UI 적합).
- **웹(다운로드 페이지) 스택**: 정적 HTML/CSS + **Vanilla JavaScript** + **Firebase JS SDK**(Firestore·Storage), Firebase Hosting 배포. 단일 페이지로 충분(프레임워크 불필요).
- **외부 의존성 후보**: 영상 배속/인코딩(FFmpeg 등), QR 코드 생성 라이브러리.

## 8. 비기능 요구사항

- **성능**: 촬영 응답 지연 최소화, 합성·영상 생성·업로드 중 진행 상태 표시.
- **안정성**: 무인 상정 시 예외가 나도 대기화면으로 자동 복귀, 장시간 무인 동작.
- **개인정보**: 촬영물은 민감정보 → 업로드본은 **설정된 보관 시간(기본 24h, 1~72h) 후 자동 삭제**로 보관 최소화.
- **계정 보안(MVP)**: 로그인은 인증 절차(이메일 인증·OAuth·2FA) 전부 제외, id/pw만으로 생성. *개인 사용/시험 목적 전제.* 외부 배포 시 최소 비밀번호 해싱·세션 보호 필요(후순위).
- **네트워크**: 업로드/전송뿐 아니라 **로그인·커스텀 프레임도 Firestore 의존** → 오프라인 시 **게스트 + 번들 기본 프레임 모드**로만 동작(QR 전송 불가 안내), 업로드 실패 시 재시도 정책 포함.

## 10. 운영·안정성·보안 고려사항

### MVP 반영
- **유휴 타임아웃 자동 리셋**: 촬영/선택/편집 중 일정 시간(예: 60~90초) 무동작 시 진행 취소 → 대기화면 복귀 + 임시 데이터 폐기.
- **업로드·네트워크 신뢰성**: 결과물 **업로드 성공 후에만 QR 노출**. 실패 시 재시도·오류 안내. 인터넷 불가 시 "전송 불가" 안내.
- **다운로드 URL 보안**: 세션 식별자는 순차 ID가 아닌 **추측 불가 토큰(UUID/서명 URL)**. 만료·삭제 후 접근 시 안내 페이지.
- **로컬 임시 파일 정리**: 촬영 원본·중간 산출물은 세션 종료 시 로컬에서 삭제(개인정보·디스크 관리). **최종 결과물은 `saveLocalCopy` on일 때만 `result\mcphoto_YYMMDD_HHMM\`에 보존**(그 외 로컬 잔존 없음). 이 로컬 보존분은 **자동삭제(TTL) 대상이 아님** — 사용자가 수동 관리.
- **컷 → 슬롯 매핑**: 선택 순서대로 슬롯을 채움(기본), **정확히 슬롯 수만큼 선택**(빈 슬롯 없음). *(슬롯별 수동 지정은 향후)*
- **Firebase 보안 규칙 (필수)**: 웹 페이지의 Firebase 설정(API 키)은 공개되므로 **보안 규칙이 유일한 방어선**. `User`·`FrameTemplate` 컬렉션은 **웹에서 접근 불가**, `ResultSession`은 **토큰 ID 단건 get만 허용(list 쿼리 금지)**, Storage 공개 read는 `results/{sessionId}/` 한정. 특히 MVP는 비밀번호 평문 저장이므로 `User` 노출 = 전체 계정 유출.
- **화면 방향 레이아웃**: 가로 화면=가로 레이아웃, 세로 화면=세로 레이아웃 자동. 프레임은 자기 비율대로 화면 중앙에 맞춰 표시.
- **표시 모드(전체화면/창모드)**: 기본 **전체화면**, 설정으로 **창모드** 전환 가능(테스트용). 창모드는 반응형이며 **최소 1280×720**을 하한으로 둔다. *(전체화면 표시는 포함하되, 시스템키 차단 등 락다운은 아래 인지 사항대로 MVP 제외)*

### 설치·배포
- **인스톨러(제안 확정)**: **Inno Setup**(무료·스크립트 기반) — 앱 + 기본 프레임(`Frame/`) + FFmpeg 등 네이티브 의존성 번들에 적합, 샌드박스 제약 없음. *(MSIX는 자동 업데이트/스토어 배포가 필요할 때 향후 검토 — 단 컨테이너 파일 가상화로 Frame 폴더 쓰기가 번거로움)*
- **데이터 폴더 위치**: 런타임에 갱신되는 기본 프레임/설정은 `Program Files`(보호됨)이 아닌 **쓰기 가능한 위치**(예: `%ProgramData%\MCPhoto\`)에 배치. **로컬 결과물은 별도**로 기본 `{실행 경로}\result\`(변경 가능, `localSavePath`)에 세션 폴더로 저장 — 실행 경로가 보호된 위치면 쓰기 가능한 경로로 변경 필요.
- **네이티브 의존성**: 타임랩스 생성용 **FFmpeg** 바이너리 번들 예상.

### 인지 사항(향후)
- **키오스크 락다운**(전체화면·시스템키 차단·부팅 자동 실행): MVP 제외, 필요 시 추후 지시.
- **Firebase 무료(Spark) 한도**: Firestore 1GB·읽기 5만/쓰기 2만(일), Hosting 저장 1GB·전송 10GB/월. ⚠️ **Cloud Storage는 기본(appspot) 버킷이 Blaze 요금제를 요구하는 방향으로 변경됨** — 기보유 프로젝트에서 Storage 사용 가능 여부 확인 필요(불가 시 예산 상한을 건 Blaze 전환). 영상 포함이라 저장·전송이 binding constraint이므로 TTL 삭제가 완화책.
- **Supabase 대비**: Supabase 무료는 DB 500MB·파일 Storage 1GB로 **오히려 더 작음**(DB 한도는 Firestore 1GB가 큼, 파일 저장 여력도 Firebase가 유리). → Firebase 유지 타당.
