## C1. 카메라 설정 (SettingsView + 테스트 모달)

- 웹캠이 **여러 개** 연결되었거나 **한 개도** 연결되지 않은 경우를 **모두** 처리한다.
- 현재 "카메라 장치 인덱스" TextBox(`{Binding CameraDevice}`)를 **ComboBox**로 교체:
  - `ICameraService.EnumerateDevices()` 결과를 나열해 선택 가능하게 한다.
  - 선택값은 기존 설정(장치 인덱스, `AppSettings.CameraDevice`)과 호환되게 저장한다.
- **연결된 카메라가 하나도 없으면 ComboBox를 Disable** 처리한다(안내 문구 포함 권장).
- 카메라 선택 옆에 **"미리보기/테스트" 버튼**을 둔다. 누르면 **별도 모달 창(Window)**을 연다.
  - 이 모달은 **실제 촬영과 동일한 화면**으로 테스트 가능해야 한다(선택된 카메라로 라이브 프리뷰).
  - **"테스트 화면입니다" 류의 노티 문구**가 항상 보여야 한다(저장되지 않음을 명시).
  - 기본은 프리뷰 화면. **셔터를 누르면 현재 플래시 옵션(FlashMode 설정)을 확인 후 촬영 진행**(플래시 효과 재현). 단, **저장은 하지 않음**(테스트 전용).
  - 모달을 닫으면 카메라 리소스를 확실히 해제한다(프리뷰 스레드/VideoCapture Dispose).

## C2. 설정 페이지 저장/닫기 버튼 겹침 수정

- `SettingsView.xaml` 하단 sticky 바: 열 정의 없는 단일 `Grid` 셀에 좌측 StackPanel(저장 버튼 + 안내문)과 우측 "닫기" 버튼이 겹쳐 배치되어, 안내문이 길어지거나 폭이 좁으면 겹친다.
- 명확한 레이아웃(`Grid.ColumnDefinitions` 2열 등)으로 좌/우를 분리해 **절대 겹치지 않게** 수정한다.
- 기존 sticky 동작/토스트 색 분기(성공=민트, 실패=로즈)는 **유지**한다.

## C3. 앱 이름(브랜딩) 외부 설정화

- 기본값은 "MC포토"이되, 외부 설정 파일(ini 등 고객이 쉽게 편집 가능한 형태)로 앱 이름을 바꾸면 그 이름으로 앱 전체가 표시되도록 한다("외부 언어 리소스를 읽어오는 기능" 취지).
- 설정 파일이 없거나 값이 비면 "MC포토"로 폴백한다.
- 하드코딩된 "MC포토"를 전수 조사해 이 브랜딩 소스로 치환한다(창 제목, 홈 화면 로고/타이틀 등 사용자에게 보이는 모든 지점). Window Title 포함.
- 파일 위치/포맷과 로딩 시점(앱 시작 시 1회 로드 후 리소스/서비스로 노출)을 설계한다. 단순하고 배포 친화적인 방식을 우선한다.

## 비범위 (Non-goals)

- 다국어 전면 지원(리소스 사전 전환, 문자열 카탈로그). C3은 **앱 이름 한 항목**만.
- OS 장치명(FriendlyName) 조회를 위한 신규 네이티브 P/Invoke 의존성 도입(결정 사항으로 분리).
- 테스트 모달에서 촬영 결과 저장·업로드·합성(테스트 전용, 저장 금지).
