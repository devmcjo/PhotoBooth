# 13 · 클라이언트 동작 규격 (플랫폼 중립)

| 항목 | 내용 |
|------|------|
| 문서 | 어떤 플랫폼에서 구현하더라도 **동일하게 동작해야 하는** 화면·상태 전이·흐름·타이밍·검증 규칙·사용자 문구 |
| 범위 | 촬영 클라이언트(P2)·저작(P3)·운영(P4)·소비자(P1) 전 화면. UI 배치/미학은 규격이 아니며, **동작·판정·타이밍·문구**만 규격이다 |

| 갱신 규칙 | 화면 추가·전이 규칙 변경·타이밍 상수 변경·사용자 문구 변경 시 이 문서를 갱신하고, Windows 구현이 함께 바뀌면 [11](./11-exe-app-features.md)도 갱신 |

**모달(상태가 아닌 것)**: 카메라 테스트, 진단·상태, PIN 입력, 기존 프레임 불러오기, 삭제 확인, **서버 등록 확인**(§6.3), 유휴 경고, **프레임 준비 대기·실패**(§4.2). 이들은 화면 상태 전이를 일으키지 않고 현재 화면 위에 올라온다.

> 겹침 규칙: 유휴 경고는 **셸이 소유**하므로 화면 로컬 오버레이보다 항상 위에 그려진다. 화면 로컬 오버레이끼리는 동시에 뜨지 않는다(각 화면이 상호배타 상태로 관리).

> 모바일 플랫폼에서 상단바는 네이티브 내비게이션 바로 대체할 수 있으나, **`Capture`·`Qr`에서 이탈 UI를 숨기는 규칙은 유지**해야 한다(오조작 방지). 대신 그 두 화면은 **자체 취소 버튼**을 제공해야 한다 — 그러지 않으면 손님이 갇힌다.

### 1.1 상단바 구성 (it21)

| 위치 | 요소 | 노출 조건 | 비고 |
|------|------|-----------|------|
| 좌 | **브랜드-홈 칩** = 홈 글리프 + 워드마크 | `Home`에서 숨김 | 로고=홈은 확립된 관례지만 보편 신호는 아니므로 글리프를 병기한다. 키오스크는 홈이 **항상 명확히** 보여야 한다 |
| 중앙 | (비움) | — | 화면 제목 슬롯으로 예약. 하위 화면들이 이미 자기 제목을 콘텐츠에 갖고 있어 브랜드를 중앙에 두면 제목이 둘이 된다 |
| 우 | **계정** → **설정** | 계정=상시 / 설정=`Settings`에서 숨김 | 좌=내비게이션, 우=액션이 상용 관례 |

- 아이콘은 전부 **벡터 `Geometry`**(`Themes/Icons.xaml`)다. 유니코드 글리프(`⚙`·`⌂`)는 폰트 폴백으로 모양이 통제되지 않아 폐기했다.
- 계정 버튼은 게스트=사람 아이콘, 로그인=**이니셜 아바타**(로즈 원). 종전 계정 ID 텍스트는 **툴팁**으로 이전했다.
- 아이콘 전용 버튼은 **ToolTip + `AutomationProperties.Name`이 둘 다 필수**다. 터치에는 hover 툴팁이 없으므로, 손님 접점인 로그인은 Home 화면의 텍스트 진입점이 발견성을 보완한다.
- 계정 팝오버는 **계정 버튼 자신을 기준으로 우측 정렬**한다(상단바 기준이면 버튼과 팝오버가 화면 양끝으로 분리된다).

## 2. 화면 상태 전이 규칙

### 2.1 정방향 전이표

| From | 진행 가능 |
|------|-----------|
| `Home` | `FrameSelect`, `Login`, `Settings` |
| `Login` | `FrameSelect`, `FrameEditor`, `Settings` |
| `FrameSelect` | `Guide`, `FrameEditor` |
| `Guide` | `Capture` |
| `Capture` | `CutSelect` |
| `CutSelect` | `Result`, `Guide`(= 전체 재촬영) |
| `Result` | `Qr`, `Done` |
| `Qr` | `Done` |
| `Done` | `Home` |
| `Settings` | `Login`, `FrameEditor` |
| `FrameEditor` | `FrameSelect`, `Settings`, `Login` |
| `Account` | `UserMgmt` |
| `UserMgmt` | `Account` |

### 2.2 전이 판정 규칙

```
canTransition(from, to):
  1) to ∈ {Home, Settings, Login, Account} → 항상 허용   (오버레이성 진입/복귀)
  2) from == to                            → 거부
  3) 그 외                                  → 위 표에 to가 있으면 허용
```

- 전이 실패는 **예외가 아니라 거부 로그**로 처리한다(무인 안정성).
- 전이 순서: 이탈 화면의 정리 → 상태·화면 교체 → 유휴 감시 갱신 → 진입 화면의 초기화. 각 단계의 예외는 **삼켜 로그**한다.

### 2.3 오버레이 복귀

`Settings`·`Login`·`Account`는 **진입 전 상태를 복귀 지점으로 보존**한다.
- **오버레이 화면 집합** = `Settings`·`Login`·`Account`·`UserMgmt`. 진입 시 현재 상태가 이 집합에 **속하지 않을 때만** 복귀 지점으로 저장한다.
  - 오버레이끼리의 전환이 복귀 지점을 덮어쓰면 [닫기]가 **자기 자신으로 복귀**해 아무 일도 하지 않는다. 계정 화면에서도 상단바 계정 메뉴가 열리므로(§1 화면 표의 "상단바" 열) 계정관리↔관리자도구를 바로 전환할 수 있어 실제로 발생한다.
  - `UserMgmt`는 오버레이 진입 대상이 아니지만(관리자 도구의 하위 페이지) 같은 집합이다 — 복귀 지점이 되면 `Account`↔`UserMgmt`를 [닫기]로 벗어날 수 없다.
- 복귀는 **전이 검증 면제**(진입의 역방향은 항상 합법).
- 복귀 시 **촬영 세션 데이터를 폐기하지 않는다**(설정 보러 갔다 왔다고 촬영분이 사라지면 안 된다).
- 사용자 관리의 [뒤로]는 복귀 지점을 쓰지 않는다 — 관리자 도구(`Account`/Admin)로 **직행**하며 복귀 지점을 건드리지 않는다.

### 2.4 홈 복귀

어디서든 홈으로 갈 수 있다. 홈 복귀는 항상:
1. 촬영 세션 데이터 폐기(컷·선택·프레임·재촬영 카운터)
2. 세션 임시 작업 폴더 정리
3. 유휴 감시 정지
4. **로그인 상태는 유지**(§3.3)

## 3. 세션·인증 상태 규칙

### 3.1 두 개의 홀더를 혼동하지 않는다

| 홀더 | 내용 | 수명 |
|------|------|------|
| **세션 컨텍스트** | 현재 사용자(도메인 계정 객체) — 화면·권한 판정의 **유일한** 근거 | 앱 사용 동안(촬영 세션보다 상위) |
| **토큰 홀더** | 로그인 JWT — `Authorization` 조립용 | 프로세스 수명, **메모리 전용** |

- 현재 사용자 변경 진입점은 `login` / `logout` / `reset(clearUser)` **3개뿐**이며, 변경 시 **통지 이벤트**를 발행한다. UI는 미러 상태를 두지 않고 이 통지로 갱신한다.
- **토큰 폐기는 "로그아웃 버튼"에 거는 게 아니라 "현재 사용자가 null이 되는 통지"에 건다.** 게스트 전환 경로가 늘어도 한 곳이 전부를 덮는다. ([05 §6 M1](./05-cross-platform-client-guide.md))

### 3.2 로그인 진입점

| 상태 | 계정 버튼 클릭 결과 |
|------|---------------------|
| 비로그인 | 로그인 화면(오버레이 진입) |
| 로그인 | 계정 메뉴 토글 — **계정 관리**(전원) / **관리자 도구**(power만) / **로그아웃**(전원) |

계정 라벨: 비로그인 = "로그인", 로그인 = 계정 id.

### 3.3 로그아웃/유지 매트릭스 (중요)

| 트리거 | 현재 사용자 | 촬영 데이터 |
|--------|-------------|-------------|
| 계정 메뉴 "로그아웃" | **해제** + **JWT 폐기** | 폐기 |
| 홈 버튼·각 화면 취소 | 유지 | 폐기 |
| 촬영 완료 후 자동 홈 복귀 | **유지** | 폐기 |
| **유휴 타임아웃 만료** | **유지(로그아웃 금지)** | 폐기 |
| 유휴 경고에서 "메인 화면으로" | 유지 | 폐기 |
| 전역 예외 복구 | 유지 | 폐기 |

> **유휴가 로그아웃하지 않는 이유**: 운영자가 로그인해 두고 손님이 번갈아 쓰는 키오스크 모델이다. 유휴마다 로그아웃하면 운영자가 계속 재로그인해야 한다. 반대로 명시적 로그아웃은 반드시 토큰까지 지워야 한다(§3.1).

## 4. P2 촬영 흐름 상세

### 4.1 `Home`

- [촬영하기] → **프레임 선택으로 직행**(로그인 화면을 강제로 거치지 않는다 = 게스트 직행).
- 시작 시 촬영 데이터만 초기화하고 **로그인은 보존**한다(로그인 사용자는 본인 커스텀 프레임을 쓴다).
- 타이틀·소제목은 브랜딩 값을 쓴다([41 §6](./41-local-data-and-file-formats.md)).

### 4.2 `FrameSelect`

**진입 시**
1. 공용 프레임 목록 로드 + (로그인 시) 본인 커스텀 프레임 로드 → 합쳐서 표시, **첫 항목 자동 선택**.
2. 권한 플래그 계산: `canCreateFrame` = `canDelete` = `역할이 프레임 쓰기 권한 보유`(= `advanced_user` 이상), `isPower` = manager/admin. **두 축은 별개다.**

**규격**
- **목록 로딩은 역할과 무관하다.** 프레임 쓰기 권한이 없는 `user`·`temp_user`의 기존 프레임도 목록에 그대로 보이고 촬영에 쓸 수 있다 — **편집·삭제 UI만 사라진다**. 숨기면 쓰던 프레임이 사라지는 체감 회귀가 된다.
- 공용 프레임 목록 우선순위(§5)를 따른다.

**프레임 로딩 국면 (it20)**

최초 실행은 로컬에 기본 프레임이 0개라 서버 다운로드를 기다린다. 그 대기를 4국면으로 규격화한다.
국면 확정은 로딩 종료 시 **항상** 일어난다 — `Loading`으로 남는 경로는 "화면이 이미 바뀐 경우"(결과 미기록)뿐이다.

| 국면 | 도달 조건 | 대기 오버레이 | 실패 카드 | 인라인 안내 | 목록 | [다음]·[만들기]·[선택 편집]·삭제 ✕ |
|------|-----------|:-------------:|:---------:|:-----------:|:----:|:----------------------------------:|
| `Loading` | 진입·[다시 시도] 직후 | **표시**(스피너 + 진행 문구 + [기다리지 않고 시작]) | – | – | scrim 아래 | **차단**(scrim + VM 가드) |
| `Ready` | 프레임 ≥ 1 + 대기 중단 없음. **서버 조회 즉시 실패(오프라인)도 이 국면** — 조용한 폴백 보존 | – | – | – | 표시 | 권한대로 |
| `Degraded` | 프레임 ≥ 1 + 대기 중단(무진행 30초·총 60초 상한 초과 / [기다리지 않고 시작] / 예외) | – | – | **표시** + [다시 시도] | 표시 | 권한대로 |
| `Failed` | 프레임 0개(로컬 폴백·fallback PNG 생성까지 실패) | – | **표시** + [다시 시도]/[메인으로] | (카드 문구로 대체) | scrim 아래(비어 있음) | **차단** |

- **대기 상한은 wall-clock이 아니라 무진행(inactivity) 기준**이다: 진행 보고(로컬 확인 / 서버 조회 / n번째 다운로드)가 올 때마다 30초 타이머를 재무장하므로 정상 진행 중인 다운로드를 잘라 "실패했다"는 거짓 안내를 띄우지 않는다. 총 60초는 별도 상한이며 **유휴 경고(120초)보다 짧다** — 대기 중에 "자리를 비우셨나요?" 팝업이 겹치지 않는다.
- **[기다리지 않고 시작]은 새 로딩을 시작하지 않는다.** 진행 중 로딩을 취소해 로컬 폴백으로 마감시킨다. 백그라운드 공유 작업은 계속 진행해 캐시를 완성하므로, 잠시 뒤 [다시 시도]가 성공할 가능성이 높다.
- **삭제 후 재스캔은 조용한 갱신이다**(§6.6). 목록이 이미 보이는 상태에서 전면 오버레이가 번쩍이지 않고, 네트워크 안내도 끼어들지 않는다. 단 재스캔 결과가 0개면 `Failed`, 종전이 `Failed`였는데 프레임이 생겼으면 `Ready`로 회복한다.
- `Degraded`·`Failed`를 방치하면 종전 안전망대로 유휴 경고가 위에 겹치고 홈으로 복귀한다 — **의도된 최종 탈출 경로**다.
- [다음]: 선택 프레임을 세션에 **고정**하고 촬영 세션을 시작한다. 이 시점이 **컷 수 해석 지점**이다 — 슬롯 수가 확정되어 있으므로 설정 의도를 실제 컷 수로 바꾼다(it17):
  - 자동(설정값 `0`): `실제 컷 수 = max(6, 슬롯 수 + 2)`
  - 고정(설정값 6/8/10): `실제 컷 수 = max(설정 컷수, 슬롯 수)`
  - 세션은 자동 여부(`isAutoCutCount`)도 함께 기억한다 — 이후 설정이 바뀌어도 이번 세션 표기는 불변.
- **이후 프레임 변경 불가**([05 §6 M11](./05-cross-platform-client-guide.md)).

### 4.3 `Guide`

세션의 확정값을 보여준다: 컷 수(**해석된 실제 값** — 자동이면 7·8도 나온다) · 컷당 카운트다운 초 · 슬롯 수 · 거울모드 여부. 자동으로 산출된 세션이면 컷 수 옆에 **"(자동)" 배지**를 붙인다(it17 — 설정에 없는 숫자가 뜨는 이유를 알린다). [촬영 시작] → `Capture`, [취소] → `Home`.

### 4.4 `Capture` — N컷 연속 촬영

**진입 절차(순서 고정)**

```
1. 카메라 시작(장치, 목표 종횡비, 거울 여부)
   실패 → 상태 Failed + "카메라를 찾을 수 없습니다." (시퀀스 시작 안 함)
2. Ready 게이트 대기 (최대 8000ms)
   조건: 누적 8프레임 수신 AND 최소 500ms 경과 AND 현재 fps > 0
   타임아웃 → 상태 Failed (무한 로딩 금지)
3. 세션 작업 폴더 생성 + 세션 동영상 경로 확정 + 세션 시작 시각 기록
4. 녹화 시작 (첫 컷 카운트다운 시작 시점 = 컷 루프 진입 직전)
5. 컷 루프 (i = 1..N)
     a. 카운트다운 (설정 초, 1초 간격 감소)
     b. 플래시 on (설정 on이면 화면 하양 오버레이) → 120ms 대기
     c. 셔터음 (설정 on이면 재생. 비동기·실패 무시 — 저장 흐름을 막지 않는다)
     d. 스틸 캡처 → 컷 버퍼에 추가
     e. 플래시 off        ← 캡처 "후"다. 플래시가 캡처 순간까지 켜져 있다
     f. 300ms 대기
6. 녹화 종료 (마지막 컷 후)
7. → CutSelect
```

| 요소 | 규격 |
|------|------|
| 카메라 상태 | `Initializing` / `Ready` / `Failed` 3값. 로딩·오류 오버레이를 상태로 구분 |
| 컷 수 | 설정값 {6, 8, 10} 또는 `0`=자동(기본 6). 실제 촬영 수 = 자동이면 `max(6, 슬롯 수 + 2)`, 고정이면 `max(설정 컷수, 슬롯 수)`. 자동은 허용 집합에 없는 **7**도 만들 수 있고 루프는 임의 정수 N을 견딘다 |
| 카운트다운 | 설정값 {3, 6, 8, 10}초(기본 6) |
| **[바로 촬영]** | 남은 카운트다운을 취소하고 즉시 셔터. **매 컷 사용 가능**. 세션은 계속 진행 |
| 플래시 | 하드웨어 제어 없음. **화면 하양 오버레이 120ms**가 규격 |
| 거울모드 | 기본 **on**. 프리뷰·스틸·녹화에 동일 적용(WYSIWYG) |
| 취소/이탈 | 카운트다운·시퀀스 취소 → 녹화 정지 → 카메라 정지 → 홈. 실패해도 예외 전파 금지 |

### 4.5 `CutSelect` — 컷 선택

| 요소 | 규격 |
|------|------|
| 썸네일 비율 | **대표 슬롯의 종횡비**로 컨테이너 비율을 맞춘다(WYSIWYG, 기본 3:4) |
| 토글 | 이미 선택된 컷 → 해제. 아니면 추가. **슬롯 수 초과 불가** |
| 선택 번호 | 선택 순서를 표시하고, 해제 시 이후 번호를 재계산 |
| [다음] 활성 조건 | `선택 수 == 슬롯 수` (정확히) |
| **[재촬영]**(전체) | 설정 `retakeEnabled`가 on일 때만 버튼 노출. `전체재촬영횟수 < retakeLimit`(1~3)일 때만 활성. 클릭 시 **컷·선택 폐기 + 카운터 증가, 프레임 유지** → `Guide`로 되돌아간다 |
| 컷별 재촬영 | **미구현**(비범위, [90 §2](./90-roadmap-and-future-work.md)) |

### 4.6 `Result` — 합성·필터

- 진입 시 즉시 합성해 미리보기를 만든다. 출력 파일명은 `final.{설정 확장자}`.
- 프레임은 변경 불가. **필터만 변경 가능**하며 변경 시 **전체 컷 일괄 재합성**한다(개별 컷만 바꾸지 않는다).
- 필터 노출 목록 = **항상 "원본"** + 설정에서 켜진 것(흑백/밝게/뷰티). "원본"은 항상 존재하고 끌 수 없다.
- **같은 파일 경로로 재합성**하므로 이미지 캐시를 우회해 갱신된 픽셀이 보이도록 해야 한다(플랫폼별 이미지 캐시 주의).
- 알고리즘·필터 파라미터는 [14 §5](./14-media-pipeline-spec.md).

### 4.7 [다음] 처리 순서 (Result → 이후)

**순서가 규격이다.** 로컬 저장이 업로드보다 먼저다([05 §6 M6](./05-cross-platform-client-guide.md)).

```
1. 타임랩스 생성        (세션 녹화본이 있고 인코더 사용 가능할 때. 실패 시 null로 계속)
2. 로컬 저장            (설정 on이면. 실패 시 null 반환 + 로그, 크래시 금지)
3. effective QR 판정  →  on 이면 Qr 화면 / off 이면 Done 화면
     isQrEnabled(raw설정, isLoggedIn, isTempUserBlocked):   ← QrEffectivePolicy(it13 §7.1b)
       ① 게스트(미로그인)        → false  (Qr을 건너뛰고 Done — QR은 계정 단위 과금·한도의 대상)
       ② TempUser이고 한도 초과  → false
       ③ 그 외                   → 설정 EnableQrDelivery 그대로
     저장된 설정 값은 어떤 경우에도 write하지 않는다(런타임 오버라이드일 뿐 — 한도 해제 시 즉시 원복).
```

> ⚠️ 2026-07-30 정정: 종전 서술("QR 전송 설정 on?")은 effective 판정을 생략해 **게스트도 Qr 화면에 간다고 오독**될 수 있었다. 실제로는 미로그인이면 항상 `Done`이다(`src/MCPhoto.Core/Settings/QrEffectivePolicy.cs`, 호출부 `ResultViewModel.Next`).

### 4.8 `Qr` — 업로드 및 QR 표시

**진입 절차**
```
1. 전송 대상 확정: (사진 전송 on && 파일 존재) / (타임랩스 전송 on && 파일 존재)
   둘 다 없으면 → "전송할 결과물이 없습니다." 안내로 종료(업로드 시도 안 함)
2. 업로드 3단계 실행 (진행률 표시: "사진 업로드 중" → "영상 업로드 중" → "마무리 중")
3. 성공 → QR 표시 + "업로드된 사진·영상은 {N}시간 후 자동 삭제됩니다."
   실패 → QR 숨김 + 사유별 안내 + [완료] / [재시도]
```

| 실패 유형 | 안내 문구 |
|-----------|-----------|
| 무료 사용 **시간** 초과(403 `TEMP_USER_TIME_EXCEEDED`) | "무료 사용 시간이 지났습니다. 관리자에게 문의해주세요." |
| 무료 사용 **횟수** 소진(403 `TEMP_USER_COUNT_EXCEEDED`) | "무료 사용 횟수가 소진되었습니다. 관리자에게 문의해주세요." |
| 그 밖의 실패 · 로컬 저장 **on** | "전송 실패 — 사진은 기기에 저장되었습니다." |
| 그 밖의 실패 · 로컬 저장 **off** | "전송에 실패했습니다. 로컬 저장을 켜면 기기에 보관됩니다." |

- **QR은 업로드 성공 후에만 노출**한다([05 §6 M5](./05-cross-platform-client-guide.md)).
- QR에 인코딩하는 문자열은 **다운로드 페이지 URL 전체**다([31 §7](./31-backend-api-reference.md)).
- [재시도]는 진행률·상태를 0에서 재시작한다. **동일 세션 ID로 재commit하면 409**이므로, 재시도 시 어느 단계부터 다시 하는지 결정해야 한다 — 권장: **새 세션 ID로 전 과정 재실행**(가장 단순하고 이중집계도 없다).
- 흐름을 막지 않는다: 실패해도 [완료]로 진행할 수 있고 결과물은 이미 로컬에 있다.

### 4.9 `Done`

- 진입 후 **6초** 뒤 자동 홈 복귀.
- **로그아웃하지 않는다**(§3.3). 촬영 데이터는 홈 복귀가 항상 폐기한다.

## 5. 공용 프레임 목록 우선순위 (오프라인 내구성)

```
① 로컬 공용 프레임        (번들 자산 + 서버 프레임 캐시)
② 서버 공용 기본 프레임    → 로컬에 "같은 이름"이 없는 것만 다운로드·캐시 (이름 기준 dedup)
③ 번들 이미지 폴더        (슬롯 정보가 없으면 2×2 격자 자동 생성)
④ 코드 생성 fallback 프레임
```

- 서버 미도달 시 ②를 건너뛰고 ③④로 폴백한다 → **오프라인에서도 촬영이 가능하다.**
- 로그인 사용자는 여기에 **본인 로컬 커스텀 프레임**이 추가된다.
- **이름 기준 dedup이 규격인 이유**: 편집으로 만든 로컬 사본이 원본 이름을 남겨 두므로, 원본을 서버에서 매번 다시 내려받는 일이 없다([41 §3](./41-local-data-and-file-formats.md)).
- fallback 프레임 스펙: 1200×1600(3:4) 하양 배경, 슬롯 4개(2×2), 슬롯 종횡비 3:4.

## 6. P3 프레임 저작 규격

### 6.1 권한 게이트 (3중)

```
1차: 역할이 프레임 쓰기 권한을 갖는가?  (advanced_user / manager / admin)
     아니면 → 출처를 보지 않고 즉시 불가
2차: 프레임 출처별 판정
3차: 저장 시점 재확인 (fail-closed)
```

**출처 분류** (프레임 id 접두 + 기본 프레임 플래그로 판정)

| 출처 | 판정 | 편집 | 로컬 삭제 |
|------|------|------|-----------|
| 본인 로컬 생성분 | id가 `local:` 접두 | 소유자 본인만 | ○ |
| 서버 공용 기본 | 접두 없는 실 id + `isDefault=true` | **power만** | **power만** |
| 번들 자산 | id가 `bundle:` 접두 | ✕ | ✕ |
| 코드 생성 fallback | id가 `fallback` 접두 또는 빈 id | ✕ | ✕ |

- 게스트는 전부 불가. `user`·`temp_user`는 **사용만**(읽기 전용).
- ⚠️ **로컬 삭제 판정은 소유자를 보지 않는다.** power가 사본 저장한 *공용* 로컬 프레임은 소유자 없이 로드되므로, 소유자 판정을 넣으면 삭제 능력이 사라진다. 타인의 개인 프레임은 목록 필터에서 이미 제외된다.
- 상세 매트릭스는 [60 §1.2·§2](./60-auth-accounts-and-roles.md).

### 6.2 편집 범위

**슬롯 배치만** 편집한다. 텍스트·스티커·배경 변경은 범위 밖([90 §2.1](./90-roadmap-and-future-work.md) 장기).

| 조작 | 규격 |
|------|------|
| 이미지 불러오기 | PNG/JPG/JPEG만, **10MB 이하**, 장변 4000px 초과 시 축소, **PNG로 재인코딩** |
| 슬롯 개수 | 1~6 |
| 슬롯 종횡비 | 4:3 / 3:4 / **1:1**. 기본 3:4 |
| 슬롯 크기 | 10~300% 스케일. **항상 원본 기준으로 계산**(누적 오차 방지), 중심 유지, 경계 클램프 |
| 드래그 이동 | 경계 클램프. 표시·드래그·클램프가 **동일한 좌표 변환**을 쓴다(WYSIWYG) |
| 저장 검증 | 개수 1~6 **AND** 전부 경계 내 **AND** 겹침 없음 |
| 이름 | 1~100자, **`_` 금지**, 파일시스템 금지문자 금지(치환하지 않고 거부) |

알고리즘(자동 배치·스케일·좌표 변환)은 [14 §4](./14-media-pipeline-spec.md).

### 6.3 저장 스코프 (역할별)

| 역할 | 신규 생성 저장 결과 |
|------|---------------------|
| `manager` / `admin` (power) | 로컬 공용 저장 + **확인 팝업에서 선택한 경우에만** 서버 공용 기본 프레임 등록(`POST /frames`). 공용 프레임을 서버에 배포하는 **유일한 경로** |
| `advanced_user` | **로컬 전용**. 개인 스코프로 저장(서버 쓰기 요청 없음) |
| `user` / `temp_user` / 게스트 | 저장 경로에 도달하지 않음 |

- 계정당 로컬 프레임 **최대 10개**. 초과 시 저장 거부.
- 저장 버튼 근처에 **이번 저장의 실제 결과**를 동적으로 안내한다(공용 목록 생성 / 사본 생성 / 덮어쓰기 / 내 프레임). power 신규 생성은 서버 등록 여부가 저장 시점의 선택이므로 **여기서 등록을 단정하지 않는다**.

**서버 등록 확인 팝업**

power가 **신규 생성 세션**(빈 편집기에서 시작 / 기존 프레임 불러오기로 시작 — §6.5)을 저장할 때만 뜬다. 노출 조건은 **DB insert 분기와 완전히 같은 조건**이다(`power AND 세션=신규 생성`) — 두 축이 갈라지면 "팝업은 떴는데 등록은 안 되는" 조용한 불일치가 생긴다.

| 항목 | 규격 |
|------|------|
| 체크박스 | "서버에도 등록" — **기본 on**. 팝업을 열 때마다 기본값으로 리셋한다(직전 선택 잔존 금지) |
| 캡션(고정) | *"체크하면 서버에 공용 기본 프레임으로 등록되어 다른 기기에서도 내려받습니다. 체크하지 않으면 이 기기에만 저장됩니다."* — 체크 상태와 무관한 고정 문구다(두 결과를 모두 명시) |
| 체크 on | `POST /frames` → 성공한 문서로 로컬 공용 저장(서버 문서 id 기록) |
| 체크 off | 로컬 공용 저장만. 서버 문서 id를 기록하지 않는다 |
| [취소] | 팝업만 닫는다. 저장·화면 전환·디스크 모두 무변경(편집 세션 유지) |
| **원자성** | 체크 on에서 서버 등록이 실패하면 **로컬 저장도 하지 않는다**(부분 성공 금지). 화면을 전환하지 않고 편집 세션을 유지한 채 *"서버 등록 실패: {사유} 이 기기에만 저장하려면 '서버에도 등록'을 해제하고 다시 저장해 주세요."* 를 안내한다 |

- ⚠️ **기본값이 삭제 확인 팝업("서버에서도 제거", 기본 off)과 갈리는 것은 관례 위반이 아니라 축이 다르기 때문이다** — 삭제는 파괴적 행위라 opt-in, 생성은 배포가 통상 목적이다.
- 원자성을 택한 이유: 로컬만 저장해 두면 재시도 시 **이름 충돌 가드가 자기 자신과 충돌**해 저장이 영구히 막힌다(§6.4).

### 6.4 편집은 로컬 전용 (정책)

- 편집기 상단에 **상시 배너**: *"이 프레임 편집은 이 기기에만 적용되며, 서버와 다른 기기에는 반영되지 않습니다."* (**편집 모드 전용** — 신규 생성 세션에는 표시하지 않는다. 배너는 정책, 저장 버튼 위 캡션은 이번 저장의 결과다)
- **편집 저장은 어떤 경로로도 서버를 호출하지 않는다.** `PUT /frames/{id}`는 호출 대상이 아니다([31 §4.13](./31-backend-api-reference.md)).
- **사본 분기(fork) 규칙** — 적용 대상은 **[선택 편집]으로 진입한 세션뿐이다**(§6.5의 "기존 프레임 불러오기"는 fork가 아니라 신규 생성이다). 출처가 "본인 로컬 생성분"이 **아니면**(= 서버 공용·번들·fallback) 원본 파일을 건드리지 않고 새 이름으로 신규 저장한다.
  - 사본 이름: `{원본이름} 사본` → 충돌 시 `{원본이름} 사본 2`, `… 3` … **99까지** → 그 뒤 `{원본이름} 사본 {8자리 난수}`.
  - 이름이 이미 `{X} 사본` 또는 `{X} 사본 N` 형태면 **X를 base로 되돌려** 무한 누적을 막는다.
  - 이름이 비면 base는 `새 프레임`(결과: "새 프레임 사본").
  - 사본에는 **서버 문서 id를 기록하지 않는다** → 로컬 사본은 서버 문서와 연결이 끊긴다.
  - 이름 제안값은 진입 시 1회 계산하고 사용자가 수정할 수 있다.
- 공용 스코프 저장 시 이름에 `_`가 있으면 *"이름에 '_'가 있어 공용 목록에서 보이지 않을 수 있습니다."* 를 **비차단** 경고로 남긴다.

**저장 전 검증 — 순서가 규격이다 (fail-closed)**

진입점이 [저장]과 서버 등록 확인 팝업 2개이므로 **양쪽에서 같은 판정을 재실행**한다. 한쪽만 검사하면 팝업 경로로 우회된다.

| # | 검사 | 차단 문구 |
|---|------|-----------|
| ① | 로그인 상태 | 로그인이 필요합니다. |
| ② | 프레임 쓰기 권한(`advanced_user` 이상) | 프레임을 만들 권한이 없습니다. |
| ③ | 슬롯 유효성(개수 1~6 · 경계 내 · 겹침 없음) | 슬롯이 겹치거나 프레임을 벗어났습니다. |
| ④ | **원본 덮어쓰기 가드** — fork 세션 + 공용 스코프에서 이름이 원본과 같음 | 원본과 같은 이름은 사용할 수 없습니다. 이름을 변경해 주세요. |
| ⑤ | 이름이 비어 있음(공백만도 포함) | 프레임 이름을 입력해 주세요. |
| ⑥ | 파일시스템 금지문자 포함 | 이름에 사용할 수 없는 문자가 있습니다. |
| ⑦ | **스코프 이름 충돌 가드** — 저장 스코프의 기존 이름과 겹침 | 이미 같은 이름의 프레임이 있습니다. 다른 이름을 입력해 주세요. |

- **④를 ⑦보다 먼저 두는 것이 규격이다.** ④는 "원본 이름"이라는 확정 사실만 보고 판정하지만 ⑦은 로컬 목록 열거에 의존해 **조회 실패 시 조용히 꺼진다**(비차단, 빈 집합으로 취급). ④가 남아 있어야 2중 방어가 성립한다.
- **⑦의 예외는 `[선택 편집]`으로 진입한 "본인 로컬 생성분" 세션 하나뿐이다** — 그 세션은 덮어쓰기가 의도이기 때문이다. 신규 생성·fork 세션은 차단한다. 로컬 저장은 같은 이름 파일을 **경고 없이 덮어쓰므로**, 가드가 없으면 다른 공용 프레임이 조용히 파괴된다.
- 비교는 **정확 일치(Ordinal)** — 로컬 파일명 규약과 같은 축이다.
- **⑤⑥은 서버 등록보다 먼저 수행해야 한다.** power 신규 생성은 서버 등록이 로컬 저장보다 먼저이므로, 선검증이 없으면 로컬 저장만 실패해 **"서버에는 있는데 이 기기에는 없는" 반쪽 상태**가 만들어진다(§6.3 원자성과 짝).
- **다루지 않는 것**(의도적 수용): 서버 측 동명 문서는 검사하지 않는다(네트워크 실패가 오프라인 저장을 막게 되므로). 서버 중복은 새 id가 부여되어 데이터 파괴가 아니라 목록 중복이며, 삭제는 이름 매칭 폴백으로 처리된다(§6.6).

### 6.5 기존 프레임 불러오기

- 생성 모드에서만 노출. **파일 탐색기가 아니라 앱 내부 선택 UI**(프레임 선택 화면과 동일한 썸네일 그리드).
- 후보 = 공용 프레임 전체 + 본인 개인 로컬. 번들·fallback도 **복사는 허용**(원본을 수정하지 않으므로 안전). 역할 필터 없음.
- 적용 시 **이미지는 읽기만** 하고, 슬롯은 `현재 프레임 폭 / 원본 이미지 폭` 배율로 보정해 값 복사한다.
- **임시 파일을 만들지 않는다**(디스크 쓰기는 저장 1회뿐) → "저장 전 취소 시 임시 파일 정리" 문제가 애초에 없다.
- **세션 정체성은 "신규 생성"이다 — 사본(fork)이 아니다.** 불러온 것은 이미지·슬롯이라는 *정보*이고, 만들어지는 것은 새 프레임이다. 따라서 power가 불러온 세션도 **서버 등록 대상**이며 저장 시 확인 팝업이 뜬다(§6.3).
- **이름을 자동으로 제안하지 않는다.** 사본 자동 네이밍(`{원본이름} 사본`)을 붙이지 않고, 사용자가 이미 입력한 이름이 있으면 **그대로 보존**한다(이름 먼저 → 이미지 나중 순서를 지원). 원본 이름을 그대로 채우면 §6.4 ⑦ 가드에 100% 걸리는 값을 제안하는 셈이므로 채택하지 않는다.
- 대신 이름 입력 필드 위에 **불러온 원본을 명시하는 캡션**을 노출한다: *"'{원본이름}'의 이미지·슬롯을 불러왔습니다. 새 프레임 이름을 입력해 주세요."* — "사본이 아니라 새로 만드는 중"이라는 유일한 시각 신호다. 이미지를 직접 다시 불러오면 이 캡션을 **비운다**(사실과 어긋나므로).
- 원본 보호는 이름이 아니라 **§6.4 ⑦ 스코프 이름 충돌 가드**가 담당한다.
- [취소]는 선택 UI만 닫고 편집기 상태·디스크 모두 무변경.

> 이력: it15는 이 경로를 "사본 세션(fork) + 서버 미등록"으로 규정했으나, **2026-07-30 사용자 결정으로 신규 생성으로 재정의**됐다. fork는 [선택 편집] 경로에만 남는다. 근거: `docs/design/wpf-frame-create-from-existing-and-server-register-design.md`.

### 6.6 프레임 삭제

```
1. 삭제 가능 판정: 권한(§6.1) AND 출처가 삭제 가능
2. 확인 UI (power에게는 "서버에서도 제거" 체크 제공)
3. 로컬 삭제는 항상 실행
4. power && 체크됨 → 서버 삭제 시도
     저장된 서버 문서 id로 시도 → 실패 시 이름 매칭으로 재시도
     결과를 명확히 안내 (성공 오인 금지)
```

| 결과 | 안내 문구 |
|------|-----------|
| 로컬 삭제 실패 | "로컬 프레임 파일을 삭제하지 못했습니다(사용 중일 수 있음)." |
| 서버 삭제 성공 | "서버에서도 삭제되었습니다." |
| 서버 문서 미발견 | "로컬은 삭제했지만 서버에서 '{이름}' 문서를 찾지 못했습니다." |
| 서버 삭제 예외 | "서버 삭제 실패: {사유}" |

- 로컬 삭제 성공 판정은 **파일이 실제로 사라졌는지**로 한다(예외를 삼키고 성공으로 보고하지 않는다).
- 서버 응답 `{deleted:false}`는 **성공이 아니다**([31 §4.14](./31-backend-api-reference.md)).

## 8. 설정 화면 규격

전체 항목·기본값·유효 범위는 [41 §2](./41-local-data-and-file-formats.md)가 진실원이다. 화면 규격만 여기 적는다.

### 8.1 그룹 구성

| 그룹 | 항목 |
|------|------|
| 촬영 | 컷 수 · 컷당 카운트다운 · 거울모드 · 플래시 · 셔터음 · 재촬영 사용(+ on일 때 횟수 제한 1~3) |
| 장치·표시 | 카메라 장치(선택 + 재검색 + 테스트) · 표시 모드 |
| 출력·전송 | 출력 포맷(JPG/PNG) · QR 전송(+ 하위 사진/타임랩스 토글 · 보관 시간 1~72h) · 로컬 저장 · 로컬 저장 경로 |
| 필터 | 원본(**항상 on·비활성**) · 흑백 · 밝게 · 뷰티 (노출 여부 토글) |
| 고급 | 다운로드 페이지 Base URL · Storage 버킷 · **서버 연결 상태(읽기 전용)** · [진단·상태] 버튼(로그인 전용) |

### 8.2 진입 게이트

| 사용자 | 게이트 |
|--------|--------|
| 게스트 | **무가드** — 바로 진입 |
| 로그인 사용자 | **PIN 게이트 통과 필수**(매번). PIN 미설정이면 **최초 설정 강제** |

- 역할 검사는 **없다**(설정은 키오스크 운영자가 접근하는 열린 화면). 계정·관리 기능은 별 화면으로 분리돼 있다.
- 설정 화면에 있는 동안 설정 진입 버튼은 숨긴다(자기 화면 재진입 방지).

### 8.3 게스트 편집 제한

게스트에게는 다음 항목이 **OFF로 표시 + 컨트롤 비활성 + 옆에 "로그인 필요" 안내 상시 표시**된다: 거울모드 · 재촬영(횟수 포함) · 필터 노출 3종 · QR 전송(하위 포함) · 다운로드 페이지 URL · Storage 버킷.

- **런타임 동작은 저장된 관리자 값대로 유지된다.** 제한되는 것은 편집 권한뿐이고, 저장 시 이 항목들은 **기록하지 않아 기존 값을 보존**한다(값을 0/false로 덮어쓰지 않는다).
- TempUser는 무료 한도 초과 시 QR 관련 편집만 추가로 차단된다.

### 8.4 저장 절차 (순서가 규격)

```
1. (데스크톱) 현재 창 기하 캡처   ← 표시 모드 값을 갱신하기 "전"에 해야 한다
2. 화면 입력값 → 설정 객체 반영 → 저장(내부에서 범위 보정)
3. 저장된 값을 다시 화면으로 재반영 (보정된 값이 보이도록)
4. 표시 모드 적용
```

- **저장 성공/실패를 정직하게 표시**한다. 실패 시 오류 안내(색상도 구분). 성공 오인 절대 금지.
- 1번을 2번보다 뒤에 하면 창모드 → 전체화면 저장 시 직전 창 위치를 잃는다.
- 저장/닫기 버튼은 스크롤 영역 밖에 고정해 항상 노출한다.

### 8.4.1 창 최소 크기 (it21)

최소 크기는 **표시 모드가 소유**한다. 창(Window) 요소에 하드코딩하지 않는다.

| 모드 | MinWidth × MinHeight | 근거 |
|------|----------------------|------|
| 창모드 | **800 × 600** | 운영자 점검 용도. 종전 하한(1280×720)이 기본 창 크기와 같아 **창을 전혀 줄일 수 없었다** |
| 전체화면 | **0 × 0**(해제) | Maximized가 패널 크기를 그대로 따르게 한다. 1024×768 같은 작은 패널에서 창이 화면을 넘기던 결함도 함께 사라진다 |

- ⚠️ 전체화면 분기에서 **하한 해제를 `Maximized` 적용보다 먼저** 수행해야 한다. 뒤에 두면 한 프레임 동안 창이 화면을 넘긴다.
- 모드가 바뀌지 않은 저장(`DisplayApplyAction.None`)에서는 하한도 건드리지 않는다 — "설정 저장이 창 기하를 바꾸지 않는다"는 규격을 지킨다.
- 좁은 창에서 잘릴 수 있는 모달(프레임 피커·QR 팝업)은 `ScrollViewer`로 감싸 전체 접근을 보장한다. 화면 본문은 기존 wrap·스크롤 메커니즘에 위임한다.

### 8.5 QR 전송 토글 연동 규칙

```
정규화: QR 전송 on && 사진 off && 타임랩스 off  →  QR 전송을 off로 정규화 (하위 값은 보존)
재활성: QR 전송이 off → on 으로 바뀌는 순간      →  하위 둘 다 강제 on
```

설정 로드 중에는 이 연동을 억제한다(로드된 값이 즉시 변형되지 않게).

### 8.6 카메라 장치 선택

- 장치 열거는 수백 ms~수 초가 걸릴 수 있으므로 **백그라운드**로 수행한다.
- 목록이 비면 선택·테스트 컨트롤을 비활성하고 안내한다.
- 저장된 장치 식별자가 목록에 없으면 **첫 장치로 보정**한다.
- 장치 식별 방식은 플랫폼마다 다르다(인덱스 / uniqueID / cameraId). **설정 키의 의미를 "플랫폼별 장치 식별자"로 정의**하고 저장 형식만 맞추면 된다([41 §2.2](./41-local-data-and-file-formats.md)).

## 9. 모달 규격

### 9.1 카메라 테스트

- 목적: **실촬영과 동일한** 프리뷰·플래시·셔터 재현. **저장하지 않는다.**
- 절차: 창 먼저 표시(로딩 오버레이) → 카메라 시작 → 모달로 대기 → 닫힌 뒤 카메라 확실히 정지.
- 카메라가 이미 다른 화면에서 열려 있을 수 있으므로 **정지 후 지정 장치로 재시작**한다(시작 함수가 멱등이면 "이미 실행 중"으로 무시될 수 있다).
- Ready 게이트는 실촬영과 **동일 규칙**(누적 8프레임 + 500ms + fps>0, 8초 타임아웃).
- 셔터: 플래시 옵션까지 재현하고 캡처 결과는 **폐기** + "저장되지 않았습니다" 안내.

### 9.2 진단·상태

- 진입: 설정 [고급] → [진단·상태] (**로그인 전용**).
- 4개 섹션(데스크톱 기준):
  > **웹 클라이언트는 6섹션이다** — 위 4개에 **개발자 문의**(이메일 + 복사 · Version · Build Date · Web Deploy Date)와
  > **앱**(버전 · Service Worker 상태 + [지금 적용] · PWA 설치 여부)이 더해진다. 4섹션의 **상위집합**이라 모순이 아니다.
  > 규격은 [web-client/03 §15.2](../web-client/03-screens-spec.md).

| 섹션 | 표시 |
|------|------|
| 카메라 | 연결 장치 수 + 목록 |
| 비디오 인코더 | 사용 가능 여부 + 경로/식별 정보 |
| **서버 연결** | 백엔드 구성 여부 · 주소 · 버킷 · **게이트 키 "설정됨/미설정"만**(값 절대 미표시) · 현재 로그인 계정 |
| 로그 | 로그 위치 **상시 텍스트 표시** + [로그 열기/공유] |

- 정상/이상을 색으로 구분한다.
- **"구성됨"은 "도달 성공"이 아니다.** 실도달 확인은 `GET /health` 프로브다.
- 로그 열기 실패해도 크래시 없이 로그만 남긴다. 경로 텍스트가 상시 노출되므로 수동 탐색이 가능하다.

### 9.3 PIN 입력

- 2모드: **확인** / **최초 설정**(새 PIN 2회 일치).
- PIN은 **정확히 4자리 숫자**.
- **연속 5회 불일치 시 창을 닫는다**(게이트 미통과).
- **불일치마다 1.5초 입력 비활성**.
- 네트워크·서버 오류는 **실패 횟수에 세지 않고** 게이트도 열지 않는다: *"확인할 수 없습니다. 네트워크를 확인하세요."*
- 서버에는 계정 잠금이 없다 — 위 두 완화가 클라이언트의 전부다([31 §4.5](./31-backend-api-reference.md)).

## 10. P4 운영 화면 규격

> 계정 관리·관리자 도구는 **같은 화면의 모드 분기**다. 두 화면의 [닫기]는 **오버레이 진입 전 화면으로 복귀**한다(§2.3) —
> 계정 메뉴로 두 모드를 오가더라도 복귀 지점은 진입 전 화면을 유지해야 한다. 유지하지 않으면 [닫기]가 무반응이 된다.

### 10.1 계정 관리 (내 정보 + PIN 변경)

- 진입: 계정 메뉴 → "계정 관리"(로그인 전원). **PIN 게이트** 통과 필수(설정 진입과 **같은 PIN·같은 다이얼로그**).
- 표시(읽기 전용): 계정 id · 이메일 · 로그인 방식 · 역할 · 가입일.
  - 로그인 방식은 `"google"` → **"Google SSO"**. **모르는 값은 "알 수 없음"** 으로 표시한다(조용한 오인 방지).
- PIN 변경: 기존 PIN 있으면 현재 PIN 확인 후 새 PIN 2회 일치. 미설정이면 최초 설정.
- **비밀번호 개념은 없다.** 비밀번호 변경 UI를 만들지 않는다.

### 10.2 관리자 도구

- 진입: 계정 메뉴 → "관리자 도구"(**power만 노출 + 커맨드 가드**).
- 항목: 사용자 관리 진입 · 전역 무료 한도 편집(**admin만**) · 앱 종료(플랫폼이 허용할 때).

### 10.3 사용자 관리

| 액션 | 게이트 |
|------|--------|
| 목록 조회 | power (화면 진입 자체가 power 전용) |
| 삭제 | power **AND** 대상이 자신과 같거나 낮은 위계 **AND** 자기 자신 아님 |
| 타 계정 PIN 재설정 | power **AND** 대상이 **엄격히 낮은 위계**(동급 차단 — **매니저 PIN은 admin만**) **AND** 자기 자신 아님. 관리자가 새 4자리 PIN을 2회 입력(고정값 아님) |
| 역할 변경 | 서버 매트릭스와 1:1인 옵션 필터([31 §4.7](./31-backend-api-reference.md)). 자기 계정 행은 콤보 미노출 |

- 삭제는 **행위자와 같거나 낮은 위계에만 노출**한다(예: manager는 admin 계정을 삭제할 수 없다). **PIN 재설정만 한 칸 좁아 동급도 미노출**이다 — PIN이 진입의 유일한 자격증명이라 동급끼리 서로의 진입 자격을 갈아치우지 못하게 한다.
- UI 미노출 + 커맨드 가드 + 서버 최종 강제(403 우아 처리)의 3중 방어.
- 삭제 성공 시 "소유 프레임 포함"임을 알린다(cascade).
- 목록 조회 실패는 **빈 목록으로 폴백하지 않고** 오류로 표시한다: "사용자 목록을 불러올 수 없습니다."

## 11. 오류·실패 처리 정책 (전 화면 공통)

| 상황 | 정책 |
|------|------|
| 미처리 예외 | 로그 + **홈 복귀**. 크래시 금지. 로그인 유지 |
| 화면 진입/이탈 중 예외 | 삼켜 로그하고 흐름 계속 |
| 서버 미도달 | 기능별로 다르게: 로그인 **불가** / 게스트 촬영·로컬 저장 **정상** / 프레임 목록 **로컬 폴백** / 업로드 **우아 실패** / PIN 게이트 **fail-closed** / 무료 한도 조회 **fail-open** |
| 저장·삭제 실패 | 반드시 사용자에게 표시(성공 오인 금지) |
| 로그에 남기면 안 되는 것 | JWT · 게이트 키 · 인가 코드 · PKCE verifier · state · nonce · PIN |

**오프라인 능력 요약**: 백엔드에 도달하지 못하면 로그인·업로드·QR은 실패하지만 **게스트 촬영과 로컬 저장은 계속 동작한다.** 오프라인 로그인 폴백은 **없다**(어떤 계정으로도 로그인 불가).

## 12. P1 소비자 클라이언트 규격 (결과물 열람)

### 12.1 상태 4종 (한 번에 하나만 노출)

| 상태 | 진입 조건 | 화면 |
|------|-----------|------|
| **loading** | 초기 진입·재시도 시작 | 스피너 + "결과물을 불러오는 중…" |
| **success** | 문서 존재 **AND** 미만료 | 사진/영상 미리보기 · 다운로드 · 만료 고지 |
| **expired** | 문서 부재 **OR** `expiresAt < now` **OR** `expiresAt` 파싱 실패 **OR** 존재하는 미디어 전부 로드 실패 | "보관 기간이 지나 만료되었습니다" |
| **error** | 토큰 없음·형식 오류 **OR** 초기화 실패 **OR** 네트워크·권한 예외 | "일시적인 오류" + [다시 시도] |

- **재시도는 error 상태에서만** 제공한다. 만료·부재는 재시도 대상이 아니다.

### 12.2 토큰 파싱

- 진입 URL의 `s` 파라미터에서 토큰을 얻는다.
- 검증은 **경량**만: 빈 값 또는 200자 초과 → error. **엄격한 형식 정규식을 강제하지 않는다**(존재하지 않는 문서 조회가 무효 토큰을 걸러 준다).

### 12.3 만료 판정 (fail-safe)

세 갈래 모두 **안전측(만료로 처리)** 로 기운다.

| 판정 | 조건 | 결과 |
|------|------|------|
| 문서 부재 | 조회 결과 없음 | expired |
| 필드 부재/파싱 실패 | `expiresAt` 없음·타입 불일치·유효하지 않은 시각 | expired |
| 시각 경과 | `expiresAt < now` | expired |
| 미만료 | 위 어느 것도 아님 | success |

- **무효 토큰과 삭제된 문서를 구분하지 않는다**(토큰 존재 여부 노출 방지).

### 12.4 미디어 "옵션 꺼짐" vs "로드 실패" 구분

만료 판정을 통과한 뒤 URL이 없다면 그것은 **"전송 옵션이 꺼진 것"**(의도적 제외)이다.

| 상태 | 화면 처리 |
|------|-----------|
| URL 있음 | 프리뷰 + 다운로드 버튼 + 저장 힌트 |
| URL null (옵션 꺼짐) | 프리뷰·다운로드·실패 문구를 모두 숨기고 **"전송 옵션이 꺼져 있어 제공되지 않습니다"** 안내만. **중립 정보 톤**(만료·실패와 시각적으로 구분) |
| URL 있으나 로드 실패 | 프리뷰 숨김 + "불러올 수 없습니다(만료되었을 수 있습니다)" + 다운로드 비활성 |

- **2차 방어**: 문서는 미만료인데 존재하는 미디어가 **전부** 로드 실패하면 expired로 폴백한다(파일이 이미 물리 삭제된 고아 상태 대응). 옵션 꺼짐은 실패로 세지 않는다.
- 영상 섹션은 옵션 꺼짐이어도 섹션 자체를 숨기지 않고 안내만 노출한다.
- 둘 다 옵션 꺼짐은 계약상 발생하지 않지만 방어적으로 처리한다(성공 화면 유지 + 안내 2개).

### 12.5 표기·다운로드

- 만료 시각은 **사용자 로컬 시간**으로 포맷해 "이 사진·영상은 {만료 시각}에 만료됩니다."로 표시한다.
- 다운로드 폴백 힌트: "저장이 안 되면 이미지를 길게 눌러(모바일)/우클릭(PC) 저장하세요."
  - 이유: 파일이 다른 오리진(Storage)에 있어 브라우저의 강제 다운로드 속성이 무시된다. **iOS 한정 문제가 아니라 공통**이다.
  - 네이티브 클라이언트로 만들 때는 이 제약이 없으므로 직접 저장 API를 쓰면 된다(힌트 불필요).
- 접근성: 로딩 영역에 라이브 리전, 실패한 다운로드는 비활성 상태를 접근성 트리에도 반영, 터치 타깃 최소 48px, 가로 스크롤 금지, 모션 감소 설정 존중, 다크 모드 지원.

## 14. 사용자 문구 카탈로그

현행 문구를 그대로 옮겼다. 다국어를 도입하기 전까지는 이 문구를 유지하는 편이 운영 문의 대응에 유리하다(i18n은 [90 §2.1](./90-roadmap-and-future-work.md) 장기 항목).

| 상황 | 문구 |
|------|------|
| 카메라 미연결 | 카메라를 찾을 수 없습니다. |
| 전송 대상 없음 | 전송할 결과물이 없습니다. |
| 업로드 진행 | 업로드 중... / 사진 업로드 중 / 영상 업로드 중 / 마무리 중 |
