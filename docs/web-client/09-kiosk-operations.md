# 09 · 키오스크 운영 가이드 (설치·설정·백업·진단)

| 항목 | 값 |
|------|-----|
| 문서 | 웹 앱을 **실제 부스로 운영**하기 위한 기기·브라우저 설정과 운영 절차 |
| 대상 독자 | 부스를 설치·운영하는 사람(개발자 아님) + 배포 담당 |
| 왜 필요한가 | 웹 앱은 **브라우저 정책을 코드로 강제할 수 없다.** 무인 키오스크 성립 여부는 이 문서의 설정에 달려 있다(WR2·WR4) |
| 갱신 규칙 | 브라우저 정책 변경·지원 기기 추가 시 갱신 |

---

## 1. 무엇이 앱의 책임이고 무엇이 운영의 책임인가

| 항목 | 앱이 하는 것 | **운영 설정이 필요한 것** |
|------|--------------|---------------------------|
| 전체화면 | Fullscreen API 요청 + 이탈 시 재진입 배너 | **ESC 탈출 차단** → 브라우저 키오스크 모드 |
| 화면 꺼짐 | `Screen Wake Lock` 요청 | **OS 전원·화면 보호기 설정** |
| 카메라 권한 | `getUserMedia` 요청 + 거부 시 안내 | **매번 묻지 않도록 사이트 권한 허용** |
| 자동 시작 | — | **OS 자동 실행 등록** |
| 저장소 영속 | `persist()` 요청 + PWA 설치 유도 | **PWA 설치**(WebKit 저장소 회수 면제) |
| 데이터 백업 | 내보내기 기능 제공 | **주기적 내보내기 실행** |

## 2. 브라우저 키오스크 모드 (WR4 — 필수)

### 2.1 Windows — Chrome / Edge

```bat
:: 바탕화면 바로가기 또는 배치 파일
start "" "C:\Program Files\Google\Chrome\Application\chrome.exe" ^
  --kiosk ^
  --app=https://mcphoto-955fb-kiosk.web.app ^
  --user-data-dir="C:\photobooth\chrome-profile" ^
  --autoplay-policy=no-user-gesture-required ^
  --disable-pinch ^
  --overscroll-history-navigation=0 ^
  --no-first-run ^
  --disable-features=TranslateUI
```

| 플래그 | 효과 |
|--------|------|
| `--kiosk` | 전체화면 고정. **주소창·탭 없음, ESC로 나갈 수 없다** |
| `--user-data-dir` | **전용 프로필** — 저장소가 다른 브라우징과 섞이지 않고 데이터 삭제 위험이 줄어든다. **반드시 지정할 것** |
| `--autoplay-policy=no-user-gesture-required` | 셔터음 자동재생 제약 완화 |
| `--disable-pinch` / `--overscroll-history-navigation=0` | 확대·스와이프 뒤로가기 오조작 차단 |

**종료 방법(운영자용)**: `Alt+F4` 또는 작업 관리자. 손님이 알 수 없게 키보드를 치우거나 물리 잠금.

**Edge**는 같은 플래그를 대부분 지원하며(`msedge.exe --kiosk …`), 기업 환경이라면 **Edge 키오스크 모드 정책**(그룹 정책 / `assigned access`)이 더 강력하다.

### 2.2 Windows 할당된 액세스(Assigned Access) — 가장 강한 락다운

Windows 설정 → **키오스크 모드 설정** → Microsoft Edge 선택 → "공용 브라우저" → 시작 URL 지정.
- 손님이 OS로 빠져나갈 수 없다. 무인 운영에 권장.
- 단 카메라 권한·전원 설정은 별도로 미리 잡아 둬야 한다(§3·§4).

### 2.3 Android (태블릿)

| 방법 | 설명 |
|------|------|
| **PWA 설치 + `display: fullscreen`** | 홈 화면에 추가하면 주소창 없이 실행된다. 가장 간단 |
| **앱 고정(Screen pinning)** | 설정 → 보안 → 앱 고정. 최근 앱 → 핀 아이콘. 해제에 PIN 요구 설정 가능 |
| 기업 관리(MDM) | 전용 기기 모드(COSU)로 완전 락다운 |

권장 조합: **PWA 설치 + 앱 고정 + 화면 자동 꺼짐 없음**.

### 2.4 iOadOS / iOS

| 방법 | 설명 |
|------|------|
| **홈 화면에 추가**(PWA) | Safari 공유 → 홈 화면에 추가. 주소창 없이 전체화면 실행 + **저장소 회수 면제** |
| **안내 접근(Guided Access)** | 설정 → 손쉬운 사용 → 안내 접근 ON + 암호 설정. 앱 실행 후 홈 버튼 3회(또는 상단 버튼 3회)로 시작 → **앱을 벗어날 수 없다** |
| 자동 잠금 해제 | 설정 → 디스플레이 및 밝기 → 자동 잠금 → **안 함** |
| 카메라 권한 | 설정 → Safari → 카메라 → **허용**(웹사이트별 설정에서 해당 도메인 허용) |

권장 조합: **홈 화면에 추가 + 안내 접근 + 자동 잠금 안 함**.

### 2.5 macOS

Chrome `--kiosk`(§2.1과 동일 플래그) 또는 Safari 전체화면 + `시스템 설정 → 잠금 화면 → 디스플레이 끄기: 안 함`.

## 3. 카메라 권한 사전 승인 (필수 — 매번 묻지 않게)

| 플랫폼 | 방법 |
|--------|------|
| **Chrome/Edge(데스크톱)** | 앱을 한 번 열어 **[허용]** 을 누르면 그 오리진에 기억된다(전용 프로필이면 유지). 또는 정책 `VideoCaptureAllowedUrls`로 사전 허용 |
| **Chrome 정책(기업)** | `VideoCaptureAllowedUrls = ["https://mcphoto-955fb-kiosk.web.app"]` → 프롬프트 없이 허용 |
| **Android Chrome** | 최초 [허용] 후 기억됨. 사이트 설정에서 확인 |
| **iOS/iPadOS Safari** | 설정 → Safari → 카메라 → **허용** 또는 "웹사이트별 설정"에서 도메인 허용. **[한 번만 허용]을 누르면 매번 묻는다** |

| 확인 | 앱의 **진단 모달 → 카메라 섹션**에 권한 상태(granted/prompt/denied)와 장치 목록·실제 해상도가 표시된다 |

> 카메라 권한이 `denied`가 되면 앱에서 되돌릴 수 없다. **브라우저 사이트 설정에서 재허용**해야 한다. 이 문구를 촬영 화면 오류 안내에 포함해 두었다([03 §6.3](./03-screens-spec.md)).

## 4. 화면 꺼짐·절전 (WR2)

앱은 `Screen Wake Lock`을 요청하지만 **지원과 신뢰도가 기기마다 다르다.** OS 설정이 진짜 방어선이다.

| 플랫폼 | 설정 |
|--------|------|
| Windows | 설정 → 전원 → 화면 끄기: **안 함**, 절전 모드: **안 함**. 화면 보호기 **없음** |
| macOS | 시스템 설정 → 잠금 화면 → 디스플레이 끄기: **안 함** |
| Android | 설정 → 디스플레이 → 화면 자동 꺼짐: **가장 길게**(+ 개발자 옵션 "충전 중 화면 켜짐") |
| iPadOS/iOS | 설정 → 디스플레이 및 밝기 → 자동 잠금: **안 함** |
| 공통 | **상시 전원 연결**. 배터리 절약 모드는 백그라운드 스로틀링을 강화해 촬영을 방해한다 |

## 5. PWA 설치 (권장 — 저장소 보호)

| 플랫폼 | 절차 |
|--------|------|
| Chrome/Edge 데스크톱 | 주소창 오른쪽 설치 아이콘 → 설치 |
| Android Chrome | 메뉴 → "홈 화면에 추가" / 설치 배너 |
| iOS/iPadOS Safari | 공유 → **홈 화면에 추가** |

| 효과 | 내용 |
|------|------|
| 저장소 회수 면제 | **WebKit의 "7일 무상호작용 삭제" 규칙에서 벗어난다**(설정·프레임·결과물 보호 — [00 §3.2](./00-scope-and-decisions.md)) |
| `persist()` 승인률 | Chromium에서 설치된 사이트는 영속 승인 가능성이 높다 |
| 전체화면 | `display: fullscreen`으로 주소창 없이 실행 |

> 진단 모달에 **PWA 설치 여부**와 **저장소 영속 승인 여부**가 표시된다. 둘 다 "예"인 상태를 목표로 한다.

## 6. 데이터 백업 절차 (R1 완화 — 운영 필수)

브라우저 데이터가 삭제되면 **설정·개인 프레임·로컬 결과물 사본**이 사라진다. 서버에 있는 것(계정·공용 프레임·업로드된 결과물)은 영향 없다.

| 주기 | 작업 | 방법 |
|------|------|------|
| 설정 변경 직후 | **설정 내보내기** | 설정 → [설정 내보내기] → 파일을 USB·클라우드에 보관 |
| 프레임 추가 직후 | **프레임 내보내기** | 설정 → [프레임 내보내기] → zip 보관. **이 zip은 Windows 앱의 `Frame\` 폴더에 풀어 넣어도 인식된다** |
| 행사 종료 후 | 결과물 회수 | 설정 → [보관된 결과물] → 내보내기, 또는 (데스크톱 Chromium) 지정 폴더에서 직접 복사 |
| 장기 미사용 전 | 위 3개 전부 | — |

**복구**: 설정 → [설정 가져오기] / [프레임 가져오기].

> **하지 말 것**: 브라우저 "인터넷 사용 기록 삭제"·프로필 삭제·시크릿 모드 사용. 전용 프로필(`--user-data-dir`)을 쓰면 실수로 지울 위험이 줄어든다.

## 7. 계정·PIN 운영 주의

| 항목 | 내용 |
|------|------|
| **QR을 쓰려면 로그인해야 한다** | 게스트(비로그인) 촬영은 **사진이 기기에만 남고 QR·다운로드 링크가 만들어지지 않는다.** 손님에게 QR을 주는 부스라면 **운영자 계정으로 로그인한 상태를 유지**해야 한다(새로고침하면 로그인이 풀린다 — 아래 참조) |
| 신규 계정 | Google로 처음 로그인하면 서버가 **`temp_user`(임시 유저)** 로 자동 생성한다. 무료 QR 한도(기본 48시간/30회)가 걸린다 |
| 승격 | 관리자·매니저가 **사용자 관리 → 역할 콤보**에서 지정한다. 프레임을 만들어야 하면 **고급 유저** 이상 |
| PIN | 설정·계정 관리 진입에 필요. **처음 진입 시 강제로 설정**하게 된다 |
| **PIN 분실** | **앱에서 복구할 수 없다.** 서버 스크립트로만 초기화 가능: `node web/functions/scripts/migrate-google-only-accounts.mjs --clear-pin <계정id> --apply` |
| PIN 5회 실패 | **5분간 그 기기에서 입력 차단**(WD16) |
| 새로고침 | 로그인이 해제된다(정상 동작 — 보안 설계). 촬영은 게스트로 계속 가능 |

## 8. 증상별 빠른 진단

| 증상 | 먼저 볼 곳 | 흔한 원인 |
|------|-----------|-----------|
| 카메라가 안 잡힌다 | 진단 → 카메라 | 권한 거부 / 다른 앱이 점유 / HTTPS 아님 |
| 프리뷰가 뒤집혀 있다 | 설정 → 거울모드 | 정상 동작(기본 on). 끄면 반전 없음 |
| 촬영 중 화면이 꺼진다 | §4 전원 설정 | Wake Lock 미지원 기기 |
| 카운트다운이 느려진다 | 탭이 비활성인지 | 다른 탭·앱으로 전환 → 앱이 촬영을 취소하고 홈으로 간다(정상) |
| QR이 안 나온다 | **먼저 로그인 여부** → 진단 → 서버 연결 | ① **게스트로 촬영함**(가장 흔함 — QR은 로그인 전제다. 게스트는 `완료`로 바로 끝난다) ② TempUser **무료 한도 초과** ③ 업로드 실패(네트워크·CORS). **어느 경우든 결과물은 기기에 남아 있다** |
| QR을 스캔하면 앱이 열린다 | 설정 → 다운로드 페이지 Base URL | **kiosk 도메인으로 잘못 설정됨.** P1 사이트 도메인이어야 한다 |
| 타임랩스가 없다 | 진단 → 비디오 인코더 | 브라우저가 H.264 인코딩 미지원(정상 축소 — 사진만 전송) |
| 로그인이 안 된다 | 진단 → 서버 연결 + 로그 | 서버 확장 미적용(B1·B2) / 리디렉트 URI 불일치 / 도메인 제한 |
| 설정이 사라졌다 | §6 백업 | 브라우저 데이터 삭제 / 시크릿 모드 / 장기 미사용 후 저장소 회수 |
| 합성이 실패한다 | 로그(프레임 이미지 CORS) | 버킷 CORS 미구성([08 §5](./08-server-and-infra-prerequisites.md)) |
| 전체화면이 풀린다 | §2 키오스크 모드 | Fullscreen API만으로는 ESC를 막을 수 없다 |

**로그 꺼내기**: 설정 → 진단·상태 → **[로그 내보내기]** → `mcphoto-log-YYMMDD_HHMM.log` 파일을 개발자에게 전달.

## 9. 설치 체크리스트 (부스 1대 세팅)

- [ ] 기기가 지원 브라우저 매트릭스에 있다([10 §6](./10-testing-and-acceptance.md))
- [ ] 상시 전원 연결 + 화면 자동 꺼짐 **없음**(§4)
- [ ] 브라우저 **전용 프로필** + 키오스크 모드로 앱 실행(§2)
- [ ] 카메라 권한 **허용**으로 고정(§3)
- [ ] **PWA 설치**(§5)
- [ ] 진단 모달에서 확인: 카메라 정상 · 인코더 경로 · 서버 연결 정상 · 저장소 영속 승인 · 버전
- [ ] 설정 확인: 컷 수 · 카운트다운 · 거울모드 · QR 전송 · 보관 시간 · **다운로드 페이지 Base URL이 P1 도메인**
- [ ] 로컬 저장 폴더 지정(데스크톱 Chromium이면)
- [ ] **1회 실촬영 테스트**: **로그인 후** 촬영 → 합성 → 업로드 → 폰으로 QR 스캔 → 다운로드까지 확인(게스트로는 QR이 나오지 않는다 — §7)
- [ ] 설정·프레임 **내보내기 백업** 1회 수행(§6)
- [ ] 운영자용 종료 방법 숙지(§2.1)
