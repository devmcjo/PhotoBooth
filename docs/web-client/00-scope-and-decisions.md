## 1. 제품 정의 (한 문장)

> **브라우저를 전체화면으로 띄우면 Windows 키오스크 앱과 똑같이 동작하는 셀프 포토부스.** 터치 모니터 + Windows PC를 사지 않고도 태블릿·노트북·기존 PC로 부스를 구성할 수 있게 하는 것이 목적이다.

### 1.1 목표

| # | 목표 | 검증 방법 |
|---|------|-----------|
| G1 | Windows 앱의 **13개 화면 + 7개 모달 전부**를 웹에 구현한다 | [03 화면 명세](./03-screens-spec.md)의 화면별 완료 기준 |
| G2 | **동작·타이밍·판정이 Windows와 동일**하다(픽셀은 허용 오차 내) | 공유 테스트 벡터 + 골든 이미지([10](./10-testing-and-acceptance.md)) |
| G3 | **내장 카메라**를 Windows·macOS·Android·iOS·iPadOS에서 모두 쓴다 | 실기기 매트릭스([10 §6](./10-testing-and-acceptance.md)) |
| G4 | 서버 계약(`docs/analysis/31`)을 **한 글자도 바꾸지 않는다**(서버 확장은 인증 리디렉트·게이트 키·CORS뿐) | [08](./08-server-and-infra-prerequisites.md) |
| G5 | 기능 1개를 추가할 때 **모든 클라이언트에 동일하게 반영**할 수 있도록 차이를 한 표에 모아 둔다 | [12](./12-web-vs-windows-differences.md) |

### 1.2 비목표

| # | 비목표 | 이유 |
|---|--------|------|
| N1 | 기존 다운로드 페이지(`web/public/`) 재작성 | 이미 완성·검증됨. **손대지 않는다**(회귀 위험). 새 앱은 별 사이트로 배포([01 §5](./01-tech-stack-and-structure.md)) |
| N2 | 외장 DSLR 카메라 · 사진 프린터 연동 | 브라우저에 해당 SDK 경로가 없다. Windows 앱에서도 **미지원 스캐폴드**(설정 키만 존재)라 기능 손실이 아니다 → WD8 |

## 3. 기존 판정 재검토 — 무엇이 실제로 막히고, 무엇이 풀리는가

`docs/analysis/05 §7.4`는 웹에서 **계약·불변식을 만족할 수 없는 항목(W-BLOCK) 5건**을 근거로 촬영(P2)·개인 프레임(P3)을 제외 권장했다. 사용자 결정으로 범위를 넓히므로, **그 5건을 하나씩 다시 판정**한다.

### 3.1 재판정 결과 요약

| 기존 판정 | 항목 | 재판정 | 해결 수단 |
|-----------|------|--------|-----------|
| **WB1** 막힘 | 세션 녹화 → 타임랩스(mp4/H.264 강제) | **해결됨** | 브라우저에서 H.264/mp4를 직접 만든다(WebCodecs + JS MP4 muxer). 배속 변환 대신 **촬영 중 프레임 샘플링**으로 목표 길이를 맞춘다 → WD2 |
| **WB2** 막힘 | 결과물 로컬 보관(M6: 업로드 이전 저장) | **조건부 해결** | OPFS에 **즉시·무제스처** 기록(업로드 이전) + 데스크톱 Chromium은 실제 폴더 저장 + 명시적 내보내기 → WD3, 불변식 **M6-W**로 재정의 |
| **WB3** 막힘 | 개인(로컬) 프레임 저장 | **해결됨** | ① 근거 2 "웹에 소비자가 없다"는 **웹이 촬영까지 하게 되면서 소멸**한다 ② 근거 1(저장소 회수)은 키오스크 운영 조건에서 실질 위험이 낮다(§3.2) + 내보내기/가져오기로 복구 가능 → WD4 |
| **WB4** 막힘 | 앱 종료(관리자) | **막힘 유지** | 브라우저 탭을 스크립트로 닫을 수 없다. **미노출** + "키오스크 종료"로 대체 → WD5 |
| **WB5** 막힘 | 로그 영속 | **해결됨** | IndexedDB 링버퍼 로거 + 진단 화면 조회 + 파일 내보내기 → WD6 |

정책 의존(W-RISK) 항목의 처리는 §3.3.

### 3.2 WB3 재판정의 근거 (저장소 회수 위험)

기존 판정은 **WebKit이 "설치되지 않은 사이트의 script-writable 저장소를 약 7일 무상호작용 시 삭제"** 하는 규칙을 들었다. 이 규칙의 트리거는 **"7일간 그 사이트와 상호작용이 없음"** 이다.

| 상황 | 7일 규칙 적용 |
|------|---------------|
| 손님이 QR로 한 번 열어보는 페이지 | **적용됨**(위험 실재) |
| **매일 영업하는 키오스크** | 매일 상호작용이 발생 → **트리거되지 않는다** |
| 홈 화면에 추가(PWA 설치)된 키오스크 | **면제** |
| 몇 주 쉬었다 다시 켜는 행사용 기기 | 적용될 수 있음 → **복구 수단 필요** |

따라서 판정은 "불가"가 아니라 **"운영 조건 + 복구 수단으로 관리 가능"** 이다. 웹 클라이언트는 세 가지를 함께 둔다.

1. **PWA 설치를 권장·유도**한다(설치 시 WebKit 면제 + Chromium `persist()` 승인률 상승).
2. `navigator.storage.persist()`를 시작 시 요청하고, **결과를 진단 화면에 정직히 표시**한다("영속 승인됨 / 미승인 — 장기 미사용 시 삭제될 수 있음").
3. **설정·프레임 내보내기/가져오기(JSON+PNG 번들)** 를 제공한다. 유실 시 30초 안에 복구할 수 있으면 치명적 결함이 아니다.

> **정직한 잔여 위험**: 위 3중 장치에도 "브라우저 데이터 삭제"·시크릿 모드·기기 초기화는 막을 수 없다. 이것은 **웹 클라이언트의 고유 성질**이며 [12 §3](./12-web-vs-windows-differences.md)에 등재하고 운영 문서([09 §6](./09-kiosk-operations.md))에 백업 절차를 남긴다.

### 3.3 W-RISK 항목 처리표

| # | 위험 | 처리 | 상세 |
|---|------|------|------|
| WR1 | 클라이언트 설정이 저장소 회수로 사라짐 | localStorage + **내보내기/가져오기** + PWA 설치 권장. 서버 저장은 미도입(엔드포인트 없음) | [05 §2](./05-storage-and-persistence.md) |
| WR2 | 화면 꺼짐으로 촬영 중단 | `Screen Wake Lock` 요청 + **OS 전원 설정을 운영 필수 조건으로 문서화** | [09 §4](./09-kiosk-operations.md) |
| WR3 | 탭 백그라운드 스로틀링으로 타이머·인코딩 붕괴 | ① 모든 타이머를 `performance.now()` **실경과 기반**으로 구현 ② `visibilitychange`(hidden)에서 촬영 시퀀스를 **안전 취소 + 홈 복귀** | [02 §6](./02-app-shell-and-navigation.md), [04 §4](./04-media-pipeline-web.md) |

| WR5 | JWT 메모리 전용 vs 새로고침 | **M2 유지.** 새로고침 = 재로그인이 정상 흐름. 게스트 촬영은 새로고침과 무관하게 동작 | WD9, [07 §4](./07-auth-and-permissions-web.md) |
| WR6 | 배포 게이트 키가 브라우저에 공개됨 | **공개를 전제**하고 웹 전용 키를 별도 발급. 게이트 키는 인증이 아니라 배포 식별자이며 역할·한도는 서버가 JWT로 강제한다 | WD10, [08 §4](./08-server-and-infra-prerequisites.md) |
| WR7 | 버킷 CORS 미구성 | **P0 선행 작업.** 업로드 PUT뿐 아니라 **서버 프레임 이미지로 합성할 때도 필수**(canvas 오염) | [08 §5](./08-server-and-infra-prerequisites.md) |
| WR8 | 모바일 브라우저 메모리 한계 | 컷을 즉시 JPEG로 OPFS에 내리고 `ImageBitmap`은 썸네일 용도로만 유지, 합성은 순차 처리 + `close()` 즉시 해제. 성능 예산 명시 | [04 §8](./04-media-pipeline-web.md) |

## 4. 빼는 것 — 웹에서 무의미하거나 불가한 항목

**설정 키는 삭제하지 않는다.** 저장된 값을 보존하고 **UI만 미노출**한다(다른 클라이언트와 설정 호환성 유지, `docs/analysis/41 §2.1` 계약).

| 항목 | 설정 키 | 처리 | 이유 |
|------|---------|------|------|
| 표시 모드(전체화면/창모드) | `DisplayMode` | **미노출** | 브라우저에 창 스타일 개념이 없다. 전체화면은 Fullscreen API + OS 키오스크 모드로 대체 → WD7 |
| 창 위치·크기 기억 | `WindowBounds` | **미노출** | 동상 |
| 외부 카메라(DSLR) | `ExternalCameraEnabled` | **미노출** | 브라우저에 SDK 경로 없음. Windows에서도 미지원 스캐폴드 → WD8 |
| 사진 프린터 | `PhotoPrinterEnabled` | **미노출** | 동상 |
| 앱 종료(관리자) | — | **미노출** | 스크립트로 탭을 닫을 수 없다. 대체 = "키오스크 종료"(전체화면 해제 + 로그아웃 + 홈) → WD5 |
| 로컬 저장 경로 직접 입력 | `LocalSavePath` | **경로 텍스트 입력 대신 [저장 폴더 선택] 버튼** | 브라우저는 임의 경로 문자열을 쓸 수 없다. File System Access 폴더 핸들로 대체 → WD3 |
| 로그 폴더 열기 | — | **[로그 내보내기]로 대체** | 파일 시스템 탐색기를 열 수 없다 → WD6 |
| 설정 파일 경로 폴백 3단 | — | **개념 자체가 불필요** | 브라우저 저장소는 경로 선택이 없다. 유지해야 하는 성질("쓰기 실패를 사용자에게 알린다")만 이식 |

진단 모달의 4섹션도 웹 항목으로 치환한다(아래는 Windows 4섹션의 치환이며, 웹은 여기에 **개발자 문의·앱 2섹션을 추가**해 총 6섹션이다 — [03 §15.2](./03-screens-spec.md)).

|------|---------|-----|

## 6. 불변식 — Windows 규격 M1~M16의 웹 적용

`docs/analysis/05 §6`의 16개 불변식은 **웹에서도 전부 지킨다.** 단 M6만 웹 변형(M6-W)이 있다.

| # | 불변식 | 웹에서 어떻게 지키나 |
|---|--------|----------------------|
| M1 | 로그아웃 시 JWT 즉시 폐기 | 세션 스토어의 `currentUser` 변경을 **구독하는 단일 지점**에서 토큰을 지운다(버튼에 걸지 않는다). [07 §4.2](./07-auth-and-permissions-web.md) |
| M2 | JWT는 메모리에만 | 모듈 스코프 변수 1개에만 보관. Redux/Zustand persist 미들웨어 대상에서 **명시적으로 제외**. WD9 |
| M3 | 유휴 타임아웃은 로그아웃하지 않는다 | 유휴 만료 = 홈 복귀 + 촬영 데이터 폐기. `clearUser` 경로를 만들지 않는다 |
| M4 | 성공 오인 금지 | 저장(설정·프레임·결과물)·삭제·업로드 실패를 전부 토스트/인라인으로 표시. **OPFS 쓰기 실패도 표시**한다 |
| M5 | QR은 업로드 성공 후에만 | 업로드 3단계 전부 성공 후 QR 렌더. 실패 시 QR 영역을 렌더하지 않는다 |
| **M6-W** | **결과물 로컬 보관은 업로드 분기 이전에 수행한다.** 웹에서 "보관"은 **OPFS(또는 선택된 로컬 폴더) 기록 완료**를 뜻한다 | 합성 직후 OPFS 기록 → (폴더 핸들 있으면 폴더에도 기록) → **그다음** 업로드 분기. OPFS 기록이 실패하면 사용자에게 알리고 `SaveLocalCopy` 실패로 처리 |
| M7 | `finalImageUrl`·`timelapseUrl` 중 최소 1개 non-null, 둘 다 끄면 업로드 안 함 | QR 토글 정규화(`docs/analysis/41 §2.4`)를 순수 함수로 이식 + 업로드 직전 재확인. **effective QR 판정**(`qrEffectivePolicy` — 게스트·TempUser 초과 오버라이드)은 그보다 앞선 게이트이며 **저장된 `EnableQrDelivery`를 write하지 않는다** |
| M8 | URL null = "전송 옵션 꺼짐"을 만료·실패와 구분 | P1 페이지 책임(현행 구현 유지). 웹 앱은 이 규칙을 깨는 commit을 만들지 않는다 |
| M9 | PIN 게이트 fail-closed / 한도 조회 fail-open | [07 §5·§6](./07-auth-and-permissions-web.md) |
| M10 | 권한 = UI 미노출 + 커맨드 가드 + 서버 강제 3중 | 컴포넌트 렌더 가드 + 액션 함수 첫 줄 가드 + 서버 403 우아 처리 |
| M11 | 프레임은 촬영 시작 전 확정, 이후 변경 불가 | 세션 스토어에 프레임을 고정하고 `Capture` 이후 setter를 노출하지 않는다 |

|---|--------|-------------|------|
| R1 | 브라우저 데이터 삭제·시크릿 모드에서 설정·프레임·결과물 사본이 사라진다 | 브라우저의 본질적 성질. 대신 서버 업로드본과 내보내기 백업이 있다 | [09 §6](./09-kiosk-operations.md) 백업 절차 |
| R2 | 타임랩스가 일부 구형 브라우저에서 미제공된다 | 계약상 합법(`timelapseUrl=null`)이고 진단 화면에 판정을 표시한다 | 브라우저 지원 매트릭스([10 §6](./10-testing-and-acceptance.md))로 기기 선정 가이드 |
| R3 | ESC/제스처로 전체화면을 벗어날 수 있다 | 브라우저 보안 정책. OS 키오스크 모드가 진짜 방어선이다 | [09 §2](./09-kiosk-operations.md) 필수 설정 |
| R4 | 해상도·fps가 기기마다 다르다 | `getUserMedia` constraints는 요청일 뿐이다. 로직은 실제 값 기준으로 계산되므로 깨지지 않는다 | 진단 화면 표시 + 실기기 검증 |
| R5 | 게이트 키가 공개된다 | 게이트 키는 인증이 아니다. 역할·과금 한도는 서버가 JWT로 강제한다 | 웹 전용 키 + 폐기 가능성 + rate limit 권장 |
| R6 | iOS Safari의 메모리 한계로 10컷 세션에서 탭이 죽을 수 있다 | 완전 보장 불가 | 컷 즉시 JPEG화 + 순차 합성 + 성능 예산([04 §8](./04-media-pipeline-web.md)) + 실기기 검증 필수 |

## 8. 착수 전 체크리스트

코드를 쓰기 전에 아래가 끝나 있어야 한다. 상세·명령은 [08](./08-server-and-infra-prerequisites.md).

- [ ] **P0-1** Google Cloud Console에 **Web application** 유형 OAuth 클라이언트 생성 + 리디렉트 URI 등록
- [ ] **P0-2** 서버 `redirectUri` 검증을 **허용 목록 방식**으로 확장(B1)
- [ ] **P0-3** 서버 audience를 **client_id 목록**으로 일반화(B2)
- [ ] **P0-4** 웹 전용 배포 게이트 키 발급(`CLIENT_API_KEYS`에 추가)(B4)
- [ ] **P0-5** **Storage 버킷 CORS 구성**(업로드 PUT + 프레임 이미지 GET)(B5)
- [ ] **P0-6** Hosting 멀티사이트 타깃 `kiosk` 생성
- [ ] P1-1 웹 게이트 키에 Origin 제한·rate limit(권장)
- [ ] P1-2 번들 기본 프레임 PNG + `.slots` 자산 준비(오프라인 폴백용)

> **선행 작업이 안 끝났을 때도 진행 가능한 범위**: P0-5(CORS)만 있으면 **촬영 전 흐름 + 로컬 보관 + 업로드 3단계 + QR 렌더**까지 **구현**할 수 있다. 단 **QR은 로그인 전제**이므로(§2 표 8행) 화면 흐름을 통한 종단 검증은 로그인이 필요하고, Step 11 단계에서는 effective QR 판정을 목으로 고정해 검증한다([08 §1.1](./08-server-and-infra-prerequisites.md), [11 Step 11](./11-wbs.md)). P0-1~4는 **로그인·프레임 저작·계정·관리 화면**의 선행 조건이다.
