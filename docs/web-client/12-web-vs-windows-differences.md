# 12 · Web ↔ Windows 차이 보고서

| 항목 | 값 |
|------|-----|
| 문서 | 웹 클라이언트가 Windows 앱과 **다르게 동작하는 모든 항목**의 단일 목록 |
| 왜 필요한가 | 기능 1개를 추가할 때 **모든 클라이언트에 동일하게 반영**하려면, 이미 다른 부분이 어디인지가 한 표에 있어야 한다 |
| 규칙 | **여기 등재되지 않은 동작 차이는 버그다.** 웹에서만 다르게 만들었다면 반드시 행을 추가한다([10 §8](./10-testing-and-acceptance.md) 수락 기준) |
| 갱신 규칙 | 차이가 생기거나 해소될 때 즉시 갱신. 해소된 항목은 삭제하지 않고 **"해소"로 표시**해 이력을 남긴다 |

## 0. 한눈에 보는 요약

| 분류 | 개수 | 사용자에게 보이나 |
|------|:----:|-------------------|
| **A. 완전히 동일** — 동작·타이밍·판정·문구 | 대부분 | — |
| **B. 기술만 다름** — 내부 구현 대체, 동작 동일 | 12건 | ✕ |
| **C. 동작이 다름** — 사용자 체감 차이 있음 | **10건** | **○** |
| **D. 미노출·제거** — 웹에서 의미 없거나 불가 | **7건** | ○(항목이 없음) |
| **E. 웹에만 있음** — 추가 기능 | **9건** | ○ |
| **F. 웹 고유 제약** — 운영 조건·리스크 | **6건** | 조건부 |

**가장 중요한 3가지 차이**

1. **결과물이 "기기 폴더"가 아니라 "브라우저 저장 공간(OPFS)"에 남는다** — 데스크톱 Chromium에서만 실제 폴더에도 저장 가능(C1).
2. **타임랩스를 만드는 방식이 다르다** — 세션 전체 녹화 없이 프레임 샘플링으로 직접 인코딩. 일부 브라우저에서는 **미제공**(C2·C3).
3. **새로고침·탭 종료 시 로그아웃된다** — JWT 메모리 전용 규칙(M2)의 결과(C6).

## B. 기술만 다름 (동작은 동일 — 사용자에게 보이지 않음)

| # | 항목 | Windows | Web | 동일성 근거 |
|---|------|---------|-----|-------------|
| B1 | 카메라 획득 | OpenCV `VideoCapture`(DirectShow) + 전용 스레드 | `getUserMedia` + `requestVideoFrameCallback` + Worker | 같은 가공(거울→크롭)을 프레임당 1회, 3소비자 공유([04 §1](./04-media-pipeline-web.md)) |
| B2 | 거울 반전·크롭 | `Cv2.Flip` + ROI | Canvas `setTransform` + `drawImage` 소스 사각형 | 동일 식·동일 정수 연산([04 §9](./04-media-pipeline-web.md)) |
| B3 | 합성·리사이즈 | OpenCV `INTER_AREA` | `createImageBitmap(resizeQuality:"high")`(폴백 단계 축소) | 골든 이미지 허용 오차 내([10 §4.2](./10-testing-and-acceptance.md)) |
| B4 | 필터 연산 | OpenCV | WebGL2 셰이더(CPU 폴백) | 흑백·밝게는 동일 식, 뷰티는 근사 |
| B5 | 이미지 인코딩 | `imwrite`(JPEG q95) | `convertToBlob('image/jpeg', 0.95)` | 바이트는 다르지만 픽셀은 허용 오차 내 |
| B6 | 설정 저장 | INI + 실행경로→ProgramData→LocalAppData **3단 폴백** | localStorage 단일 위치 | 유지 성질은 "쓰기 실패를 사용자에게 알린다" — 폴백은 Windows 전용 개념 |
| B7 | 로컬 프레임 저장 | `Frame\{이름}.png` + `.slots`, **파일명 접두**로 공용/개인 구분 | IndexedDB 메타(`scope`·`ownerId`) + OPFS PNG | `analysis/41 §3.2`가 명시 허용한 대체. 의미(공용=전원/개인=본인)와 `_` 금지는 유지 |
| B8 | 세션 임시 폴더 | `%ProgramData%\MCPhoto\sessions\{guid}` | OPFS `sessions/{sessionId}/` | 시작 시 잔재 일괄 정리 규격 동일 |
| B9 | QR 생성 | QRCoder `PngByteQRCode`, **ECC Q**, 기본 모듈 20px(`QrService.cs`) | JS QR 라이브러리, **ECC Q**(동일), 모듈 픽셀은 화면 크기에 맞춤 | 인코딩 문자열 동일(다운로드 페이지 URL 전체) + ECC 레벨 동일. 모듈 픽셀 크기는 계약이 아니다 |
| B10 | 업로드 진행률 | HTTP 스트림 래핑 | **XHR `upload.onprogress`**(`fetch`는 업로드 진행률 미제공) | 단계 라벨·합산 로직 동일(순서 비의존) |
| B11 | OAuth 인가 코드 수신 | loopback `HttpListener` + 시스템 브라우저 | **같은 브라우저 리디렉트** `/oauth2callback` | PKCE·state·nonce·3분 타임아웃 동일. 서버 확장 필요([08 §4](./08-server-and-infra-prerequisites.md)) |

| B14 | 타임랩스 인코더의 라이선스 노출 | **ffmpeg.exe 동봉(GPLv3)** — 준수 의무(전문 동봉·고지·대응 소스 제공)가 배포물에 붙는다(`design/wpf-ffmpeg-licensing-and-distribution-design.md`) | **브라우저 내장** `WebCodecs`/`MediaRecorder` — **GPL 노출이 없다.** 추가 의존은 MP4 muxer(MIT 계열)뿐이며 `webclient/THIRD-PARTY.md`에 기록한다 | 산출물 규격(H.264/MP4·배속·해상도)은 동일. 라이선스 의무만 다르다 — **웹이 유리한 방향의 차이** |

## C. 동작이 다름 (사용자 체감 차이 — 10건)

> **이 표가 이 문서의 핵심이다.** 각 항목은 [00 §5](./00-scope-and-decisions.md)의 결정(WD)에 대응한다.

### C1. 결과물 로컬 보관 위치와 방식 (WD3 · M6-W)

| | Windows | Web |
|---|---------|-----|
| 어디에 | `{실행경로}\result\mcphoto_YYMMDD_HHMM\` | **OPFS**(브라우저 내부 저장 공간) `results/mcphoto_YYMMDD_HHMM/` |
| 실제 폴더 저장 | 항상 | **데스크톱 Chromium에서만**(운영자가 폴더를 1회 선택하면 그 폴더에도 기록) |
| 파일 탐색기에서 바로 보이나 | ○ | 폴더 지정 시 ○ / 아니면 **✕**(앱의 [보관된 결과물]에서 내보내야 함) |
| 설정의 경로 항목 | 경로 문자열 직접 입력 | **[폴더 선택] 버튼**(브라우저가 실 경로를 노출하지 않음) |
| 용량 정리 | 무기한 영구 보관 | **2GB / 200세션 초과 시 오래된 것부터 자동 삭제**(브라우저 할당량 때문) |
| 불변식 | M6("업로드 이전 저장") | **M6-W**("업로드 이전 **OPFS(또는 선택 폴더) 기록 완료**") |

**사용자 체감**: 데스크톱 Chromium + 폴더 지정이면 Windows와 사실상 동일하다. 태블릿·iOS에서는 "앱 안에 보관되고 [기기에 저장]으로 꺼낸다".

### C2. 타임랩스 생성 방식 (WD2)

| | Windows | Web |
|---|---------|-----|
| 방식 | 세션 전체를 30fps로 `session.mp4` 녹화 → ffmpeg `setpts` 배속 재인코딩 | **녹화 없음.** 촬영 중 OPFS에 스풀(≤15fps) → **종료 시 실제 세션 길이로 균등 선별 → 30fps 타임라인 mp4 인코딩**([04 §7.2](./04-media-pipeline-web.md)) |
| 산출물 | `session.mp4`(업로드 안 함) + `timelapse.mp4` | **`timelapse.mp4`만** |
| 결과 길이 | 10~15초(짧은 세션은 원속) | **동일**(같은 배속 함수를 실경과에 적용 — [바로 촬영] 다용 세션도 원속 산출) |
| **실효 소스 프레임레이트** | 30fps | **최대 15fps**(스풀 수집률 — 출력 타임라인은 30fps, 부족분은 프레임 duration 연장). 움직임이 많은 장면에서 약간 덜 부드러울 수 있다 |
| 계약 | `video/mp4` + H.264 무음 | **동일** |

**사용자 체감**: 결과물은 같다. 다만 웹은 **"세션 원본 영상"이 존재하지 않는다**(향후 원본 영상 기능을 추가하려면 웹은 별도 설계 필요).

### C3. 타임랩스 미제공 가능성 (WD2 · 브라우저 의존)

| | Windows | Web |
|---|---------|-----|
| 가용성 | ffmpeg 번들이므로 **항상 가능** | **브라우저 H.264 인코딩 지원 여부에 따라 다름** |
| 미지원 시 | (해당 없음) | 타임랩스 **미제공**(`timelapseUrl = null`) — 계약상 합법, 사진만 전송 |
| 사용자 안내 | — | `Guide` 화면 하단 안내 + 진단 모달에 인코더 경로 표시 |

**사용자 체감**: 구형 브라우저·일부 기기에서 **영상이 없고 사진만** 전송된다.

### C4. 전체화면·키오스크 모드 (WD7)

| | Windows | Web |
|---|---------|-----|
| 설정 항목 | 표시 모드(전체화면/창모드) + 창 위치·크기 기억 | **없음**(미노출) |

| 진짜 락다운 | 앱 자체로 성립 | **브라우저 키오스크 모드가 필수**([09 §2](./09-kiosk-operations.md)) |

### C5. 카메라 권한 (브라우저 정책)

| | Windows | Web |
|---|---------|-----|
| 권한 요청 | 없음(앱이 바로 장치 열기) | **브라우저 권한 대화상자**(최초, 또는 설정에 따라 매번) |
| 거부 시 | (해당 없음) | 전용 안내 + [다시 시도]. **앱에서 되돌릴 수 없고 브라우저 설정에서 재허용해야 한다** |
| 장치 이름 | WMI FriendlyName | **권한 부여 전에는 빈 문자열** → "카메라 1/2"로 표시 |

### C6. 새로고침·탭 종료 시 로그아웃 (WD9 · M2의 결과)

| | Windows | Web |
|---|---------|-----|
| 세션 수명 | **프로세스 수명**(앱을 켜 둔 동안 로그인 유지) | **페이지 수명**(새로고침·탭 종료 시 로그아웃) |
| 이유 | JWT를 메모리에 두는 규칙(M2)이 동일하게 적용됨 | 동상 — 페이지가 곧 프로세스다 |
| 영향 | — | 운영자가 관리 작업 전 재로그인 필요. **게스트 촬영은 영향 없음** |

### C7. 탭 비활성 시 촬영 취소 (WM4)

| | Windows | Web |
|---|---------|-----|

### C8. 앱 종료 / 로그 폴더 열기 (WD5·WD6)

| | Windows | Web |
|---|---------|-----|
| 관리자 도구의 앱 종료 | 있음 | **없음** → **[키오스크 종료]**(전체화면 해제 + 로그아웃 + 홈) |
| 로그 확인 | `explorer.exe`로 로그 폴더 열기 | **[로그 내보내기]**(`.log` 다운로드) + 진단 모달에서 최근 항목 조회 |
| 로그 저장 | 파일 일 롤링 14개 | **IndexedDB 링버퍼**(14일 또는 5,000건) |

### C9. PIN 잠금 강화 (WD16)

| | Windows | Web |
|---|---------|-----|
| 완화 장치 | 5회 실패 → 창 닫힘, 실패마다 1.5초 | **동일 + 5회 실패 시 5분간 기기 단위 입력 차단**(앱 재시작에도 유지) |
| 계정 단위 잠금 | 없음(DoS 회피) | **동일하게 없음** |

> 이 항목은 **웹이 규격보다 강화**된 경우다. `docs/analysis/61 §7.3`이 권장한 방향이므로, **Windows에도 같은 강화를 적용하는 것을 후속 과제로 제안**한다(§7 참조).

### C10. JWT 만료(401) 감지 시 세션 해제 (웹 추가 동작)

| | Windows | Web |
|---|---------|-----|
| Bearer 필수 호출이 401(만료·위조) | 국소 처리만(만료 감지·자동 해제 경로 없음 — `analysis/60 §5` 개선 여지로 등재된 상태) | **토큰 폐기 + 세션 사용자 해제** + "세션이 만료되었습니다. 다시 로그인해 주세요." 화면 유지(게스트로 계속). PIN 검증의 401은 예외(불일치로 해석 — 세션 불변) |
| 근거 | — | 만료 토큰은 어차피 무효이고, 로그인 표시가 남으면 운영자가 QR이 되는 상태로 오인한다([07 §4.3](./07-auth-and-permissions-web.md), [02 §5.2](./02-app-shell-and-navigation.md) 매트릭스 등재) |

> Windows에 같은 처리를 도입하는 것을 후속 과제로 제안한다(§H7).

**설정 키는 삭제하지 않고 값을 보존한다** — 다른 클라이언트와의 설정 호환성 유지.

| D4 | 사진 프린터 | `PhotoPrinterEnabled` | 동상 | — |
| D5 | 앱 종료(관리자) | — | 스크립트로 탭을 닫을 수 없다 | [키오스크 종료](C8) |

| D7 | 설정 파일 경로 폴백 3단 | — | 브라우저 저장소에 경로 선택이 없다 | (개념 불필요) |

## G. 서버·인프라에 생긴 변경 (웹 때문에 필요해진 것)

Windows에는 없던 요구다. 상세는 [08](./08-server-and-infra-prerequisites.md).

| # | 변경 | 왜 |
|---|------|-----|
| G1 | `redirectUri` 허용 목록화(B1) | 웹은 https 리디렉트를 쓴다(현재 loopback만 허용) |
| G2 | audience 목록화(B2) + 요청 본문에 **`clientKind`** 추가 | 웹 전용 OAuth 클라이언트 id/secret이 별도다. **웹은 `clientKind:"web"`을 보내고 Windows는 미지정(=desktop)으로 무변경 통과**한다([07 §2.2](./07-auth-and-permissions-web.md)) |
| G3 | 웹 전용 게이트 키 발급(B4) | 브라우저에 키가 공개되므로 분리·폐기 가능성 확보 |
| G4 | **Storage 버킷 CORS**(B5) | ① 서명 URL PUT ② **서버 프레임 이미지로 합성**(canvas 오염 방지 — 기존 문서에 없던 새 요구) |
| G5 | Hosting 멀티사이트 | P1 페이지와 CSP·캐시를 분리하기 위함 |
| — | ~~client_secret 조건부(B3)~~ | **불필요** — Web application 유형은 secret이 있다 |
| — | ~~타임랩스 서버 변환(B6)~~ | **불필요** — 클라이언트에서 해결(C2) |

**Windows 클라이언트에 미치는 영향**: **없다.** G1·G2는 기존 loopback·기존 client_id 경로를 그대로 통과시키고, G3는 기존 키를 유지하며, G4는 브라우저 요청에만 영향을 준다. 각 항목의 회귀 테스트가 이를 고정한다([08 §4](./08-server-and-infra-prerequisites.md)).

## H. 후속 제안 (웹 작업에서 발견된 개선점)

웹을 만들며 드러난 것 중 **다른 클라이언트에도 적용할 만한 것**이다. 결정은 사용자·팀에 맡긴다.

| # | 제안 | 근거 |
|---|------|------|
| H1 | **PIN 기기 단위 잠금(5회 → 5분)을 Windows에도 적용** | `docs/analysis/61 §7.3`이 이미 권장. 웹이 먼저 구현(C9)하므로 규격을 맞추면 드리프트가 사라진다 |
| H2 | **로컬 결과물 정리 정책을 Windows에도 도입** | Windows는 무기한 영구 보관이라 디스크가 찬다(`analysis/41 §5` 개선 항목). 웹은 2GB/200세션 정책을 이미 갖는다(C1) |
| H3 | **설정·프레임 내보내기/가져오기를 Windows에도** | 기기 교체·백업 동선이 현재 없다. 웹의 zip 형식이 `Frame\` 규칙과 호환되므로 그대로 재사용 가능(E1·E2) |
| H4 | **`docs/spec-vectors/` 공유 벡터를 정식 자산으로 유지** | 두 클라이언트의 순수 로직 드리프트를 자동으로 잡는다([10 §3](./10-testing-and-acceptance.md)) |
| H5 | 개인 프레임 서버 저장(D7 결정) 재검토 | 도입하면 기기 교체·저장소 회수 문제가 함께 해소된다(`design/multiplatform-client-architecture.md §7.1`에 비용 분석 있음) |
| H6 | 진단 화면에 **실제 해상도·fps** 표시를 Windows에도 | 현장 품질 문의 대응에 유용(E7) |
| H7 | **JWT 만료(401) 감지 시 세션 해제·재로그인 안내를 Windows에도** | `analysis/60 §5`가 "만료 감지 경로 없음"을 개선 여지로 등재해 둔 상태다. 웹이 먼저 구현(C10)하므로 규격을 맞추면 드리프트가 사라진다 |

## I. 기능 추가 시 규칙 (모든 클라이언트 동기화)

새 기능 1개를 추가할 때 **아래 순서**를 지킨다. 사용자가 이 문서 세트를 요청한 근본 이유가 이것이다.

```
1. 규격을 먼저 쓴다
     docs/analysis/13(동작·문구·타이밍) / 14(미디어) / 31(API) / 41(로컬 데이터) / 60·61(권한·인증)
     → "어떤 플랫폼에서든 이렇게 동작해야 한다"를 확정
2. 공유 테스트 벡터를 추가·수정한다
     docs/spec-vectors/*.json → 양쪽 테스트가 동시에 실패하는 상태를 만든다
3. 각 클라이언트를 구현한다
     Windows: src/MCPhoto.*        (설계는 docs/design/wpf-*)
     Web:     webclient/            (설계는 docs/web-client/)
4. 플랫폼 차이가 생겼다면 이 문서(12)에 행을 추가한다
     차이가 없으면 §A에 항목을 추가한다
5. 수락 체크리스트를 갱신한다
     docs/web-client/10 §8 + docs/analysis/05 §11
```

### I.1 새 기능을 넣기 전 확인할 질문

| 질문 | 왜 |
|------|-----|
| 이 기능은 **서버 계약**을 바꾸는가? | 바꾸면 모든 클라이언트가 동시에 배포돼야 한다. 웹은 즉시 배포되지만 Windows는 인스톨러가 필요하다 → **하위 호환 설계 필수** |
| 브라우저에서 **가능한가**? | 불가하면 이 문서 D 분류에 넣고 대체 수단을 정의한다. "웹은 나중에"로 미루면 드리프트가 굳는다 |
| **불변식 M1~M16 + WM1~WM5**를 건드리는가? | 건드리면 [00 §6](./00-scope-and-decisions.md)을 함께 갱신한다 |
| 설정 키가 추가되는가? | `docs/analysis/41 §2.1`에 키·기본값·범위를 먼저 등재한다. **웹에서 미노출이어도 값은 보존**한다 |
| 새 화면인가? | `docs/analysis/13 §1·§2`(화면 목록·전이표)와 [02 §2](./02-app-shell-and-navigation.md)·[03](./03-screens-spec.md)을 동시 갱신한다 |
| 사용자 문구가 생기는가? | `docs/analysis/13 §14` 카탈로그에 추가하고 양쪽이 같은 문자열을 쓴다(테스트로 고정) |

### I.2 절대 하지 말 것

| 금지 | 이유 |
|------|------|
| 웹에서만 계약 상수를 바꾸기(컷 수·슬롯 수·보관 시간 등) | 같은 프레임·같은 서버를 공유한다. 한쪽만 바꾸면 결과물이 깨진다(WD18) |
| 규격 문서를 건너뛰고 코드부터 고치기 | 두 클라이언트가 조용히 달라진다 |
| 이 문서에 등재하지 않고 웹만 다르게 만들기 | 다음 사람이 그것을 버그로 착각하거나, 반대로 버그를 "의도된 차이"로 오해한다 |
| 브라우저 저장소를 신뢰해 서버 데이터를 대체하기 | 저장소는 회수될 수 있다(F3) |
| JWT를 저장소에 넣어 새로고침 로그인 유지하기 | M2 위반. 필요하면 **HttpOnly 쿠키 세션을 별도 설계**로 다뤄야 한다(현 JWT 모델 변경) |
