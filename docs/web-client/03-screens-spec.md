## 1. 공통 규격

### 1.1 화면 로직 인터페이스

모든 화면은 같은 형태를 갖는다(Windows `ViewModelBase`의 `OnEnterAsync`/`OnLeaveAsync` 대응).

```ts
interface ScreenLogic {
  onEnter(ctx: EnterContext, signal: AbortSignal): Promise<void>;
  onLeave(): Promise<void>;
  // 상태는 Zustand 슬라이스, 명령은 async 함수
}
```

| 규칙 | 내용 |
|------|------|
| 재진입 가드 | 모든 명령은 `isBusy`로 이중 실행을 막는다 |
| 취소 | `onEnter`는 `AbortSignal`을 받고, 전이가 겹치면 이전 진입을 취소한다 |
| 예외 | `onEnter`/`onLeave` 예외는 **삼켜 로그**하고 흐름을 계속한다(`analysis/13 §2.2`) |

### 1.2 반응형·터치 규격

| 항목 | 값 |
|------|-----|
| 대상 폼팩터 | 세로 태블릿(주력) · 가로 데스크톱 · 세로 폰 |
| 브레이크포인트 | `< 600px`(폰) / `600~1023px`(태블릿 세로) / `≥ 1024px`(가로·데스크톱) |
| 터치 타깃 | **최소 48×48px**, 주요 CTA는 56px 이상 |
| 가로 스크롤 | **금지**(`overflow-x: hidden` + 콘텐츠는 세로 스크롤) |
| 안전 영역 | `env(safe-area-inset-*)` 적용(노치·홈 인디케이터) |
| 폰트 | 최소 16px(모바일 브라우저 자동 확대 방지) |
| 텍스트 선택 | 키오스크 오조작 방지로 `user-select: none`(입력 필드는 예외) |
| 확대 제스처 | `viewport`에 `user-scalable=no` + `touch-action: manipulation`(더블탭 확대 차단) |

### 1.3 권한 게이트 3중 방어 (M10)

모든 권한 분기는 **세 곳**에 둔다. 하나만 두면 우회된다.

```
1) 렌더 가드   : 버튼·섹션을 렌더하지 않는다
2) 커맨드 가드 : 액션 함수 첫 줄에서 권한 재확인 → 거부 시 로그 + 토스트
3) 서버 강제   : 403 응답을 우아하게 안내
```

권한 판정은 전부 `domain/roles/userRole.ts`·`roles/roleChangePolicy.ts`·`accounts/accountAdminPolicy.ts`(순수 함수)로 하고 컴포넌트에서 직접 역할 문자열을 비교하지 않는다(정적 검사 ACC-1).

## 2. `Home` — 대기 화면

**Windows 원본**: `HomeViewModel.cs`, `HomeView.xaml` · **규격**: `analysis/13 §4.1`

```
┌──────────────────────────────────────────────┐
│ [로그인]          MCPhoto          [⚙]       │  ← 홈 버튼 숨김
│                                              │
│              {브랜딩 앱 이름}                 │  ← branding.json AppName
│           {브랜딩 소제목}                     │  ← branding.json Subtitle
│                                              │
│            ┌──────────────────┐              │
│            │    촬영하기       │              │  ← 주 CTA
│            └──────────────────┘              │
│                                       v1.2.0 │
└──────────────────────────────────────────────┘
```

| 항목 | 규격 |
|------|------|
| [촬영하기] | **프레임 선택으로 직행**(로그인 화면을 강제로 거치지 않는다 = 게스트 직행) |
| 세션 초기화 | 촬영 데이터만 초기화하고 **로그인은 보존**한다 |
| 타이틀·소제목 | 브랜딩 값(`analysis/41 §6`). 폴백 `MCPhoto` / `self custom photobooth`(2026-07-30 원격 이름 통일 반영 — `analysis/41 §6`) |
| 유휴 감시 | 없음 |
| **웹 추가** | 화면 아무 곳이나 첫 포인터 이벤트에서 **전체화면 + AudioContext unlock + Wake Lock** 시도(1회, 실패 무시) |
| **웹 추가** | 카메라 권한 안내는 **상태별**이다. `prompt`·조회 불가 → *"촬영을 시작하면 카메라 사용 권한을 묻습니다."* / `denied` → *"카메라 권한이 거부되어 있습니다. 촬영 안내 화면에서 복구 방법을 확인해 주세요."* / `granted` → **렌더하지 않는다**. ⚠️ 권한 **요청**은 여기서 하지 않는다 — Home은 CTA 1개 화면이다. 사전 요청 버튼은 `Guide`에 있다(§5) |

**완료 기준**: [촬영하기] 탭 → `FrameSelect` 진입. 로그인 상태였다면 상단 계정 라벨이 유지된다.

## 3. `Login` — Google SSO

**Windows 원본**: `LoginGuestViewModel.cs`, `LoginGuestView.xaml` · **규격**: `analysis/61 §3.4·§8`, `analysis/13 §14`

```
┌──────────────────────────────────────────────┐
│                   로그인                      │
│                                              │
│      ┌────────────────────────────┐          │
│      │   Google로 로그인           │          │
│      └────────────────────────────┘          │
│      {인라인 오류 문구 영역}                  │
│                                              │
│              [닫기]                          │  ← 항상 노출
└──────────────────────────────────────────────┘
```

| 항목 | 규격 |
|------|------|
| 버튼 1개 | "Google로 로그인"만. **비밀번호·회원가입·게스트 계속 버튼은 존재하지 않는다** |
| `GoogleClientId` 빈 값 | 버튼을 **통째로 숨기고** 정적 안내: *"로그인이 구성되지 않았습니다. 관리자에게 문의하세요."* |
| [닫기] | **항상 노출**. 실패·미구성 상태에서도 게스트 촬영으로 복귀할 수 있어야 한다 |
| 성공 시 | 토큰 메모리 보관 + 세션 사용자 설정 → **직전 화면으로 복귀**(오버레이 복귀) |
| 오류 문구 | 4종을 **구분해서** 표시(§3.1) |
| **웹 차이** | 로그인은 **페이지를 떠나는 리디렉트**다. 복귀 지점·PKCE·state·nonce를 `sessionStorage`에 보관하고 `/oauth2callback`에서 복원한다([07 §2](./07-auth-and-permissions-web.md)) |
| **웹 차이** | 리디렉트 직전 화면을 "이동 중…" 상태로 두고 버튼을 비활성화한다(중복 클릭 방지) |

### 3.1 오류 문구 (`analysis/13 §14` 그대로)

| 상황 | 문구 |
|------|------|
| 사용자 취소 / `state` 불일치 / 코드 없음 | Google 로그인이 취소되었습니다. |
| 서버 401(계정·도메인 거부) | 이 Google 계정으로는 로그인할 수 없습니다. 허용된 계정·도메인인지 확인해 주세요. |
| 서버 501(SSO 미구성) | Google 로그인이 구성되지 않았습니다. 관리자에게 문의하세요. |
| 네트워크·기타 | Google 로그인 중 오류가 발생했습니다. 네트워크를 확인해 주세요. |
| 클라 미구성(`GoogleClientId` 빈 값) | 로그인이 구성되지 않았습니다. 관리자에게 문의하세요. |

**완료 기준**: 로그인 성공 후 직전 화면 복귀 + 상단 계정 라벨 = 계정 id. 취소 시 화면 유지 + 문구 표시. **어느 실패에서도 [닫기]로 게스트 흐름 복귀 가능.**

## 4. `FrameSelect` — 프레임 확정

**Windows 원본**: `FrameSelectViewModel.cs`, `FrameSelectView.xaml`, `Core/Frames/FrameLoadPolicy.cs` · **규격**: `analysis/13 §4.2·§5·§6.1`

```
┌──────────────────────────────────────────────┐
│ [계정]           프레임 선택          [홈][⚙] │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐                │
│  │ ▣✕ │ │ ▣  │ │ ▣  │ │ ▣  │  ← 썸네일 그리드│
│  └────┘ └────┘ └────┘ └────┘                │
│  선택: 베이직 4컷 (슬롯 4개 · 3:4)            │
│  [프레임 만들기] [선택 편집]        [다음]     │
└──────────────────────────────────────────────┘
```

| 항목 | 규격 |
|------|------|
| 진입 시 로드 | 공용 프레임 + (로그인 시) 본인 커스텀 → 합쳐 표시, **첫 항목 자동 선택** |
| **목록 로딩은 역할과 무관** | 프레임 쓰기 권한 없는 `user`·`temp_user`의 기존 프레임도 **그대로 보이고 촬영에 쓸 수 있다**. 편집·삭제 UI만 사라진다 |
| 권한 플래그 | `canCreateFrame` = `canDeleteFrames` = `canWriteFrames(role)`(advanced_user 이상), `isPower` = manager/admin. **두 축은 별개** |
| 목록 우선순위 | ① 로컬 공용 캐시(번들 + 서버 캐시) → ② 서버 `GET /frames/default` 중 **로컬에 같은 이름이 없는 것만** 다운로드·캐시(이름 dedup) → ③ 번들 이미지(슬롯 없으면 2×2 자동 생성) → ④ 코드 생성 fallback |
| 오프라인 | ②를 건너뛰고 ③④로 폴백 → **오프라인에서도 촬영 가능** |
| [다음] | 선택 프레임을 세션에 **고정** + **컷 수 해석(it17 — 이 시점이 유일한 해석 지점)**: 자동(설정 `0`)이면 `max(6, 슬롯 수 + 2)`, 고정이면 `max(설정 컷수, 슬롯 수)`. 세션은 `isAutoCutCount`도 함께 기억한다(이후 설정이 바뀌어도 이번 세션 표기는 불변). **이후 프레임 변경 불가**(M11) |
| 카드 ✕(삭제) | 노출 조건 = `canDelete(frame, role)`. 게스트·user·temp_user 미노출 / `local:` = **쓰기 권한 보유 역할(소유자 검사 없음** — `FrameEditPolicy.CanDelete`는 `userId`를 받지 않는다. 소유자 판정을 넣으면 power가 fork 저장한 공용 로컬 프레임의 삭제 능력이 회귀한다, `analysis/13 §6.1`**)** / 서버 공용 = power만 / 번들·fallback = 불가. 타인의 개인 프레임은 목록 필터에서 이미 제외된다 |
| [선택 편집] | `canEdit(frame, role, userId)` 통과 시만 노출 |
| 유휴 감시 | **○** |
| **웹 차이** | 서버 프레임 이미지는 **`crossOrigin="anonymous"`로 로드**하고 **OPFS에 캐시**한다(WM2 — 합성 시 canvas 오염 방지) |
| **웹 차이** | 썸네일은 `createImageBitmap` + `resizeWidth`로 축소해 메모리를 아낀다(원본 1200×1600을 그대로 여러 장 들고 있지 않는다). **resize 옵션은 Safari에서 오래 미지원이었으므로 기능 감지 + 폴백**(작은 캔버스에 `drawImage`)이 필수다 — 옵션이 무시되면 원본 크기 비트맵이 그대로 만들어져 메모리 절감이 사라진다([04 §5.2](./04-media-pipeline-web.md)) |

### 4.1 프레임 로딩 국면 (it20 · `analysis/13 §4.2`)

첫 방문은 로컬 캐시가 비어 있어 서버 다운로드를 기다린다. **웹은 이 상황이 Windows보다 훨씬 잦다** — 신규 기기·시크릿 창·저장소 비우기마다 매번 첫 방문이다. 그 대기를 4국면으로 규격화한다.

| 국면 | 도달 조건 | 대기 오버레이 | 실패 카드 | 인라인 안내 | 목록 | [다음]·[만들기]·[선택 편집]·삭제 ✕ |
|------|-----------|:---:|:---:|:---:|:---:|:---:|
| `Loading` | 진입·[다시 시도] 직후 | **표시**(스피너 + 진행 문구 + [기다리지 않고 시작]) | – | – | scrim 아래 | **차단**(scrim + 상태 가드 2중) |
| `Ready` | 프레임 ≥ 1 + 대기 중단 없음. **서버 조회 즉시 실패(오프라인)도 이 국면** | – | – | – | 표시 | 권한대로 |
| `Degraded` | 프레임 ≥ 1 + 대기 중단(상한 초과 / [기다리지 않고 시작] / 예외) | – | – | **표시** + [다시 시도] | 표시 | 권한대로 |
| `Failed` | 프레임 0개(로컬 폴백·fallback 생성까지 실패) | – | **표시** + [다시 시도]/[메인으로] | (카드 문구로 대체) | scrim 아래(비어 있음) | **차단** |

| 항목 | 규격 |
|------|------|
| 대기 상한 | **무진행 30초** + **총 60초** 2단. 무진행 타이머는 진행 보고(로컬 확인 / 서버 조회 / n번째 다운로드)마다 **재무장**한다 — 정상 진행 중인 다운로드를 잘라 거짓 실패를 띄우지 않기 위해 wall-clock 예산을 쓰지 않는다 |
| **유휴 경고와의 관계** | 총 상한 60초 **<** 유휴 경고 120초(`IDLE_TIMEOUT_MS`). 대기 중에 "자리를 비우셨나요?" 팝업이 겹치지 않는다. **두 값의 부등식이 불변식이다** — 정적 테스트로 고정한다 |
| [기다리지 않고 시작] | **새 로딩을 시작하지 않는다.** 진행 중 로딩을 취소해 로컬 폴백으로 마감시킨다. 백그라운드 공유 작업은 계속 진행해 캐시를 완성하므로 잠시 뒤 [다시 시도]가 성공할 가능성이 높다 |
| 국면 확정 | 로딩 종료 시 **무조건** 일어난다(`finally`). `Loading`으로 남는 경로는 "화면이 이미 바뀐 경우"뿐이다 — 오버레이 고착 경로가 없어야 한다 |
| 삭제 후 재스캔 | **조용한 갱신**이다(오버레이·안내 없음). 단 결과가 0개면 `Failed`, 종전이 `Failed`인데 프레임이 생겼으면 `Ready`로 회복 |
| 진행 문구 | 로컬 확인 중 / 서버 목록 확인 중 / **내려받는 중 (n/m)** / 정리 중. 시작 직후(보고 전)는 "기본 프레임을 준비하고 있어요…" |
| `Degraded` 안내 | *"서버 프레임을 모두 가져오지 못해 지금 준비된 프레임으로 진행합니다."* — "모두"가 들어가는 이유: 총 상한 초과는 일부만 받은 상태일 수 있어 "전부 실패"로 적으면 거짓이 된다 |
| `Failed` 안내 | *"사용할 수 있는 프레임이 없습니다. 네트워크를 확인하고 다시 시도해 주세요."* |
| **웹 차이** | 판정·문구는 순수 함수(`domain/frames/frameLoadPolicy.ts`)로 두고 화면은 국면만 소비한다. 상한 타이머는 **실경과 기준**(WM3와 동종 — 탭 백그라운드에서 타이머가 늘어져도 판정이 흔들리지 않게) |

- `Degraded`·`Failed`를 방치하면 유휴 경고가 위에 겹치고 홈으로 복귀한다 — **의도된 최종 탈출 경로**다.
- **오프라인은 `Degraded`가 아니다.** 서버 조회 즉시 실패는 캐시로 조용히 운영되는 것이 종전 동작이며(E20), 안내를 띄우면 매 진입 노이즈가 된다.

**완료 기준**: 목록에 공용 프레임이 최소 1개 보이고(오프라인 포함), 첫 항목이 자동 선택되며, [다음] 후 `Guide`에서 슬롯 수가 반영된다. 서버 미도달 시에도 목록이 비지 않는다. **첫 방문에서 "빈 목록 + 활성 [다음]"이 단 한 프레임도 나타나지 않는다.**

## 6. `Capture` — N컷 연속 촬영

**Windows 원본**: `CaptureViewModel.cs`, `CaptureView.xaml` · **규격**: `analysis/13 §4.4`, `analysis/14 §2·§3·§7`

```
┌──────────────────────────────────────────────┐
│                                     [취소]   │  ← 상단바 숨김, 자체 취소
│         ┌────────────────────┐               │
│         │                    │               │
│         │   카메라 프리뷰      │  3 / 6       │  ← 진행 표시
│         │    (거울·크롭 적용)  │               │
│         └────────────────────┘               │
│                  5                           │  ← 카운트다운 숫자
│            [바로 촬영]                        │
└──────────────────────────────────────────────┘
```

### 6.1 진입 절차 (순서가 규격)

```
1. 카메라 시작(장치, 목표 종횡비, 거울 여부)
     실패 → 상태 Failed + "카메라를 찾을 수 없습니다." (시퀀스 시작 안 함)
2. Ready 게이트 대기 (최대 8000ms)
     조건: 누적 8프레임 수신 AND 최소 500ms 경과 AND 현재 fps > 0
     타임아웃 → Failed (무한 로딩 금지)
3. 세션 작업 공간 생성(OPFS sessions/{id}/) + 세션 시작 시각 기록
4. 타임랩스 프레임 수집 시작              ← 웹: 녹화가 아니라 "샘플링 수집"(WD2)
5. 컷 루프 (i = 1..N)
     a. 카운트다운 (설정 초, 1초 간격 감소)
     b. 플래시 on(설정 on이면 화면 하양 오버레이) → 120ms 대기
     c. 셔터음 (설정 on이면 재생. 비동기·실패 무시)
     d. 스틸 캡처 → 컷 버퍼 추가 + OPFS에 cut{i}.jpg 기록
     e. 플래시 off        ← 캡처 "후"다
     f. 300ms 대기
6. 프레임 수집 종료
7. → CutSelect
```

### 6.2 규격 표

| 요소 | 규격 |
|------|------|
| 카메라 상태 | `Initializing` / `Ready` / `Failed` 3값. 로딩·오류 오버레이를 상태로 구분 |
| 컷 수 | 설정 의도 {6, 8, 10} 또는 `0`=자동(기본 6). 실제 촬영 수 = 자동이면 `max(6, 슬롯 수 + 2)`, 고정이면 `max(설정 컷수, 슬롯 수)`. **자동은 허용 집합에 없는 7도 만들 수 있고 컷 루프는 임의 정수 N을 견딘다**(it17) |
| 카운트다운 | 설정 {3, 6, 8, 10}초(기본 6) |
| **[바로 촬영]** | 남은 카운트다운 취소 후 즉시 셔터. **매 컷 사용 가능**. 세션은 계속 진행 |
| 플래시 | 하드웨어 제어 없음. **화면 하양 오버레이 120ms** |
| 거울모드 | 기본 on. **프리뷰·스틸·타임랩스에 동일 적용**(WYSIWYG, WM1) |
| 취소/이탈 | 시퀀스·카운트다운 취소 → 인코더 정지 → 카메라 정지 → 홈. 실패해도 예외 전파 금지 |
| 유휴 감시 | **○** |

### 6.3 웹 차이

| 항목 | 내용 |
|------|------|
| 권한 프롬프트 | `getUserMedia` 호출 시 브라우저 권한 대화상자가 뜬다. 실패는 **사유 9종으로 갈라진다**(아래 표) — 권한 거부와 장치 부재는 손님이 할 조치가 완전히 다르다 |

**실패 사유 9종**(판정: `domain/capture/cameraFailure.ts` 순수 함수 · 예외 `name`에서만 유도)

| 사유 | 확정 지점 / 유발 예외 | 문구 | [다시 시도] |
|------|-----------------------|------|:-----------:|
| `insecureContext` | `isSecureContext === false`(**가장 먼저 판정**) | "보안 연결(https)에서만 카메라를 사용할 수 있습니다." | ✕ |
| `permissionDenied` | `NotAllowedError`·`SecurityError` | "카메라 권한이 거부되었습니다. 브라우저 설정에서 허용해 주세요." | ✕ |
| `unsupportedBrowser` | `TypeError`(보안 컨텍스트일 때 = `navigator.mediaDevices` 부재 · **인앱브라우저·구형 WebView**) | "이 브라우저에서는 카메라를 사용할 수 없습니다. Safari·Chrome 등 기본 브라우저에서 열어 주세요." | ✕ |
| `noDevice` | `NotFoundError`·`OverconstrainedError`(**제약 없는 재시도 후에도** 실패) | "사용할 수 있는 카메라를 찾지 못했습니다. 연결을 확인해 주세요." | ○ |
| `inUse` | `NotReadableError`·`TrackStartError` | "카메라를 다른 앱이 사용 중입니다. 그 앱을 닫고 다시 시도해 주세요." | ○ |
| `playbackBlocked` | `FrameSource.attach()`가 `{ok:false}` — 스트림은 열렸는데 `video.play()`가 reject(iOS 자동재생 정책) | "카메라 영상을 시작하지 못했습니다. 화면을 한 번 누른 뒤 다시 시도해 주세요." | ○ |
| `pipelineStalled` | Ready 타임아웃 · 가공 프레임 **0장**([04 §2.3.3](./04-media-pipeline-web.md)) | "카메라 영상을 표시하지 못했습니다. 다시 시도하거나 다른 브라우저에서 열어 주세요." | ○ |
| `pipelineSlow` | Ready 타임아웃 · 가공 프레임 **1장 이상**(막힌 것이 아니라 느리다) | "카메라 영상이 원활하지 않습니다. 다시 시도하거나 다른 브라우저에서 열어 주세요." | ○ |
| `unknown` | 그 외 전부(`AbortError`·`InvalidStateError` 등) | "카메라를 사용할 수 없습니다. 권한과 연결을 확인해 주세요." | ○ |

⚠️ **`permissionDenied`·`insecureContext`·`unsupportedBrowser`에는 [다시 시도]를 붙이지 않는다**(`isCameraRetryable`) — 같은 조건에서 다시 눌러도 반드시 실패해 손님을 헛돌게 한다. 권한 복구는 브라우저 사이트 설정([09 §3](./09-kiosk-operations.md))에서만, `unsupportedBrowser`는 **다른 브라우저로 여는 것**으로만 가능하다.
⚠️ **`insecureContext`를 가장 먼저 판정한다** — `http://`로 열면 `navigator.mediaDevices` 자체가 `undefined`라 예외 `name`이 `TypeError`가 되고, 선판정이 없으면 `unsupportedBrowser`로 오진된다. 이 **순서가 계약이다**.
⚠️ **`AbortError`는 매핑하지 않는다**(2026-08-07). 규격상 `NotReadableError`와 분리된 잔여 범주라 "다른 앱 점유"로 단정할 근거가 약하다 — 실기기에서 관측된 뒤에 결정한다. 그동안은 아래 오류 코드가 `unknown/AbortError`로 이름을 실어 나른다.

**오류 코드 캡션**(2026-08-07 신설 · `CameraPreview`의 `Failed` 오버레이 최하단)

| 항목 | 규격 |
|------|------|
| 표시 | `오류 코드 <사유>/<상세>`(예: `unknown/AbortError` · `playbackBlocked/NotAllowedError` · `pipelineStalled/main-none` · `pipelineSlow/f3`). 상세가 없으면 사유만 |
| 노출 조건 | 카메라가 `Failed`일 때만. `Idle`·`Starting`·`Ready`에서는 렌더되지 않는다 |
| 스타일 | caption 크기 · `--fg-muted` · 고정폭(`tabular-nums`) — [다시 시도]의 우선순위를 흐리지 않는다 |
| 왜 게스트에게도 보이는가 | 진단 모달은 **로그인 전용**(§15.2)이고 클라이언트 로그는 기기 IndexedDB에만 쌓인다. 현장 운영자·테스터가 실패 원인을 전할 수 있는 **유일한 창구**다 |
| 안전 | 상세는 `/^[A-Za-z0-9_.:+-]{1,32}$/`를 통과한 값뿐이다 — 공백·`@`·한글·32자 초과를 거부하므로 예외 **메시지**·이메일·토큰·게이트 키·기기 `label`이 원리적으로 섞일 수 없다(DIAG-1·AUTH-3와 같은 계열) |

| 권한 사전 승인 | 키오스크는 브라우저 정책으로 사전 허용하는 것을 권장([09 §3](./09-kiosk-operations.md)) |
| 세션 녹화 | **하지 않는다.** 타임랩스용 프레임을 샘플링해 바로 인코딩한다(WD2, [04 §7](./04-media-pipeline-web.md)) |
| 탭 hidden | **시퀀스 취소 + 홈 복귀**(WM4) |
| 프리뷰 렌더 | `<video>`를 직접 보여주지 않는다. **가공 결과 canvas**를 보여준다(WM1) |
| 카운트다운 정확도 | `performance.now()` 실경과 기반(WM3) |

**완료 기준**: 6컷 세션이 카운트다운·플래시·간격을 지키며 완주하고 컷 6장이 수집된다. 카메라 없는 기기에서 8초 내 `Failed`로 전환되고 무한 로딩이 없다. 탭을 숨기면 홈으로 복귀하고 부분 컷이 남지 않는다.

| 컷별 재촬영 | **미구현**(Windows도 미구현 — `analysis/90 §2`). 웹도 만들지 않는다 |
| 유휴 감시 | **○** |
| 그리드 레이아웃 | **열 수를 하드코딩하지 않는다**(it17 — 자동 컷 수로 7·9 같은 값이 올 수 있다). CSS `auto-fill`/flex-wrap로 임의 N을 수용 |
| **웹 차이** | 썸네일은 OPFS의 `cut{i}.jpg`에서 `createImageBitmap`으로 축소 생성. 화면 이탈 시 `close()`로 해제 |

**완료 기준**: 슬롯 4개 프레임에서 4개 선택 시에만 [다음]이 활성되고, 2번을 해제하면 3번이 2번으로 재계산된다. 재촬영 상한 도달 시 버튼이 비활성이고 커맨드도 거부된다.

## 8. `Result` — 합성·필터

**Windows 원본**: `ResultViewModel.cs` · **규격**: `analysis/13 §4.6·§4.7`, `analysis/14 §5·§6`

┌──────────────────────────────────────────────┐
│ [계정]          결과 확인            [홈][⚙] │
│         ┌────────────────┐                   │
│         │   합성 미리보기  │                   │

│                                    [다음]     │

| 항목 | 규격 |
|------|------|
| 진입 시 | 즉시 합성해 미리보기를 만든다. 출력 파일명 `final.{설정 확장자}` |

| 유휴 감시 | **○** |

### 8.1 [다음] 처리 순서 (순서가 규격 — M6-W)

```
1. 타임랩스 생성/마무리       (수집 프레임이 있고 인코더 사용 가능할 때. 실패 시 null로 계속)
2. 로컬 보관                  (SaveLocalCopy on이면)
     2-a. OPFS 결과 폴더에 final·timelapse 기록      ← 반드시 여기서 완료 (M6-W)
     2-b. 폴더 핸들이 있으면 그 폴더에도 기록          (데스크톱 Chromium)
     실패 시 → 실패 토스트 + 로그(크래시 금지)
3. effective QR 판정  →  on 이면 Qr 화면 / off 이면 Done 화면
     qrEffectivePolicy.isQrEnabled(rawEnableQr, isLoggedIn, isTempUserBlocked)
       ① 게스트(미로그인)          → false   (Qr을 건너뛰고 Done)
       ② TempUser이고 한도 초과    → false
       ③ 그 외                     → 설정 EnableQrDelivery 그대로
```

| ⚠️ **게스트는 `Qr` 화면에 도달하지 않는다** | Windows도 같다(`QrEffectivePolicy.IsQrEnabled` — 미로그인이면 `Result → Done`). QR은 계정 단위 과금·한도의 대상이므로 로그인이 전제다. **설정의 `EnableQrDelivery`(ini/localStorage) 값은 어떤 경우에도 쓰지 않는다** — 런타임 오버라이드일 뿐이며 한도가 풀리면 즉시 원복된다 |
|---|---|

| **웹 차이** | 내용 |
|-------------|------|
| 합성 | Canvas 2D(+필터는 WebGL2). 출력은 `toBlob('image/jpeg', 0.95)` 또는 `'image/png'`([04 §5](./04-media-pipeline-web.md)) |
| 진행 표시 | 합성이 500ms를 넘을 수 있으므로 **스피너 + "결과를 만드는 중…"** 을 표시하고 필터 버튼을 비활성화한다 |
| 성능 | 필터 변경마다 전체 재합성이므로 [04 §8](./04-media-pipeline-web.md)의 예산(**1200×1600 출력**·4슬롯 ≤ 1.2s)을 지킨다 |

**완료 기준**: 진입 후 미리보기가 뜨고, 필터를 바꾸면 같은 컷으로 전체가 재합성된다. `SaveLocalCopy` on 상태에서 [다음] 후 OPFS에 결과 폴더가 생성되어 있다(업로드 전에).

## 9. `Qr` — 업로드 및 QR 표시

**Windows 원본**: `QrPopupViewModel.cs` · **규격**: `analysis/13 §4.8`, `analysis/31 §5`

```
┌──────────────────────────────────────────────┐
│                                              │  ← 상단바 숨김
│              ▓▓▓▓▓▓▓▓                        │
│              ▓ QR   ▓                        │
│              ▓▓▓▓▓▓▓▓                        │
│   업로드된 사진·영상은 24시간 후 자동 삭제됩니다  │
│   [기기에 저장]              [완료]           │
└──────────────────────────────────────────────┘
```

### 9.1 진입 절차

**진입 전제**: `Result`의 effective QR 판정이 `true`인 경우에만 도달한다(§8.1) → **로그인 상태이고 TempUser 한도 초과가 아니다**. 이 화면 안에서 로그인 여부를 다시 분기하지 않는다.

```
1. 전송 대상 확정: (SendPhoto && 사진 존재) / (SendTimelapse && 타임랩스 존재)
     둘 다 없으면 → "전송할 결과물이 없습니다." 안내로 종료 (업로드 시도 안 함 — M7)
2. 업로드 3단계 (진행률: "사진 업로드 중" → "영상 업로드 중" → "마무리 중")
3. 성공 → QR 표시 + "업로드된 사진·영상은 {N}시간 후 자동 삭제됩니다."
   실패 → QR 숨김 + 사유별 안내 + [완료] / [재시도]
```

| 항목 | 규격 |
|------|------|
| QR 내용 | **다운로드 페이지 URL 전체**(`{HostingBaseUrl}/?s={sessionId}`) |
| QR 표시 조건 | **업로드 성공 후에만**(M5) |
| [재시도] | 진행률·상태를 0에서 재시작. **새 세션 ID로 전 과정 재실행**(동일 세션 재commit은 409) |
| 흐름 차단 금지 | 실패해도 [완료]로 진행 가능. 결과물은 이미 로컬(OPFS)에 있다 |
| 유휴 감시 | **○** |
| QR 렌더 | 오류정정 레벨 **Q**(Windows `QrService.cs`의 `ECCLevel.Q`와 일치 — `analysis/30 §3`) · 여백(quiet zone) 4모듈 · 배경 흰색 고정(다크모드에서도 반전 금지 — 스캐너 호환). **모듈 픽셀 크기는 표시 파라미터**로 화면 크기에 맞춰 정한다(Windows 기본 20px, 계약 아님) |

### 9.2 실패 문구 (`analysis/13 §4.8` 그대로)

| 실패 유형 | 안내 문구 |
|-----------|-----------|
| 403 `TEMP_USER_TIME_EXCEEDED` | 무료 사용 시간이 지났습니다. 관리자에게 문의해주세요. |
| 403 `TEMP_USER_COUNT_EXCEEDED` | 무료 사용 횟수가 소진되었습니다. 관리자에게 문의해주세요. |
| 그 밖의 실패 · 로컬 저장 **on** | 전송 실패 — 사진은 기기에 저장되었습니다. |
| 그 밖의 실패 · 로컬 저장 **off** | 전송에 실패했습니다. 로컬 저장을 켜면 기기에 보관됩니다. |

### 9.3 웹 차이

| 항목 | 내용 |
|------|------|
| **[기기에 저장] 버튼 추가** | 이 화면의 사용자 제스처를 이용해 사진·영상을 **브라우저 다운로드**로 내보낸다(WD3 3계층 중 ③). 파일이 2개면 버튼도 2개(다중 자동 다운로드는 차단될 수 있다) |
| 진행률 | XHR `upload.onprogress`로 파일별 바이트 진행률(WM5). 콜백 순서를 가정하지 않는다 |
| CORS 실패 | 서명 PUT이 CORS로 막히면 네트워크 오류로 보인다 → 진단 문구에 **"업로드 구성(CORS) 확인 필요"** 를 로그로 남긴다([08 §5](./08-server-and-infra-prerequisites.md)) |

**완료 기준**: 업로드 성공 시 QR이 뜨고 폰으로 스캔해 다운로드 페이지가 열린다. 실패 시 QR이 **뜨지 않고** 사유별 문구가 나오며 [완료]로 진행할 수 있다. TempUser 한도 초과 시 전용 문구가 나온다.

## 11. `FrameEditor` — 프레임 생성·편집

```
┌──────────────────────────────────────────────┐
│ [계정]        프레임 편집            [홈][⚙] │
│ ⓘ 이 프레임 편집은 이 기기에만 적용되며…       │  ← 편집 세션 전용 배너
│ ┌──────────────────┐  이미지: [불러오기]      │
│ │                  │        [기존 프레임…]    │
│ │  프레임 + 슬롯    │  슬롯 개수: [4 ▾]        │
│ │  (드래그 이동)    │  종횡비: 4:3 / 3:4 / 1:1 │
│ │                  │  크기: ──●──── 100%      │
│ └──────────────────┘  이름: [___________]     │
│ 저장하면: 내 프레임으로 저장됩니다             │  ← 동적 안내
│                        [취소]     [저장]      │
└──────────────────────────────────────────────┘
```

### 11.1 권한 게이트 (3단, `analysis/13 §6.1`)

```
1차: canWriteFrames(role)?          (advanced_user / manager / admin)
     아니면 → 출처 무시하고 즉시 불가
2차: 출처별 판정
3차: 저장 시점 재확인 (fail-closed)
```

| 출처 | 판정 근거 | 편집 | 로컬 삭제 |
|------|-----------|------|-----------|
| 본인 로컬 생성분 | id `local:` 접두 | 소유자 본인만 | ○ |
| 서버 공용 기본 | 접두 없는 실 id + `isDefault` | **power만** | **power만** |
| 번들 자산 | id `bundle:` 접두 | ✕ | ✕ |
| 코드 생성 fallback | id `fallback` 또는 빈 id | ✕ | ✕ |

### 11.2 편집 규격

| 조작 | 규격 |
|------|------|
| 이미지 불러오기 | PNG/JPG/JPEG만, **10MB 이하**, 장변 4000px 초과 시 축소, **PNG로 재인코딩** |
| 슬롯 개수 | 1~6 |
| 슬롯 종횡비 | 4:3 / 3:4 / **1:1**(기본 3:4) |
| 슬롯 크기 | 10~300% 스케일. **항상 원본 기준 계산**(누적 오차 방지), 중심 유지, 경계 클램프 |
| 드래그 | 경계 클램프. 표시·드래그·클램프가 **동일 좌표 변환**(`analysis/14 §4.5`) |
| 저장 검증 | 개수 1~6 **AND** 전부 경계 내 **AND** 겹침 없음 |
| 이름 | 1~100자, **`_` 금지**, 파일시스템 금지문자 금지(치환하지 않고 거부) |
| 정책 배너 | **편집 세션에서만** 표시: *"이 프레임 편집은 이 기기에만 적용되며, 서버와 다른 기기에는 반영되지 않습니다."* — 신규 생성 세션은 서버 등록이 가능하므로 이 문장이 거짓이 된다 |
| **서버 호출 금지** | **편집** 저장은 **어떤 경로로도 `PUT /frames/{id}`를 호출하지 않는다** |
| 사본 분기(fork) | **[선택 편집] 경로 전용**(§11.5의 "기존 프레임 불러오기"는 fork가 아니다). 출처가 "본인 로컬 생성분"이 아니면 새 이름으로 신규 저장: `{원본} 사본` → 충돌 시 ` 2`…`99` → 그 뒤 8자리 난수. 이미 `{X} 사본 N` 형태면 **X를 base로 되돌린다**. 빈 이름의 base는 `새 프레임` |
| `_` 비차단 경고 | 공용 스코프 저장 시 이름에 `_`가 있으면 *"이름에 '_'가 있어 공용 목록에서 보이지 않을 수 있습니다."* |
| 저장 스코프 안내 | 저장 버튼 근처에 **이번 저장의 실제 결과**를 동적 표시(공용 목록 생성 / 사본 생성 / 덮어쓰기 / 내 프레임). power 신규 생성은 서버 등록을 **단정하지 않는다**: *"저장 시 '{이름}'을(를) 이 기기의 공용 목록에 만듭니다. 서버 등록 여부는 저장할 때 선택합니다."* |
| 유휴 감시 | **✕**(능동 작업) |

### 11.3 저장 전 검증 — 순서가 규격 (`analysis/13 §6.4`)

진입점이 [저장]과 서버 등록 확인 모달 **2개**이므로 양쪽에서 **같은 판정을 재실행**한다. 한쪽만 검사하면 모달 경로로 우회된다.

| # | 검사 | 차단 문구 |
|---|------|-----------|
| ① | 로그인 상태 | 로그인이 필요합니다. |
| ② | `canWriteFrames(role)` | 프레임을 만들 권한이 없습니다. |
| ③ | 슬롯 유효성(1~6 · 경계 내 · 겹침 없음) | 슬롯이 겹치거나 프레임을 벗어났습니다. |
| ④ | 원본 덮어쓰기 가드(fork + 공용 스코프 + 이름 == 원본) | 원본과 같은 이름은 사용할 수 없습니다. 이름을 변경해 주세요. |
| ⑤ | 빈 이름(공백만 포함) | 프레임 이름을 입력해 주세요. |
| ⑥ | 파일시스템 금지문자 | 이름에 사용할 수 없는 문자가 있습니다. |
| ⑦ | 스코프 이름 충돌 | 이미 같은 이름의 프레임이 있습니다. 다른 이름을 입력해 주세요. |

- **④가 ⑦보다 먼저다.** ⑦은 로컬 목록 열거에 의존해 실패 시 조용히 꺼지므로(비차단) ④가 2중 방어로 남아야 한다.
- **⑦의 예외는 [선택 편집]으로 진입한 "본인 로컬 생성분" 세션 하나뿐**(덮어쓰기가 의도). 비교는 정확 일치(Ordinal).
- **웹 주의**: ⑤⑥은 도메인의 **`isFileNameSafe`**(빈 값 + 금지문자만 판정)를 쓴다. 기존 `validateFrameName`은 **100자 길이 제한까지 묶여 있어 판정 축이 다르다** — 저장 전 선검증에는 분리된 순수 함수를 쓴다.

### 11.4 서버 등록 확인 모달 (`analysis/13 §6.3`)

power가 **신규 생성 세션**(빈 편집기 / 기존 프레임 불러오기 — §11.5)을 저장할 때만 뜬다. 노출 조건은 서버 등록 분기와 **완전히 같은 조건**(`isPower && 세션 == 신규생성`)이다 — 두 축이 갈라지면 "모달은 떴는데 등록은 안 되는" 조용한 불일치가 생긴다. `isCreateMode` 같은 파생값이 아니라 **세션 축**을 쓴다.

| 항목 | 규격 |
|------|------|
| 체크박스 | "서버에도 등록" — **기본 on**. 열 때마다 기본값으로 리셋(직전 선택 잔존 금지) |
| 캡션(고정) | *"체크하면 서버에 공용 기본 프레임으로 등록되어 다른 기기에서도 내려받습니다. 체크하지 않으면 이 기기에만 저장됩니다."* — 체크 상태와 무관한 고정 문구 |
| 체크 on | `POST /frames` + 이미지 PUT → 성공 문서로 로컬 공용 저장(서버 문서 id 기록) |
| 체크 off | 로컬 공용 저장만(서버 문서 id 미기록) |
| [취소] | 모달만 닫는다. 저장·화면 전환·저장소 모두 무변경 |
| **원자성** | 체크 on에서 서버 등록 실패 시 **로컬 저장도 하지 않는다**. 편집 세션을 유지한 채 *"서버 등록 실패: {사유} 이 기기에만 저장하려면 '서버에도 등록'을 해제하고 다시 저장해 주세요."* |

- 삭제 확인 모달("서버에서도 제거", 기본 **off**)과 기본값이 갈리는 것은 축이 달라서다(삭제=파괴적 opt-in, 생성=배포가 통상 목적).
- 원자성 근거: 로컬만 저장해 두면 재시도 시 **⑦ 가드가 자기 자신과 충돌**해 저장이 영구히 막힌다.

### 11.5 기존 프레임 불러오기 (`analysis/13 §6.5`)

> ⚠️ **2026-07-30 재정의**: it15의 "사본 세션 + 서버 미등록"은 **폐기**됐다. fork는 [선택 편집] 경로에만 남는다.

| 항목 | 규격 |
|------|------|
| 노출 | 생성 모드 전용. 파일 탐색기가 아니라 **앱 내부 썸네일 그리드** 모달 |
| 후보 | 공용 프레임 전체 + 본인 개인. 번들·fallback도 **복사 허용**(원본을 수정하지 않으므로 안전). 역할 필터 없음 |
| 적용 | 이미지는 **읽기만**, 슬롯은 `현재 프레임 폭 / 원본 이미지 폭` 배율로 보정해 값 복사 |
| **세션 정체성** | **신규 생성** — 사본이 아니다. 따라서 power가 불러온 세션도 **서버 등록 대상**이고 저장 시 §11.4 모달이 뜬다 |
| **이름** | **자동 제안하지 않는다.** 사용자가 이미 입력한 값을 보존한다(이름 먼저 → 이미지 나중 순서 지원). 원본 이름을 채우면 ⑦ 가드에 100% 걸리는 값을 제안하는 셈 |
| 원본 안내 캡션 | 이름 입력 위: *"'{원본이름}'의 이미지·슬롯을 불러왔습니다. 새 프레임 이름을 입력해 주세요."* — "사본이 아니라 새로 만드는 중"이라는 유일한 시각 신호. 이미지를 직접 다시 불러오면 **비운다** |
| 원본 보호 | 이름이 아니라 **⑦ 스코프 이름 충돌 가드**가 담당한다 |
| [취소] | 모달만 닫고 편집기 상태·저장소 무변경 |

### 11.6 역할별 저장 결과 (`analysis/13 §6.3`)

| 역할 | 신규 생성 저장 결과 |
|------|---------------------|
| manager / admin | 로컬 공용 저장 + **§11.4 모달에서 선택한 경우에만** 서버 공용 기본 프레임 등록(`POST /frames` + 이미지 PUT) |
| advanced_user | **로컬 전용**(개인 스코프) |
| user / temp_user / 게스트 | 저장 경로에 도달하지 않음 |

계정당 로컬 프레임 **최대 10개**. 초과 시 저장 거부.

### 11.7 웹 차이

| 항목 | 내용 |
|------|------|
| 이미지 선택 | `<input type="file" accept="image/png,image/jpeg">`. 카메라 촬영 선택도 OS가 제공 |
| 재인코딩 | canvas → `toBlob('image/png')` |
| 좌표 변환 | 캔버스 크기는 **실제 렌더 크기**(`getBoundingClientRect()` × `devicePixelRatio`)를 쓴다. 선언 크기 사용 금지 |
| 드래그 | Pointer Events(`pointerdown/move/up` + `setPointerCapture`). **그랩 오프셋 기반 절대 위치 이동**(델타 누적 금지) |
| 터치 | 드래그 중 스크롤 방지(`touch-action: none`) |
| 저장 | 공용(power)은 서버 등록 + 이미지 PUT(CORS 필요), 개인은 IndexedDB+OPFS |
| 임시 파일 | **만들지 않는다.** OPFS 쓰기는 저장 1회뿐 |

**완료 기준**: 이미지 로드 → 슬롯 4개 자동 배치 → 드래그로 이동 → 저장 시 목록에 새 프레임이 나타나고 **그 프레임으로 촬영한 합성 결과의 슬롯 위치가 편집기에서 본 위치와 일치**한다(WYSIWYG). 겹침·경계 이탈 상태에서는 저장이 거부된다.

## 14. `UserMgmt` — 사용자 관리 (power)

**Windows 원본**: `UserMgmtViewModel.cs`, `UserMgmtView.xaml` · **규격**: `analysis/13 §10.3`, `analysis/60 §1.3.1·§1.4`

│ id        이메일          역할        가입일    작업        │
│ devmcjo   dev@…          관리자      2025-11   (자기: 없음) │

| 규격 | 내용 |
|------|------|
| 목록 정렬 | **역할 위계가 높은 계정이 위, 동급은 먼저 가입한 계정이 위**. 컬럼 헤더에 정렬 표기(▼/▲)를 두고 별도 안내 문구는 두지 않는다(it19). 상단에 인원 요약(계정 수) 표시 |
| [뒤로] | 관리자 도구(`Account`/Admin)로 **직행**(복귀 지점을 쓰지 않는다 — it19) |
| 역할 콤보 순서 | **위계 오름차순** `temp_user → user → advanced_user → manager`. `admin` 지정은 누구도 불가 |
| no-op | `target == current`이면 서버로 보내지 않는다 |
| 삭제 성공 안내 | *"{id} 삭제됨(소유 프레임 포함)."* (cascade) |
| 목록 조회 실패 | **빈 목록으로 폴백하지 않고** 오류 표시: *"사용자 목록을 불러올 수 없습니다."* |

| **웹 차이** | 좁은 화면에서는 표를 **카드 리스트**로 전환(가로 스크롤 금지 규칙) |

## 15. 모달·오버레이 9종 — **셸 모달 4 + 화면 로컬 오버레이 5**

> ⚠️ **2026-08-01 정정(Step 15 구현)**: 종전 제목은 "모달 7종"이었으나 실제 구조는 **둘로 나뉜다**.
> **셸 모달 4종**(`ModalId` — 카메라 테스트 §15.1 · 진단·상태 §15.2 · PIN 입력 §15.3 · 유휴 경고 §15.6)은
> 셸 스택이 소유하고, **화면 로컬 오버레이 5종**(§790 목록 — 프레임 준비 대기·프레임 준비 실패·삭제 확인 §15.5 ·
> 기존 프레임 불러오기 §15.4 · 서버 등록 확인 §15.7)은 각 화면이 상호배타 단일 필드로 소유한다.
> `ModalId`에서 `"framePicker"`·`"confirmDelete"`는 **제거됐다**(정적 검사 FR-8이 재발을 막는다).

### 15.1 카메라 테스트 (`analysis/13 §9.1`)

| 항목 | 규격 |
|------|------|
| 목적 | **실촬영과 동일한** 프리뷰·플래시·셔터 재현. **저장하지 않는다** |
| 절차 | 모달 먼저 표시(로딩 오버레이) → 카메라 시작 → 대기 → 닫힌 뒤 **카메라 확실히 정지** |
| 장치 전환 | 이미 열려 있을 수 있으므로 **정지 후 지정 장치로 재시작**(시작이 멱등이라 "이미 실행 중"으로 무시될 수 있다) |
| Ready 게이트 | 실촬영과 **동일 규칙**(누적 8프레임 + 500ms + fps>0, 8초 타임아웃) |
| 셔터 | 플래시 옵션까지 재현하고 결과는 **폐기** + *"저장되지 않았습니다"* 안내 |
| **웹 추가** | 실제 획득 해상도·fps·거울 적용 여부를 하단에 표시(WC2 대응) |

### 15.2 진단·상태 (`analysis/13 §9.2`)

진입: 설정 [고급] → [진단·상태] (**로그인 전용**).

| 섹션 | 웹 표시 항목 |
|------|--------------|
| 카메라 | 장치 수 · 목록(label) · **현재 해상도·fps** · 권한 상태(granted/prompt/denied) |
| 비디오 인코더 | **타임랩스 경로 판정**: `MediaRecorder(mp4)` / `WebCodecs+muxer` / **미지원** + 코덱 문자열 |
| 서버 연결 | 백엔드 구성 여부 · 주소 · 버킷 · **게이트 키 "설정됨/미설정"만**(값 절대 미표시) · **[웹 OAuth 구성] "설정됨/형식 오류(값 미치환 의심)/미설정/알 수 없음"** + **[redirect 허용목록] 개수**(둘 다 값 절대 미표시 — `GET /health`의 `oauth`) · 현재 로그인 계정 · **[마지막 로그인 실패]** 사유+시각 · `GET /health` 결과와 `deployedAt` |
| 로그·저장소 | 로그 항목 수·기간 + **[로그 내보내기]** · 저장소 영속 승인 여부 · 사용량/할당량(`navigator.storage.estimate()`) · OPFS 세션 잔재 수 |
| **개발자 문의**(it17 Windows 대응) | Developer `devmcjo@gmail.com`(+**[복사]** 버튼) · Version · Build Date(빌드 시각은 여기서만 노출 — 하단 캡션 금지) · **Web Deploy Date**(`GET /health`의 `deployedAt` — 유효 게이트 키일 때만 수신) |
| 앱 | 버전 · Service Worker 상태(업데이트 대기 시 [지금 적용]) · PWA 설치 여부 |

- 정상/이상을 **색으로 구분**한다. **"구성됨"은 "도달 성공"이 아니다** — 실도달은 `GET /health` 프로브로 확인.
- 내보내기 실패해도 크래시 없이 로그만 남긴다.

### 15.3 PIN 입력 (`analysis/13 §9.3`)

| 항목 | 규격 |
|------|------|
| 모드 2종 | **확인** / **최초 설정**(새 PIN 2회 일치) |
| 형식 | **정확히 4자리 숫자** |
| 연속 5회 불일치 | **모달을 닫는다**(게이트 미통과) |
| 불일치마다 | **1.5초 입력 비활성** |
| 네트워크·서버 오류 | **실패 횟수에 세지 않고** 게이트도 열지 않는다: *"확인할 수 없습니다. 네트워크를 확인하세요."* |
| **웹 추가(WD16)** | **기기 단위 잠금**: 연속 5회 실패 시 **5분간 입력 차단**(localStorage에 해제 시각 저장, 앱 재시작에도 유지). **계정 단위 잠금은 만들지 않는다**(DoS) |
| 입력 UI | 숫자 키패드(`inputmode="numeric"` + 자체 온스크린 키패드 권장 — 키오스크에 물리 키보드가 없다) |
| 보안 | PIN을 로그·에러 리포트에 남기지 않는다. 입력 필드는 `autocomplete="off"` |

### 15.4 기존 프레임 불러오기 (`analysis/13 §6.5`)

| 항목 | 규격 |
|------|------|
| 노출 | **생성 모드에서만** |
| 형태 | 파일 탐색기가 아니라 **앱 내부 썸네일 그리드**(프레임 선택 화면과 동일 시각) |
| 후보 | 공용 프레임 전체 + 본인 개인 로컬. 번들·fallback도 **복사 허용**. 역할 필터 없음 |
| 적용 | 이미지는 **읽기만** 하고, 슬롯은 `현재 프레임 폭 / 원본 이미지 폭` 배율로 보정해 값 복사 |
| 임시 파일 | **만들지 않는다** |
| 세션 정체성 | **신규 생성**(사본 아님 — 2026-07-30 재정의). power가 불러온 세션도 **서버 등록 대상**이라 저장 시 §15.7 모달이 뜬다 |
| 이름 | 자동 제안 없음 + 원본 안내 캡션. 상세는 [§11.5](#115-기존-프레임-불러오기-analysis13-65) |
| [취소] | 모달만 닫고 편집기 상태·저장소 모두 무변경. 목록 로딩은 취소 신호로 중단 |

### 15.5 삭제 확인 (`analysis/13 §6.6`)

```
1. 삭제 가능 판정: 권한 AND 출처가 삭제 가능
2. 확인 UI (power에게는 "서버에서도 제거" 체크 제공)
3. 로컬 삭제는 항상 실행
4. power && 체크됨 → 서버 삭제 시도
     저장된 서버 문서 id로 시도 → 실패 시 이름 매칭으로 재시도
     결과를 명확히 안내 (성공 오인 금지)
```

| 결과 | 문구 |
|------|------|
| 로컬 삭제 실패 | 로컬 프레임 파일을 삭제하지 못했습니다(사용 중일 수 있음). |
| 서버 삭제 성공 | 서버에서도 삭제되었습니다. |
| 서버 문서 미발견 | 로컬은 삭제했지만 서버에서 '{이름}' 문서를 찾지 못했습니다. |
| 서버 삭제 예외 | 서버 삭제 실패: {사유} |

- 로컬 삭제 성공 판정은 **실제로 사라졌는지**로 한다(OPFS `getFileHandle`이 `NotFoundError`인지 재확인).
- 서버 응답 `{deleted:false}`는 **성공이 아니다**.

### 15.6 유휴 경고 (`analysis/13 §7`)

| 항목 | 규격 |
|------|------|
| 표시 | 스크림 + 카드 + 남은 초 + 버튼 2개 |
| [이어서 진행하기] | 경고 해제 + 무동작 타이머 재시작(화면·로그인 유지) |
| [메인 화면으로] | 즉시 홈 복귀 |
| 0초 도달 | 홈 복귀. **로그아웃 금지** |
| 표시 중 사용자 활동 | **무시**(버튼으로만 해제) |

- **셸이 소유**하므로 화면 로컬 오버레이(프레임 준비 대기·삭제 확인·서버 등록 확인)보다 **항상 위**에 그려진다.

### 15.7 서버 등록 확인 (`analysis/13 §6.3`) — **신규**

power 신규 생성 저장 시에만 뜬다. 전체 규격은 [§11.4](#114-서버-등록-확인-모달-analysis13-63).

| 항목 | 규격 |
|------|------|
| 노출 조건 | `isPower && 세션 == 신규생성` — **서버 등록 분기와 동일 조건**(파생값 금지) |
| 체크박스 | "서버에도 등록" **기본 on**, 열 때마다 리셋 |
| 확정 순서 | 체크 상태를 **닫기 전에** 지역 값으로 확정한다 — 리셋이 먼저 일어나면 선택이 조용히 무시된다 |
| 원자성 | 서버 등록 실패 시 로컬 저장도 하지 않고 편집 세션 유지 |

> 화면 로컬 오버레이 목록: `FrameSelect` = 프레임 준비 대기(§4.1) · 프레임 준비 실패(§4.1) · 삭제 확인(§15.5) / `FrameEditor` = 기존 프레임 불러오기(§15.4) · 서버 등록 확인(§15.7) / `Capture` = 카메라 초기화 대기. **같은 화면의 오버레이는 동시에 뜨지 않는다**(상호배타 상태로 관리).

## 16. P1 다운로드 페이지 (기존 — 변경하지 않음)

QR로 손님이 여는 페이지는 `web/public/`의 현행 구현을 유지한다(N1). 규격은 `docs/analysis/13 §12`, 구현 분석은 `docs/analysis/20`.

웹 앱이 지켜야 하는 것은 **그 페이지가 올바르게 동작할 수 있는 문서를 만드는 것**뿐이다.

| 웹 앱의 책임 | 내용 |
|--------------|------|
| M7 | `finalImageUrl`·`timelapseUrl` 중 최소 1개 non-null인 상태로만 commit |
| M8 | 옵션 꺼짐(null)과 실패를 혼동하게 만드는 commit을 하지 않는다 |
| URL 규약 | `downloadPageUrl = {HostingBaseUrl}/?s={sessionId}` — **P1 사이트 도메인**을 가리켜야 한다(kiosk 사이트가 아니다) |

> ⚠️ **자주 하는 실수**: 앱을 kiosk 사이트에 배포했으므로 `HostingBaseUrl`도 kiosk 도메인으로 바꾸고 싶어지는데, **그러면 QR이 앱을 열어 버린다.** `HostingBaseUrl`은 **P1 다운로드 페이지 도메인**이다.
