**`docs/web-client/14-handoff-and-user-actions.md`의 A1~A5 "✅ 완료" 표기를 근거로 삼지 마라.
그 액션의 산출물(env 파일·시크릿·콘솔 등록값)을 직접 열어 확인하라.**

**Why:** 2026-08-01 실사용 로그인 실패의 원인이 정확히 이것이었다. 문서상 A1(웹 OAuth 클라이언트 생성)·
A2(env 등록)가 "✅ 완료·검증됨"으로 표기돼 있었고 커밋 메시지도 `docs: A1~A5 완료 반영`이었으나,
실제 `web/functions/.env.mcphoto-955fb`에는 문서 §3의 **예시 명령 문자열이 치환 없이** 들어 있었다
(`GOOGLE_OAUTH_CLIENT_ID_WEB=<A1의 웹 client_id>`). 배포는 **성공**했고 — 값이 비지 않아 서버가 "구성됨"으로
판정하므로 501도 아니었다 — Google 토큰 교환만 `invalid_client`로 조용히 실패했다. 그 결과가 일반화 401
"이 Google 계정으로는 로그인할 수 없습니다"로 표시돼 **서버 구성 오류가 계정 문제로 오귀인**됐다.
문서·커밋·배포 성공 셋 다 초록이었는데 기능만 죽어 있었다.

**How to apply:**
- 설계가 사용자 액션(시크릿 등록·콘솔 설정·CORS·배포)에 의존하면, **"완료됨"을 사실이 아니라 가정으로 적어라.**
  WBS 헤더의 *미검증 가정*에 넣고 검증 단계를 매핑한다.
- 값이 **있는데 틀린** 경우를 항상 후보에 넣어라. `if (value.length > 0)` 류의 활성 판정은
  플레이스홀더를 정상값으로 통과시킨다 — "미설정"보다 훨씬 진단하기 어렵다.
- 인수인계 문서에 `<…>` 플레이스홀더가 들어간 복사용 명령을 쓸 때는 **치환 경고와 기계 검사**를 함께 설계해라.
- 같은 성질의 함정: 서버 응답을 **일반화**하는 보안 장치(열거 방지 401)는 **운영자 문제까지 감춘다.**
  계정과 무관한 사유(클라이언트 자격 오류 등)는 일반화에서 빼는 것이 방어 약화가 아니다.
