컨트롤·진입점을 다른 상태(권한·토글·플래그) 뒤에 숨기는 배치는 이 프로젝트에서 **세 번 반려됐다.**
정보를 얻어야 상태를 결정할 수 있는 경우, 그 정보의 진입점은 상태와 **무관하게** 보여야 한다.

반려 이력(전부 사용자·팀리드 피드백):

1. **게스트에게 외부 장치 섹션 `Collapsed`** → "외부 장치 연결 탭이 사라졌어" (it24에서 폐지 — 보이되 Disable + 게이트 노티로 전환)
2. **프린터 토글 하드코딩 Disable + 캡션 삭제** → "강제로 비활성화 되어 있던" (it24에서 편집 가능화 → it25에서 다시 Disable하되 **"추후 지원 예정" 캡션을 반드시 병기**)
3. **[지원 카메라 목록] 버튼을 `ExternalCameraEnabled` 하위 패널 안에 배치**(설계 §7.4 원안) → 팀리드 기각. 이 목록이 답하는 질문("내 카메라가 지원되나?")은 사용자가 **토글을 켤지 결정하기 전에** 하는 질문이라 순서가 거꾸로였다. 토글 행으로 올려 Visibility 밖에 뒀다(it25).

**Why:** 이 앱은 키오스크 운영자가 처음 만지는 화면이 설정이다. "안 보이는 것"과 "없는 것"을 사용자가 구분할 수 없어, 숨김은 항상 기능 부재로 읽힌다. 반면 Disable + 사유 캡션은 "있지만 지금은 못 쓴다"를 정확히 전달한다 — it24·it25의 "거짓말 금지" 원칙과 같은 뿌리다.

**How to apply:** UI 요소에 `Visibility` 게이트를 걸기 전에 "이걸 보고 저 상태를 결정하는가?"를 자문한다. 그렇다면 게이트를 걸지 않고 **Disable + 사유 문구**로 간다. 게이트를 뺀 배치는 주석만으로 두지 말고 **위치 단정 테스트**로 고정한다(`XamlResourceTests.SettingsView_Supported_Camera_Button_Is_Outside_Toggle_Gated_Panel`처럼 게이트 컨테이너의 여는 태그보다 앞에 있는지 인덱스로 비교) — 주석만 두면 다음 사람이 "정리"하며 다시 안으로 넣는다.
